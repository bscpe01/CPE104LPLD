Lab 10 · Memory · ILO 1

Memory Is a Row of Numbered Bytes

RAM is a long row of 1-byte cells. Each cell has a number, its address. A variable occupies one or more neighboring cells.

Every variable has four properties
Propertyint age = 19;double gpa = 1.75;
Typeint (4 bytes)double (8 bytes)
Nameagegpa
Value191.75
Address0x7ffd0c (its first byte)0x7ffd10

Key concept

A variable's address is the address of its first byte. The type tells the computer how many bytes to read from there.

Note

Addresses on these slides are illustrative and shortened. Real ones look like 0x7ffd5e8c3a4c and change on every run.

Suggested time: about 5 min

Teaching tips

  • Analogy: a long street where every house holds exactly one byte and has a house number. A 4-byte int rents four houses in a row; we refer to it by the first house number.
  • Emphasize the four properties. Until today students only cared about name and value; type mattered for sizeof. Address is the new property.
  • Why "0x"? It marks a hexadecimal number. Addresses are printed in hex because they are long binary numbers, and hex is a compact way to write binary.
  • Modern operating systems randomize where a program's memory starts (a security feature), so addresses change from run to run. Tell students not to be surprised in the next demo.

Common student pitfalls

  • Confusing the value (19) with the address (where 19 is stored).
  • Thinking variables always sit in declaration order. The compiler decides the layout.

Ask the class

  • "How many byte addresses does a double use?" (8.) "And a char?" (1.)

Lab 10 · Memory · ILO 1

The Address-of Operator &

Put & in front of a variable to get its address. cout prints addresses in hexadecimal.

Key concept

age gives the value. &age gives the address. Same variable, two different questions.

Try it twice

Run the program again: the values stay the same, but the addresses change. Here &gpa happens to be 4 bytes after &age; on another compiler it may not be.

Suggested time: about 5 min

Teaching tips

  • Live-code this in Codechum or your IDE. Run it twice and let students notice that the addresses change. That is the moment "addresses are illustrative" becomes real.
  • Read &age aloud as "the address of age".
  • On Windows (MinGW / Dev-C++), addresses look shorter, like 0x61fe1c. Both are fine.
  • Avoid printing the address of a char today: cout << &letter treats it as text and prints garbage characters. If a student tries it, cast to (void*) or just skip it.

Common student pitfalls

  • Expecting a decimal number. Addresses print in hex with a 0x prefix.
  • Copying an address from the slide into their answer. Their own run will differ, and that's correct.

Ask the class

  • "In this run, 0x…d70 − 0x…d6c = ? bytes." (4, exactly the size of age.)

Lab 10 · References · ILO 1–2

References: A Second Name for a Variable

int& ref = x; makes ref an alias of x: two names, one memory box.

#include <iostream>
using namespace std;

int main() {
    int x = 10;
    int& ref = x;     // ref is another name for x

    ref = 20;         // changes x
    cout << "x=" << x << " ref=" << ref << endl;

    x = x + 5;        // ref sees the change too
    cout << "x=" << x << " ref=" << ref << endl;

    int y = 99;
    ref = y;          // copies 99 into x
    y = 1;            // x is not affected
    cout << "x=" << x << " ref=" << ref;
    cout << " y=" << y << endl;
    cout << (&ref == &x) << endl;  // 1 = true
    return 0;
}

Rules for references

  • Must be initialized: int& r; is an error.
  • Cannot be re-seated: ref = y; only copies a value.
  • Same address as the original.
x · ref990x7ffd10

Suggested time: about 8 min

Teaching tips

  • Analogy: a nickname. "Juan" and "Jun-jun" are the same person; if Jun-jun gets a haircut, Juan has a haircut.
  • Step through the tracer. Stop at line 15 and ask the class to predict before pressing Step: most will say "ref now refers to y". The Memory panel shows x became 99 and y is still separate.
  • The memory diagram shows one box with two names. Draw it that way on the board; never draw a reference as its own box with an arrow.
  • Line 19 prints 1 because a bool prints as 1 (true) or 0 (false) by default.
  • Preview: references are the main tool for pass-by-reference in Lab 11.

Common student pitfalls

  • Declaring int& r; without a variable (compile error: "declared as reference but not initialized").
  • Thinking ref = y; re-points the reference.
  • Confusing int& ref = x; (a declaration) with &x (address-of). The next slides untangle this.

Ask the class

  • "After line 16, why is x still 99 when y became 1?" (Line 15 copied the value; it did not link ref to y.)

Lab 10 · Pointers · ILO 1

Pointers: Variables That Hold Addresses

A pointer is a variable whose value is the address of another variable. Declare it, point it, then follow it.

#include <iostream>
using namespace std;

int main() {
    int x = 10;
    int* p = &x;         // p holds x's address

    cout << "x  = " << x << endl;
    cout << "&x = " << &x << endl;
    cout << "p  = " << p << endl;     // same
    cout << "*p = " << *p << endl;    // 10

    int* q = nullptr;    // points nowhere
    cout << "q  = " << q << endl;
    cout << "sizeof(p) = " << sizeof(p) << endl;
    return 0;
}
Declareint* p;p is a pointer to an int
Pointp = &x;p gets the address of x
Follow*pthe int p points to (dereference)
Nothingnullptrpoints nowhere (prints as 0)
Sizesizeof(p)8 bytes on 64-bit, for any pointer type
x100x7ffd10
p0x7ffd100x7ffd18
q0 (nullptr)0x7ffd20

Suggested time: about 8 min

Teaching tips

  • Compare the memory diagram with the output: the pointer's value equals x's address. The pointer also has its own address, since it is a variable too.
  • Pointer size: every address has the same size, so int*, double*, and char* are all 8 bytes on our 64-bit lab PCs (4 bytes on an old 32-bit system).
  • Pointer types matter: an int* may only hold the address of an int. double* d = &x; does not compile.
  • nullptr is C++11 and later. Older books use NULL or 0; use nullptr in this course.
  • Spacing: int* p, int *p, and int * p all mean the same. We write int* p to say "the type is pointer to int".

Common student pitfalls

  • Printing p when they wanted the value (*p), or the other way around.
  • Declaring int* p; and using *p before assigning an address (a "wild" pointer; see the errors slide).

Ask the class

  • "What is sizeof(double*) on our lab PCs?" (8, the same as any pointer.)

Lab 10 · Pointers · ILO 1

The Two Meanings of & and *

The meaning depends on where the symbol appears: next to a type in a declaration, or inside an expression.

SymbolIn a declaration (after a type)In an expression
&int& r = x; → r is a reference to x&x → the address of x
(between two values, a & b is bitwise AND; a && b is logical AND)
*int* p = &x; → p is a pointer to int*p → dereference: the value p points to
(between two values, a * b is multiplication)

Read declarations right to left

  • int* p → "p is a pointer to int"
  • int& r → "r is a reference to int"
  • double* d → "d is a pointer to double"

Common pitfall

int* p, q; makes only p a pointer; q is a plain int. Declare one pointer per line.

Say it out loud

int a = 3; int* p = &a;
int& r = a; *p = r + 1;

  1. int* p = &a; p holds the address of a
  2. int& r = a; r is another name for a
  3. r + 1 3 + 1 = 4
  4. *p = 4 Store 4 where p points: a is now 4

Suggested time: about 6 min

Teaching tips

  • This is the slide students will come back to. Ask them to copy the table into their notebooks.
  • Rule of thumb: if a type is right before the symbol, it is a declaration (making a pointer or reference). Otherwise it is an operator (address-of, dereference, AND, multiply).
  • Run the "say it out loud" reveal. Have a student read each step before you click.

Common student pitfalls

  • Writing *p = &x; when they mean p = &x; (compile error: cannot assign an address to an int).
  • Writing int& r = &x; (wrong: a reference binds to the variable itself, not its address).
  • int* p, q; as shown in the pitfall box.

Ask the class

  • "In int y = *p * 2;, which * is which?" (First: dereference. Second: multiplication.)

Lab 10 · Pointers · Memory tracing

Draw It: Boxes and Arrows

Draw each variable as a box. Draw a pointer as a box with an arrow to the box whose address it holds. Redraw after every line.

int x = 10;
int y = 50;
int* p = &x;     // ① p points to x
*p = 25;         // ② change x through p
p = &y;          // ③ move p to y
*p = *p + 1;     // ④ change y through p

Key concept

An arrow means "holds the address of". *p means "follow the arrow". p = … moves the arrow; *p = … changes the box at the end of the arrow.

Highlighted box = what that line changed. Addresses are illustrative.

Suggested time: about 6 min

Teaching tips

  • Cover panels 2–4 with paper (or zoom in) and have students draw the next panel themselves before revealing it.
  • The key contrast is panel 2 vs panel 3: *p = … changes the target; p = … changes the arrow.
  • Students may write either the address (0x7ffd10) or just draw the arrow. On paper, the arrow is enough; in the worksheet, we will also write assumed addresses.
  • The next slide steps through this exact program in the tracer.

Common student pitfalls

  • In panel 3, also changing x to 50 ("p = &y copies y"). It doesn't; only p changes.
  • Drawing the arrow from x to p (backwards). The arrow starts at the pointer.

Ask the class

  • "After panel 4, what does *p print? And x?" (51 and 25.)

Lab 10 · Pointers · ILO 2

Trace It: Changing a Variable Through a Pointer

The program from the diagrams. Watch p and *p in the Memory panel.

#include <iostream>
using namespace std;

int main() {
    int x = 10;
    int y = 50;
    int* p = &x;       // p points to x

    *p = 25;           // x is now 25
    cout << "x = " << x << ", y = " << y << endl;

    p = &y;            // p now points to y
    *p = *p + 1;       // y becomes 51
    cout << "x = " << x << ", y = " << y << endl;
    cout << "*p = " << *p << endl;
    return 0;
}

Suggested time: about 6 min

Teaching tips

  • Use Step, not Play. Before each step ask: "Which box changes now: p, or the box p points to?"
  • Point out that x changes on line 9 even though line 9 never names x. This is "manipulating data indirectly" from ILO 2.
  • The Memory panel shows p as an illustrative address plus its target, e.g. 0x7ffd10 (&x). The "(&x)" part is only a label for students; a real pointer stores just the number.

Common student pitfalls

  • Thinking *p = *p + 1; moves the pointer. It changes the value; p++ would move the pointer (next section).

Ask the class

  • "Without writing x on the left side, how could we make x equal to x + y?" (Point p back to x with p = &x;, then *p = *p + y;.)

Preview: Lab 11

References and pointers power pass-by-reference: a function that changes the caller's variable, or reads a big value without copying it (const string&).

Suggested time: about 5 min

Teaching tips

  • Rule of thumb for this course: use a reference when you just need another name (especially for function parameters); use a pointer when the target can change, can be "nothing", or comes from new.
  • const int* p reads right to left: "p is a pointer to an int that is const". You cannot change the int through p, but p can point elsewhere.
  • Optional extra: int* const q = &x; is the opposite, a const pointer (q cannot move, but *q can change). Mention it only if a student asks.

Common student pitfalls

  • Thinking const int* p makes limit itself constant. It only prevents changes through p; limit = 50; still works.

Ask the class

  • "You need something that can point to the first reading, then the next, then the next. Reference or pointer?" (Pointer: it must move.)

Lab 10 · Pointers & arrays · ILO 2

Pointers and Arrays

An array's name converts to a pointer to element 0. Adding 1 to a pointer moves it to the next element, not the next byte.

#include <iostream>
using namespace std;

int main() {
    int readings[4] = {12, 7, 30, 18};
    int* p = readings;          // &readings[0]

    cout << p << endl;          // address of [0]
    cout << (p + 1) << endl;    // 4 bytes later
    cout << *(p + 1) << endl;   // readings[1]
    cout << readings[2] << " "
         << *(readings + 2) << endl;
    cout << ((p + 3) - p) << endl;  // elements
    return 0;
}
p12…160
p + 17…164
p + 230…168
p + 318…16c

Key concept

  • readings (alone) → &readings[0]
  • p + 1 → address + sizeof(int) = 4 bytes
  • *(readings + i) is the same as readings[i]
  • Pointer − pointer = number of elements apart
  • Valid only inside the array (and one past the end)

Suggested time: about 8 min

Teaching tips

  • Connect to the bridge slide: readings[2] is literally computed as *(readings + 2). The brackets are a convenient shorthand.
  • Show the hex: …160 → …164 is a jump of 4 bytes even though we wrote + 1. Ask what the jump would be for a double array (8).
  • Going past the end with pointer arithmetic is undefined behavior, exactly like an out-of-bounds index in Lab 9.
  • An array name is not a variable you can move: readings++ does not compile. A pointer copy (p) can move.

Common student pitfalls

  • Writing *readings + 2 (which is 12 + 2 = 14) instead of *(readings + 2) (which is 30). Parentheses matter: * binds tighter than +.
  • Expecting p + 1 to be 1 byte later.

Ask the class

  • "What is *readings + 2?" (14.) "What is *(readings + 2)?" (30.)

Lab 10 · Pointers & arrays · ILO 2

Trace It: Walking Through an Array with a Pointer

Instead of an index i, a pointer starts at element 0 and moves one element per loop pass.

#include <iostream>
using namespace std;

int main() {
    const int SIZE = 5;
    int scores[SIZE] = {12, 7, 30, 18, 25};
    int sum = 0;

    for (int* p = scores; p < scores + SIZE; p++) {
        sum += *p;
        cout << *p << " ";
    }
    cout << endl;
    cout << "Sum = " << sum << endl;
    return 0;
}

The pattern: start at [0] · stop one past the end · step one element

for (int* p = arr; p < arr + SIZE; p++)

12 7 30 18 25
Sum = 92

Common pitfall

p <= scores + SIZE runs one pass too many and reads past the end (undefined behavior).

Suggested time: about 6 min

Teaching tips

  • Compare with the Lab 9 index loop on the board: for (int i = 0; i < SIZE; i++) { sum += scores[i]; }. Same output, different "cursor".
  • In the tracer, the Memory panel shows p as &scores[k] so students see which element it points to without hex addresses.
  • On the last test, p equals scores + 5: a legal address to compare against, but never to dereference.

Common student pitfalls

  • Writing sum += p; (adding an address) instead of sum += *p;. g++ rejects it: "invalid conversion from int* to int".
  • Using <= in the loop condition.

Ask the class

  • "How would you print the scores backwards with a pointer?" (Start at scores + SIZE - 1, loop while p >= scores, use p--.)

Lab 10 · Dynamic memory · ILO 2

Dynamic Memory: new and delete

Size known only at run time? Request memory with new; give it back with delete.

AllocateFree with
int* c = new int(0);delete c;
double* r = new double[n];delete[] r;

Key concept

Locals vanish when their block ends; new memory stays until you delete it. Forgetting = a memory leak.

Note: int arr[n]; with a run-time n is a g++ extension, not standard C++. Use new[].

Suggested time: about 8 min

Teaching tips

  • Why store the readings at all? Printing them newest-first needs every value kept until the end. That is the reason for an array whose size the user chooses.
  • new double[n] returns a pointer to element 0, so readings[i] works exactly like an ordinary array (and *(readings + i) works too).
  • Vocabulary if students ask: local variables live on the stack; new memory comes from the heap (free store). Later courses use vector, which manages this automatically.
  • Leaks matter in programs that run for a long time (servers, embedded devices): a little leaked memory per loop eventually uses up all RAM.
  • Robust versions should check n > 0 before calling new. The lab exercise requires that check.

Common student pitfalls

  • Using delete readings; for an array (must be delete[]).
  • Using readings after delete[].
  • Forgetting delete[] entirely: the program still works, which hides the leak.

Ask the class

  • "Why set readings = nullptr; if the program ends right after?" (Habit: in bigger programs the pointer may be used later, and a null pointer is easy to test.)

Lab 10 · Debugging

Common Pointer Errors

Most of these compile. At run time the program may crash, print garbage, or seem to work today and fail tomorrow (undefined behavior).

Safe pointer habits

  1. Initialize every pointer: a real address or nullptr.
  2. Check before following: if (p != nullptr) { … }
  3. After delete, set the pointer to nullptr.
  4. Match new↔delete and new[]↔delete[]; free each block exactly once.
  5. Never keep a pointer to a variable that no longer exists.

Why these are dangerous

  • "It worked when I ran it" proves nothing: undefined behavior can look correct.
  • A wild or dangling pointer can silently overwrite another variable.

Suggested time: about 6 min

Teaching tips

  • Ask pairs to name the bug in each block before you explain it.
  • Optional live demo: compile bug 1 with g++ -Wall. g++ warns "'p' is used uninitialized". Teach students to read warnings, not just errors (Lab 15 debugging preview).
  • Bug 2 usually crashes with "Segmentation fault" on Linux/Codechum, or the program just stops on Windows. Either way it's a bug.
  • Bug 3 often prints 7 or a random number. That is the scary part: it may look fine.

Common student pitfalls

  • Believing "no compile error" means "no bug".
  • Calling delete twice on the same pointer (also undefined). Deleting a nullptr is safe, one more reason to set it after delete.

Ask the class

  • "Which habit prevents bug 3?" (Set r to nullptr after delete, and check before use.)

Lab 10 · Check your understanding

Quick Check

Answer on paper first, then click to compare.

1After int x = 7; int* p = &x;, what are p and *p?

p is the address of x (some hex number like 0x7ffd10). *p is 7, the value at that address.

2Why does int& r; fail to compile?

A reference must be initialized when it is declared, e.g. int& r = x;. It cannot exist without a variable to refer to.

3int x = 5; int& r = x; int y = 8; r = y; What is x now?

8. r = y; copies y's value into x. r still refers to x; references cannot be re-seated.

4In int* a, b; what are the types of a and b?

a is int* (a pointer); b is a plain int. The * belongs to a only.

5int arr[5]; int* p = arr; How many bytes after p is p + 2?

8 bytes: 2 elements × sizeof(int) (4). p + 2 points to arr[2].

6You wrote double* d = new double[n];. How do you free it, and what next?

delete[] d; (with brackets, because it is an array), then d = nullptr; so it does not dangle.

Suggested time: about 6 min

Teaching tips

  • Think-pair-share: 2 minutes alone, 1 minute with a seatmate, then open the answers.
  • Questions 3 and 4 catch the most students. If many miss Q3, replay the reference tracer.

Common student pitfalls

  • Q5: answering "2 bytes".
  • Q6: forgetting the brackets in delete[].

Ask the class

  • "Which question would you put on a quiz?" Students choosing questions shows what they found hard.

Need a hint?

Hint 1

Read input with a pointer loop: for (int* p = temps; p < temps + SIZE; p++) { cin >> *p; }

Pointer minus pointer gives an element count: lowest - temps is the index (0–4). Add 1 for the position.

Teaching tips

  • Have students read the table aloud row by row. The middle column is the vocabulary they need for the exercise.
  • Preview Lab 11: "Next week you'll write void swapValues(int& x, int& y), a function that changes the caller's variables. Today's references make that possible."

Common student pitfalls

  • Leaving with "pointers are magic". Ask each student to say one row of the table in their own words.

Ask the class

  • "Which is safer for a function parameter you only need to rename, a reference or a pointer, and why?" (A reference: it cannot be null or re-seated.)
