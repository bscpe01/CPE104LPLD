From Functions to Objects

Functions organized our steps. Now we also need to organize our data.

Your toolbox so far

  • Variables, data types, operators (Labs 2–3)
  • Selection and loops (Labs 4–8)
  • Arrays, references, and pointers (Labs 9–10)
  • Functions: parameters, return values, pass-by-reference, overloading (Lab 11)

You've already used objects

string name = "Ana";

cin >> name;             // cin is an object

Today you learn to build your own types like string.

Spot the bug

Line 14 passes width1 instead of width2. It compiles and runs, but R2's area is wrong. Nothing in the code says that length2 and width2 belong together.

Suggested time: about 5 min

Teaching tips

  • Run the program first and ask if the output is right. Most students won't notice that R2 (3 × 3) should be 9, not 7.5.
  • Then ask: "With 30 rectangles, how many separate variables do we need? How easy is it to mix them up?" (60 variables, very easy.)

Lab 12 · Thinking in objects

Procedural vs Object-Oriented Thinking

Procedural code is organized around steps (functions). Object-oriented code is organized around things (objects) that keep their own data and functions together.

Procedural (Labs 2–11)Object-oriented (Labs 12–14)
Building blockFunctionsClasses and objects
Where data livesSeparate variables, passed around as argumentsInside each object, next to its functions
A call looks likearea(length2, width2)r2.area()
Works well forShort, step-by-step tasksBigger programs with many "things"

Suggested time: about 5 min

Teaching tips

  • Point at the tangle of lines on the left: any variable can be fed to any function. On the right, r2.area() can only use r2's length and width, so the Lab 11-style mix-up can't happen.
  • OOP is a way of organizing code, not a different kind of logic. Inside area() it's still one line of arithmetic.
  • C++ supports both styles. Many real programs mix them: classes for the "things", plain functions for small utilities.

Common student pitfalls

  • Believing OOP code is automatically shorter. For a 10-line program it is often longer. The payoff comes as programs grow.

Ask the class

  • "In a game, which would you rather manage: 50 loose variables per enemy, or 50 Enemy objects?"

Lab 12 · Thinking in objects

Objects Have State and Behavior

Look around the lab: every "thing" has data that describes it and actions it can perform.

ObjectState (attributes): what it knowsBehavior (methods): what it does
Smartphonebrand, batteryLevel, isOncall(), charge(), turnOn()
Studentname, studentNo, quizScoresenroll(), computeAverage()
Window-type airconsetTemp, mode, isOnturnOn(), setTemperature(), changeMode()
Rectangle (a math "thing")length, widtharea(), perimeter()

Key concept

An object = state + behavior. In C++, state is stored in data members (variables inside a class) and behavior is written as member functions (functions inside a class).

Try it (1 minute)

  1. Pick one object in the room: projector, electric fan, ID card, or the instructor's laptop.
  2. List 3 attributes and 2 behaviors.
  3. Which attributes change over time? Which never change?

Suggested time: about 5 min

Teaching tips

  • Do the "Try it" box out loud with two or three students. Write their answers on the board as a two-column list (State | Behavior). This is the first step of designing a class.
  • Attributes are usually nouns or adjectives (batteryLevel, isOn); behaviors are usually verbs (charge, turnOn). That rule of thumb helps students sort them.
  • Note that behaviors usually read or change the state: charge() raises batteryLevel, turnOn() sets isOn.

Common student pitfalls

  • Listing behaviors as attributes ("charging" as data instead of charge() as an action).
  • Including details the program doesn't need. A grading program needs a student's scores, not their shoe size. Choosing only what matters is abstraction.

Ask the class

  • "Is the number of students in a section an attribute of a Student or of a Section?" (A Section: good design question.)

Lab 12 · Thinking in objects

Class = Blueprint, Object = Instance

A class describes what every object of its kind has and can do. An object is one real thing built from it, with its own values.

Class (blueprint)Objects (instances)
House floor planThe houses built from it
Cookie cutterThe cookies
Blank enrollment formEach student's filled-in form
The type intint age = 18; (a variable)

Vocabulary

  • Class: a programmer-defined type (data + functions).
  • Object or instance: a variable of that type.
  • Instantiate: create an object from a class.

One class, many objects. Each object has its own copy of the data, but they all share the same member-function code.

Suggested time: about 4 min

Teaching tips

  • The last row of the table is the most useful: a class is to an object what int is to a variable. Students already know how to declare variables, and objects are declared the same way.
  • The blueprint has question marks because a class doesn't store values; only objects do.
  • "Instance" and "object" mean the same thing. Textbooks (Gaddis, Malik) use both.

Common student pitfalls

  • Saying "the class has length 4". Classes don't hold values; objects do.
  • Thinking that changing r1 changes r2. Each object is independent.

Ask the class

  • "If I make 1,000 Rectangle objects, how many copies of length exist? How many copies of the area() code?" (1,000; one.)

Lab 12 · Design before you code

UML Class Diagrams

The Unified Modeling Language (UML) is the standard way to sketch a class before coding it: three compartments stacked in one box.

Reading a member

  • Attribute: name : type
  • Operation: name(params) : returnType
  • A constructor has no return type.

Visibility symbols

  • + public: usable from anywhere
  • - private: only inside the class
  • # protected: Lab 13

Why bother?

  • It's the flowchart of a class: plan first.
  • Teammates agree on names and types.
  • Lab exercise specs are given in UML.

Suggested time: about 5 min

Teaching tips

  • Read the Rectangle box top to bottom: name, then attributes (data), then operations (functions). Then read Student and ask students to translate one line, e.g. - name : string becomes string name; under private:.
  • UML writes the type after the name (length : double); C++ writes it before (double length;). Expect this to trip people up once.
  • Rectangle uses + (public) data on purpose, since our first C++ version will be all public. Student shows the more common design: private data, public operations. Lab 13 explains why.
  • Free tools: draw.io (diagrams.net) has a UML shape library, but paper works fine.

Common student pitfalls

  • Swapping the meaning of + and -.
  • Putting operations in the middle compartment or forgetting the parentheses on operations.

Ask the class

  • "From the Student box: what does average() return, and does it take any parameters?" (A double; no parameters.)

Lab 12 · Classes in C++

Defining a Class in C++

A class definition turns the UML box into code. It creates a new type named Rectangle.

Note

Defining a class uses no memory for length or width. Memory is set aside when you create an object (next slide).

Anatomy of a class

  1. class + a name. By convention class names start with a capital letter: Rectangle, BankAccount.
  2. public: lets code outside the class (like main) use the members below it.
  3. Data members are variables declared inside the class.
  4. Member functions use the data members directly, so area() needs no parameters.
  5. The definition ends with };, a brace and a semicolon.
UMLC++ (under public:)
+ length : doubledouble length;
+ area() : doubledouble area() { … }

Suggested time: about 5 min

Teaching tips

  • Live-code it in Codechum or Code::Blocks: type the class first, compile (nothing happens, which is expected), then add a main() on the next slide.
  • Stress that area() has no parameters, unlike Lab 11's area(length, width). The function already "sees" the data of the object it is called on.
  • Members can be declared in any order, but the usual style is data first, then functions.

Common student pitfalls

  • Forgetting the ; after the closing brace. The g++ message is expected ';' after class definition, but some compilers report the error on the line after the class, which is confusing.
  • Writing the class inside main(). Put it above main(), just like function definitions in Lab 11.
  • Trying to give data members values from input inside the class, e.g. cin >> length; at class level. Statements belong inside functions.

Ask the class

  • "Write the line for + perimeter() : double." (double perimeter() { return 2 * (length + width); })

Lab 12 · Classes in C++

Member Functions Outside the Class: ::

For longer functions, keep only the prototype inside the class and write the body outside, prefixed with ClassName::.

returnType ClassName::functionName(parameters) { … }

Key concept

:: is the scope resolution operator. Rectangle::area means "the area function that belongs to Rectangle". The class definition then reads like a table of contents.

Common pitfall

Leave out Rectangle:: and you've written an ordinary function that knows nothing about the class. g++ says:

error: 'length' was not declared in this scope

Suggested time: about 5 min

Teaching tips

  • Connect to Lab 11: prototypes above main, definitions below. This is the same idea, but the prototypes live inside the class.
  • Both styles (inside or outside) produce the same program. Use inside for one-liners, outside for anything longer. Gaddis and Malik mostly define functions outside.
  • Optional preview: in multi-file projects the class goes in Rectangle.h and the Rectangle:: bodies in Rectangle.cpp. Not needed for Codechum.

Common student pitfalls

  • Putting Rectangle:: in the wrong place: Rectangle::double area(). The return type comes first.
  • Prototype and definition that don't match (different parameter types or return type).
  • Forgetting the ; after a prototype inside the class.

Ask the class

  • "Where else have you seen ::?" (std::cout: cout belongs to namespace std, the same operator.)

Lab 12 · Classes in C++

Access Specifiers: public vs private

public members can be used anywhere; private members can be used only inside the class's own member functions.

SpecifierWho can use the member?Typically used for
publicAny code that has the object (main, other functions)Member functions: the object's "buttons"
privateOnly member functions of the same classData members

What if main touches private data?

Rectangle r;
r.length = 4;      // length is private!

error: 'double Rectangle::length' is private within this context

Note

  • In a class, members are private by default until you write public:.
  • Why hide data at all? That's encapsulation, the main topic of Lab 13.

Suggested time: about 6 min

Teaching tips

  • Live demo: change r.setSize(4, 2.5); to r.length = 4; and compile. Read the error together and point out that it names the member (Rectangle::length) and says private.
  • Private does not mean secret or encrypted. It's a compile-time rule that stops other code from touching the data directly.
  • Analogy: an ATM. You press public buttons (withdraw, check balance) but you can't reach into the cash box. Lab 13's BankAccount builds exactly this.

Common student pitfalls

  • Making everything public "so it compiles". It works today but defeats the point of a class (Lab 13).
  • Forgetting the colon: public instead of public:.
  • Thinking a member function needs the object's name to use private data. Inside setSize, length is enough.

Ask the class

  • "If length is private, how does main give it a value?" (Through a public member function such as setSize, or a constructor, next slide.)

Lab 12 · Constructors

Constructors: Initialize Objects Automatically

A constructor is a special member function that runs by itself the moment an object is created, so the object never starts with garbage.

Constructor rules

  • Same name as the class.
  • No return type, not even void.
  • Runs automatically, once per object.
  • Can be overloaded: C++ picks the one whose parameters match the arguments (Lab 11).
  • A constructor with no parameters is the default constructor.

Member initializer list

// assign inside the body
Rectangle(double l, double w) {
    length = l;
    width = w;
}
// member initializer list (preferred)
Rectangle(double l, double w)
    : length(l), width(w) {}

Note

If you write any constructor, C++ stops giving you a free default one. With only Rectangle(double l, double w), the line Rectangle r; fails: no matching function for call to 'Rectangle::Rectangle()'.

Suggested time: about 8 min

Teaching tips

  • Ask the class to predict each line of output before showing it: a uses the default constructor (1 × 1), b the "square" constructor (3 × 3 = 9), c the two-argument one (4 × 2.5 = 10).
  • The initializer list after the colon is the preferred style (Gaddis, Deitel). Both versions give the same result for double members. Later, const members and base classes (Lab 13) require the list.
  • Members are initialized in the order they are declared in the class, not the order written in the list. g++ warns (-Wreorder) if the two orders differ.

Common student pitfalls

  • Adding void: void Rectangle() { … } gives return type specification for constructor invalid.
  • Writing Rectangle a(); to call the default constructor. Empty parentheses declare a function. Use Rectangle a;.
  • Calling the constructor like a normal function after the object exists (a.Rectangle(2, 3);). Constructors run only at creation.

Ask the class

  • "Which constructor runs for Rectangle d(2);, and what is its area?" (The square one; 4.)

Lab 12 · Constructors & more

The Destructor and the this Pointer

A destructor runs automatically when an object's life ends. this points to the object a member function is working on.

Destructor

  • Name: ~ + class name, e.g. ~Lamp().
  • No parameters, no return type, only one per class.
  • Runs when the object goes out of scope (its closing }), in reverse order of creation.

this pointer

  • this holds the address of the current object (Lab 10 pointers).
  • this->name is the member; plain name is the parameter.

Suggested time: about 5 min

Teaching tips

  • Have students predict the output first. Most will guess "Desk OFF" before "Ceiling OFF". The inner block makes the end of scope visible: b dies at line 23, a at the end of main.
  • Destructors matter most when a class grabs a resource (dynamic memory with new, a file, a network connection) and must release it. For today, just know when it runs.
  • this->name is shorthand for (*this).name, the arrow operator from Lab 10. Many programmers avoid the need by naming parameters differently (n instead of name).

Common student pitfalls

  • Writing name = name; in the constructor. That assigns the parameter to itself and leaves the member empty, and g++ gives no warning even with -Wall -Wextra.
  • Giving a destructor parameters or trying to overload it.
  • Calling the destructor yourself (a.~Lamp();). Don't: it will run again at the end of scope.

Ask the class

  • "If main created lamps A, B, C in that order, in what order do they turn OFF?" (C, B, A.)

Lab 12 · Constructors & more

Arrays of Objects

An array can hold objects too. s[i] is one Student, so s[i].name is that student's name.

s[0]Ana · 85 90 78
s[1]Jun · 92 88 95
s[2]Liza · 70 75 80

Read it left to right

s[i].average(): take array s → element i (a Student) → call its average().

Note

Student s[3]; builds every element with the default constructor. If a class has only a parameterized constructor, that line won't compile.

Suggested time: about 5 min

Teaching tips

  • Compare with Lab 9: without classes this needs four parallel arrays (name[3], q1[3], q2[3], q3[3]). Here one array holds whole students.
  • Averages print with 6 significant digits by default (84.3333). Add fixed << setprecision(2) for two decimals, as in earlier labs.
  • Student has no constructors, so the compiler supplies a default one and the array works. The members hold garbage until cin fills them.

Common student pitfalls

  • Writing s.name[i] instead of s[i].name. Index the array first, then pick the member.
  • Looping to i <= 3, which is out of bounds (undefined behavior, Lab 9).
  • Names with spaces: cin >> stops at a space, so "Ana Cruz" breaks the input. Use getline or single-word names.

Ask the class

  • "How would you print only the students with an average of at least 85?" (An if inside the second loop.)

Lab 12 · The bigger picture

struct vs class, and the Four Pillars of OOP

structclass
Default member accesspublicprivate
Member functions, constructors…AllowedAllowed
Usual styleA plain group of dataAn object with behavior and hidden data
 
struct Point {       // public by default
    double x;
    double y;
};

Point p = {3, 4};    // OK: x, y are public
cout << p.x << ", " << p.y << endl;

In C++, the default access is the only difference (and the default inheritance mode, Lab 13).

The four pillars of OOP

EncapsulationBundle data with its functions and hide the data behind a public interface. Lab 13
AbstractionShow what an object does, hide how. You call r.area() without caring about the formula. Today
InheritanceBuild a new class from an existing one: a Laptop is a Device. Lab 13
PolymorphismOne call, many forms: the right describe() runs for each kind of device. Lab 14

Suggested time: about 5 min

Teaching tips

  • Students may meet struct in other courses or in C code. In C++ it is a class whose members are public by default. Use struct for simple records (a point, a date) and class for real objects.
  • The pillars are a roadmap for the rest of Part 4. Don't define them deeply today; just name them and say where each one appears.
  • We already practiced abstraction today: the Try it activity chose only the attributes that matter, and main uses area() without knowing its formula.

Common student pitfalls

  • Believing a struct can't have functions. In C++ it can (in C it can't).
  • Mixing up encapsulation (bundling + hiding data) and abstraction (hiding complexity). They are closely related; the example in each card helps.

Ask the class

  • "Change struct Point to class Point. What happens to p.x?" (Compile error: x becomes private.)

Lab 12 · Debugging classes

Common Pitfalls with Classes

Each of these appears in almost every first OOP lab. Learn to recognize the compiler message.

1 · No ; after the class

class Rectangle { … }

g++: expected ';' after class definition

Fix: end with };

2 · Private member in main

r.length = 4;

g++: 'double Rectangle::length' is private within this context

Fix: use a public member function or a constructor.

3 · Method without ()

cout << r.area;

g++: invalid use of non-static member function 'double Rectangle::area()'

Fix: r.area()

4 · Constructor with a return type

void Rectangle() { … }

g++: return type specification for constructor invalid

Fix: no return type at all.

5 · Uninitialized members

Rectangle r; cout << r.area();

Compiles with no error, but length and width hold garbage (undefined behavior). It may even print 0 by luck.

Fix: a constructor, or double length = 0;

6 · Empty parentheses

Rectangle r();

Declares a function named r! Then r.area() gives request for member 'area' in 'r', which is of non-class type 'Rectangle()'

Fix: Rectangle r;

Suggested time: about 5 min

Teaching tips

  • All messages are from g++ 13 with -Wall -Wextra. Codechum and Dev-C++ also use g++, so students will see similar text. Visual Studio wording differs.
  • Quick game: show one broken line, students hold up 1–6 for which pitfall it is.
  • Pitfall 5 is the dangerous one: no error, sometimes the "right" answer by luck. On some runs or compilers it prints nonsense. Always initialize members (a constructor, or default values in the class like double length = 0;, allowed since C++11).
  • Pitfall 6 is called the "most vexing parse". g++ 13 also warns empty parentheses were disambiguated as a function declaration.

Common student pitfalls

  • Fixing only the first error and panicking at the rest. One missing ; can cause a cascade, so fix the first message and recompile.

Ask the class

  • "Which of these six will the compiler not catch?" (Number 5.)

Lab 12 · Check your understanding

Quick Check

Answer on your own first, then click to reveal.

1In one sentence: what is the difference between a class and an object?

A class is the blueprint (a programmer-defined type). An object is one instance of it in memory, with its own values.

2After Rectangle r1, r2, r3; how many width variables exist?

Three: r1.width, r2.width, and r3.width. Each object has its own copy of every data member.

3Translate this UML line to C++: - price : double

double price; placed under private: (or before any public: in a class, since class members are private by default).

4Using the three-constructor Rectangle, what does Rectangle d(5); cout << d.area(); print?

25. One argument matches Rectangle(double side), which makes a 5 × 5 square.

5Why doesn't this compile? class Point { int x; }; … Point p; p.x = 5;

Members of a class are private by default, so main can't use x. Add public: or use struct, or better, a constructor.

6Lamp a("A"); Lamp b("B"); in main. Which destructor runs first?

b's, then a's. Objects are destroyed in reverse order of creation.

Suggested time: about 6 min

Teaching tips

  • Think-pair-share: 1 minute alone, 1 minute with a seatmate, then reveal. Call on pairs instead of volunteers.
  • Q4 and Q6 are good to test in the compiler if there's disagreement.

Common student pitfalls

  • Q2: answering "one" because there is one class. Push the blueprint/instance idea again.
  • Q3: writing price double; (UML order) instead of double price;.

Lab 12 · Seatwork

Seatwork: A Circle Class

Instruction: Write a Circle class from the UML below (use PI = 3.14159265358979). In main(), ask for the radius, create a Circle with it, and print its area and circumference.

Need a hint?

Hint 1

Area = π r² and circumference = 2 π r. Inside the class, use radius; the functions need no parameters.

Hint 2

radius is private, so it must be set by the constructor: Circle(double r) : radius(r) {}

Hint 3

Read r first, then declare the object: Circle c(r);

Seatwork timer

10:00

Reveal answer & trace

Suggested time: about 15 min (10 working, 5 review)

Running the seatwork

  • Start the timer. Students type and run their code (Codechum or IDE). Open hints one at a time only if many are stuck.
  • Before revealing, show one student's working version and one with a compiler error, and debug the error together.
  • Reveal and trace with radius 5, then try 2.5 (area 19.635, circumference 15.708): cout drops trailing zeros.
  • Extension for fast finishers: add diameter(), or a setRadius(double) that ignores negative values (a preview of Lab 13).

Common student pitfalls

  • Declaring Circle c; before reading the radius. There is no default constructor, so it won't compile.
  • Writing area(radius) with a parameter, Lab 11 style. Member functions already see radius.
  • Using ^ for squaring (radius ^ 2): ^ is XOR in C++ and doesn't even compile with a double.
  • Using PI = 3.14, which gives 78.5 instead of 78.5398.

Ask the class

  • "Why is radius private but area() public?"
