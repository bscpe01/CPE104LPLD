Lab 7 · ILO 1

The Loop Control Variable (LCV)

Every loop is steered by a variable that goes through three steps: initialize it, test it, update it.

int count = 1;             // 1. initialize
while (count <= 5) {       // 2. test
    cout << count << " ";   //    body
    count++;               // 3. update
}
// prints: 1 2 3 4 5

If one step is wrong

  • No initialize: the LCV starts with a garbage value.
  • Wrong test: the loop runs one time too many or too few (off-by-one).
  • No update: the test never changes, so the loop never ends (infinite loop).

Each pass through the body is called an iteration. This loop has 5 iterations and 6 tests (the last test is false).

Suggested time: about 6 min

Teaching tips

  • Have students say "initialize, test, update" aloud, then point at each part in the code and in the flowchart. You will use this vocabulary all lab.
  • Count tests vs iterations: 5 iterations but 6 tests. The extra false test is how the loop exits. This matters when tracing.
  • The upward arrow passes 3 symbols, the maximum allowed by the Lab 1 flowcharting rules.

Common student pitfalls

  • Drawing the loop-back arrow to Start or to the initialization box. It must return to the test; re-initializing would restart the count every time.
  • Putting the update before the body and then being surprised that the output starts at 2.

Ask the class

  • "What prints if we start at count = 6?" (Nothing. The first test is already false.)

Lab 7 · How a loop knows when to stop

Counter-, Sentinel- & Flag-Controlled Loops

Loops are classified by what controls them. Choose based on whether you know the number of repetitions in advance.

Counter-controlled

Use when: you know how many times (5 quizzes, 1 to n).

for (int i = 1; i <= 5; i++) {
    cout << "Quiz " << i << ": ";
    cin >> score;
}

Stops when the counter passes its limit.

Sentinel-controlled

Use when: the amount of data is unknown; a special value marks the end.

cin >> grade;
while (grade != -1) {
    // process grade
    cin >> grade;
}

Read once before the loop (priming read) and again at the end of the body. Stops when the sentinel (-1) is read; it is never processed as data.

Flag-controlled

Use when: you stop once something happens inside the loop.

bool found = false;
int num = 1;
while (!found) {
    if (num * num > 500) {
        found = true;
    } else {
        num++;
    }
}
// num is 23

Stops when the bool flag changes.

Suggested time: about 6 min

Teaching tips

  • Counter: the number of repetitions is known before the loop starts (even if it comes from input, like n).
  • Sentinel: choose a value that can never be real data. -1 works for grades (0–100); it would not work for temperatures.
  • Flag: the flag example finds the first whole number whose square is over 500. 22² = 484, 23² = 529, so it stops at 23. Lab Exercise 7 Problem 2 needs this pattern.
  • The full sentinel program is traced later (Sentinel slide).

Common student pitfalls

  • Forgetting the priming read, so the first test uses an uninitialized grade.
  • Adding the sentinel into the total (the average then includes -1).

Ask the class

  • "A cashier scans items until the customer is done. Which loop type?" (Sentinel or flag. A counter does not work because the number of items is unknown.)

Lab 7 · Entry-controlled (pre-test) loop

The while Loop

The condition is tested before each iteration. If it is false at the start, the body runs zero times.

while (condition) { statements; }

Suggested time: about 8 min

Teaching tips

  • Trace n = 3 step by step, then n = 0: the test is false immediately, the body never runs, and only "Liftoff!" prints. That is what "entry-controlled" means.
  • Here the LCV is n itself: initialized by cin, tested by n > 0, updated by n--.
  • Real output for 5: 5... 4... 3... 2... 1... Liftoff! on one line, because only the last cout has endl.

Common student pitfalls

  • Writing while (n > 0); with a semicolon: an empty body that never updates n, so the program hangs.
  • Forgetting n--: "5... 5... 5..." forever. Stop a runaway program with Ctrl+C in a terminal or the IDE's stop button; online compilers usually cut it off after a time limit.

Ask the class

  • "What happens for n = -3?" (Same as 0: only Liftoff!.) "How many tests run for n = 5?" (6.)

Lab 7 · Entry-controlled counter loop

Anatomy of the for Loop

A for loop puts all three LCV steps on one line, so a counter loop is hard to get wrong.

for (1. initialize; 2. test; 4. update) { 3. body; }

Order of execution

  1. Initialize runs once, before anything else.
  2. Test runs before every iteration. False → leave the loop.
  3. Body runs.
  4. Update runs, then go back to step 2.
1 2 3 4 5
Common variations
for (int i = 10; i >= 1; i--)Count down 10 … 1
for (int i = 0; i < n; i++)Exactly n times (0 … n-1)
for (int i = 2; i <= 20; i += 2)Even numbers 2 … 20

Scope

An int i declared in the for exists only inside the loop. Using it after the closing brace is a compile error.

Suggested time: about 7 min

Teaching tips

  • Number the parts on the board in execution order: 1 (init) → 2 (test) → 3 (body) → 4 (update) → 2 → 3 → 4 → … Students often think the update runs first because it is written before the body.
  • Rewrite the for as a while (right) to show it is the same loop with the three LCV parts gathered on one line.
  • i++ and ++i behave the same in the update part of a for loop. The difference only matters inside larger expressions (Lab 4).
  • The output has a trailing space after 5 that you cannot see. That is normal for this pattern.

Common student pitfalls

  • Using commas instead of semicolons: for (int i = 1, i <= 5, i++) does not compile.
  • Using i after the loop when it was declared inside the for.

Ask the class

  • "How many times does for (int i = 0; i < 10; i += 3) run, and with which values?" (4 times: 0, 3, 6, 9.)

Lab 7 · Exit-controlled (post-test) loop

The do-while Loop

The body runs first, then the test, so it always runs at least once: ideal for input validation and menus.

do { statements; } while (condition);

Suggested time: about 8 min

Teaching tips

  • Compare with the Lab 6 validation slide: an if could only reject bad input. A do-while re-asks until the input is good.
  • In the tracer, type several values separated by spaces (e.g. 150 101 100) to simulate a user who keeps typing. 100 is accepted: test the boundary.
  • In the flowchart, the body (Input) comes before the Decision. That is the visual signature of a post-test loop, and it matches REPEAT … UNTIL from Lab 1.
  • Menus are the other classic use: show the menu at least once, repeat until the user picks Exit. Lab 8 builds menu-driven programs.

Common student pitfalls

  • Forgetting the semicolon after while (…) in a do-while. It is required here (and only here).
  • Writing the "good" condition (grade >= 0 && grade <= 100) in the while, so the loop repeats on valid input. The condition must describe when to repeat.
  • Declaring grade inside the do { } block. The while condition cannot see it (scope).

Ask the class

  • "How many times does the body run if the first value is valid?" (Once.) "Could a while loop do this?" (Yes, with a priming read before the loop, but do-while avoids writing the prompt twice.)

Choosing the Right Loop

All three loops can solve any repetition problem. Pick the one that makes your intent obvious.

Ask: do I know the count?

Yes → for. "Print 10 rows", "read n values".

Ask: must it run once first?

Yes → do-while. "Ask, then check", "show the menu, then read a choice".

Otherwise

while. "Keep going until the sensor says stop".

Suggested time: about 4 min

Teaching tips

  • Call out scenarios and have students vote with fingers (1 = while, 2 = for, 3 = do-while): "print a 12-row multiplication table" (2), "ATM PIN entry, re-ask on wrong PIN" (3), "read sensor values until the value 999" (1).
  • Stress that the choice is about readability. A for loop with an empty test or a while loop that counts are legal but make readers work harder.

Common student pitfalls

  • Using do-while for a sentinel loop and processing the sentinel once by accident.
  • Believing for is "faster". All three compile to essentially the same machine code.

Ask the class

  • "Can every for loop be rewritten as a while loop? And the other way around?" (Yes to both. The choice is about readability.)

Lab 7 · Loop patterns

Counters & Accumulators

A counter adds 1 when something happens. An accumulator collects a running total (or product). Both must be initialized before the loop.

#include <iostream>
using namespace std;

int main() {
    int n, score;
    int total = 0;
    cout << "How many quizzes? ";
    cin >> n;

    for (int i = 1; i <= n; i++) {
        cout << "Quiz " << i << ": ";
        cin >> score;
        total += score;
    }
    double average = static_cast<double>(total) / n;
    cout << "Total = " << total << endl;
    cout << "Average = " << average << endl;
    return 0;
}

How many quizzes? 3
Quiz 1: 85
Quiz 2: 90
Quiz 3: 78
Total = 253
Average = 84.3333
  • total starts at 0 (the identity for addition).
  • total / n would be integer division: 253 / 3 = 84. static_cast<double>(total) makes it 84.3333.
#include <iostream>
using namespace std;

int main() {
    int count = 0;

    for (int num = 1; num <= 100; num++) {
        if (num % 7 == 0) {
            count++;
        }
    }
    cout << "Multiples of 7: " << count << endl;
    return 0;
}

Multiples of 7: 14
  • count starts at 0 and increases only when the condition is true.
  • A loop + an if inside = "count (or sum) the items that match".
#include <iostream>
using namespace std;

int main() {
    int n;
    long long factorial = 1;   // start at 1, not 0
    cout << "Enter n (0-20): ";
    cin >> n;

    for (int i = 2; i <= n; i++) {
        factorial *= i;
    }
    cout << n << "! = " << factorial << endl;
    return 0;
}

Enter n (0-20): 20
20! = 2432902008176640000
  • A product starts at 1. Starting at 0 makes every answer 0.
  • long long (8 bytes, up to about 9.22 × 1018) holds up to 20!. An int (4 bytes) overflows at 13!.
  • For n = 0 or 1 the loop runs zero times and the answer is 1, which is correct.
#include <iostream>

int main() {

    cout << "How many readings? ";
    cin >> n;
    cout << "Reading 1: ";
    cin >> reading;

    highest = reading;   // the min and max so far

        cin >> reading;
        if (reading < lowest) {
            lowest = reading;
        }
        if (reading > highest) {
            highest = reading;
        }
    }
    cout << "Min = " << lowest << endl;
    cout << "Max = " << highest << endl;
    return 0;
}

How many readings? 5
Reading 1: 31.5
Reading 2: 28
Reading 3: 35.2

Suggested time: about 12 min (3 per tab)

Teaching tips

  • For each tab ask the same three questions: What is initialized before the loop? What changes inside? What is printed after?
  • Sum & average: run it once with total / n to show 84, then fix it with static_cast (Lab 3/4).
  • Factorial: run with 13 using int to show a wrong answer (1932053504 on g++ instead of 6227020800). Signed overflow is undefined behavior, so the exact wrong value can differ between compilers.
  • Min & max: the first value is read before the loop, so the loop starts at i = 2.

Common student pitfalls

  • Initializing the accumulator inside the loop, which resets it each time.
  • Average with n = 0: 0.0 / 0 prints nan (or -nan). Validate n first (do-while!).
  • Min & max: reading the first value before the loop and starting the loop at i = 1, which asks for one reading too many.

Ask the class

  • "How would you count the passing quizzes (75 and up) in the first tab?" (Add int passed = 0; and if (score >= 75) passed++; in the loop.)

Divisible by 3: One Problem, Four Loops

Print all numbers from 1 to 100 that are divisible by 3, one per line. All four versions print the same 33 numbers.

#include <iostream>
using namespace std;

int main() {
    int num = 1;
    while (num <= 100) {
        if (num % 3 == 0) {
            cout << num << endl;
        }
        num++;
    }
    return 0;
}

#include <iostream>
using namespace std;

int main() {
    for (int num = 1; num <= 100; num++) {
        if (num % 3 == 0) {
            cout << num << endl;
        }
    }
    return 0;
}

#include <iostream>
using namespace std;

int main() {
    int num = 1;
    do {
        if (num % 3 == 0) {
            cout << num << endl;
        }
        num++;
    } while (num <= 100);
    return 0;
}

#include <iostream>
using namespace std;

int main() {
    for (int num = 3; num <= 100; num += 3) {
        cout << num << endl;
    }
    return 0;
}

Start at the first multiple and jump by 3: no % test needed. Once a loop works, look for a simpler version.

Teaching tips

  • Put Lab 1's pseudocode on the board and translate it line by line into the while version first. Then show for and do-while as rearrangements of the same LCV steps.
  • The work table was measured by counting: the while/for test runs for num = 1 … 101 (the last test is false), do-while tests after each of the 100 bodies, and the step-by-3 loop tests num = 3, 6, … 102.

Lab 7 · Sentinel-controlled while loop

Sentinel Loop: Average Grades Until -1

The user does not know in advance how many grades there are. Typing -1 (the sentinel) ends the input.

Suggested time: about 10 min

Teaching tips

Lab 7 · Debugging

Spot the Bug: Six Loop Pitfalls

Each of these compiles. Trace one or two iterations by hand to see what goes wrong.

1 · Infinite loop

int count = 1;
while (count <= 5) {
    cout << count;
}

No update: count stays 1 and prints forever. Fix: add count++; in the body.

2 · Off-by-one

// print 1 to 10
for (int i = 1; i < 10; i++) {
    cout << i << " ";
}

Prints 1 … 9 only. Fix: i <= 10. Always test the first and last values.

3 · Semicolon after the header

for (int i = 1; i <= 5; i++); {
    cout << "Hi" << endl;
}

The ; is the (empty) loop body. "Hi" prints once. With while (…); the program hangs.

4 · Uninitialized accumulator

int sum;
for (int i = 1; i <= 5; i++) {
    sum += i;
}

sum starts with garbage, so the result is unpredictable. g++ may not even warn. Fix: int sum = 0;

5 · Integer overflow

int fact = 1;
for (int i = 2; i <= 13; i++) {
    fact *= i;
}

13! = 6,227,020,800 does not fit in an int (max 2,147,483,647). g++ printed 1932053504. Fix: long long.

6 · Changing the LCV in the body

for (int i = 1; i <= 10; i++) {
    cout << i << " ";
    i++;
}

i goes up twice per pass: prints 1 3 5 7 9. Fix: update only in the header (use i += 2 if you mean it).

Suggested time: about 8 min

Teaching tips

  • Run it as a game: pairs get 30 seconds per card to predict the output before you reveal the explanation.
  • #1 and the while (…); case in #3 hang the program. Show students how to stop it: Ctrl+C in a terminal or the IDE's stop button (online compilers usually stop it after a time limit).
  • With -Wall, g++ flags #3 ("this 'for' clause does not guard…"). #4 is only reported with optimization on (-O2), and #1, #2, #5 and #6 are never reported. Testing is the real safety net.
  • #5: signed integer overflow is undefined behavior. The value 1932053504 is what g++ printed in our test, not a guaranteed result.

Common student pitfalls

  • "Fixing" #2 by changing the start to 0, which prints 0 … 9 instead.
  • Believing that because the program compiled, the loop must be right.

Ask the class

  • "In #3, what is the value of i when "Hi" prints?" (Trick question: that i no longer exists. Using it there would not compile.)

Done. The while test is false at the start, so the body runs zero times.

3Output? int n = 0; do { cout << n; n--; } while (n > 0); cout << "Done";

0Done. A do-while runs the body once before testing.

Wrap-up

Loops in One Slide

The LCV checklist

  1. Initialize before the loop.
  2. Test in the condition.
  3. Update inside the loop, every iteration.

Pre-test vs post-test

  • while, for: test first, may run 0 times.
  • do-while: runs at least once; needs ; at the end.

Patterns

  • Counter: start 0, ++.
  • Sum: start 0. Product: start 1.
  • Min/max: start with the first value.
  • Sentinel: priming read + read at the end.

Remember

  • Trace with a desk-check table before you run.
  • Test 0, 1, and the boundaries.
  • Ctrl+C stops an infinite loop.
