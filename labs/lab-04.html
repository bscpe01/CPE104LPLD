Lab 4 · Arithmetic operators

Integer vs. Floating-Point Division

The types of the operands, not the variable that receives the result, decide which kind of division happens.

Rules

  • int / int → int: the fraction is dropped, truncated toward zero (−3.5 → −3).
  • If either operand is a double, you get real division.
  • The sign of a % b follows a. Always: (a / b) * b + a % b == a.

Common pitfall

% needs integer operands. 7.5 % 2 does not compile: error: invalid operands of types 'double' and 'int' to binary 'operator%'. For doubles, use fmod(7.5, 2) from <cmath>.

Suggested time: about 7 min

Teaching tips

  • Cover the output and have students write their predictions for all 8 lines first. Collect a show of hands for -7 / 2: −3 or −4? C++ (since C++11) always truncates toward zero, so it's −3. Python's floor division (-7 // 2) gives −4, which is a good "languages differ" moment.
  • Verify the identity on the board for −7 and 3: (-7 / 3) * 3 + (-7 % 3) = (−2)(3) + (−1) = −7. ✔
  • A literal with a decimal point (7.0, 2.0) is a double. That one dot changes the result.

Common student pitfalls

  • Thinking double x = 7 / 2; stores 3.5. The division happens first, with ints, so 3 is stored (as 3.0).
  • Expecting % to always be positive, as in math class. In C++, -7 % 3 is −1, not 2.
  • Forgetting #include <cmath> for fmod. Some compilers still build it through another header; don't rely on that.

Ask the class

  • "What is 9 / 4 * 4?" (8, not 9.) "What is -9 % 4?" (−1.)

Lab 4 · Mixed-type expressions

Type Conversion and static_cast

When types mix, C++ converts values, sometimes automatically and sometimes only when you ask.

Implicit conversion (automatic)

  • Promotion: in int op double, the int is converted to double first. 5 + 2.5 → 7.5.
  • On assignment: the value is converted to the variable's type. int n = 9.99; stores 9, with the fraction truncated and no error.

Explicit conversion (a cast)

static_cast<type>(expression)

static_cast<double>(sum) / count makes sum a double before dividing, so the division is real division.

Common pitfall

Triangle area 1 / 2 * base * height is always 0, because 1 / 2 is integer division. Write 0.5 * base * height.

Suggested time: about 7 min

Teaching tips

  • Ask: "Why does wrong show 84 even though it is a double?" Because 253 / 3 is computed with ints (84), and only then stored as 84.0. The receiving variable's type comes too late.
  • Placement matters: static_cast<double>(sum / count) is still 84, because the integer division happens inside the parentheses first.
  • Older books (and Gaddis/Malik) also show the C-style cast (double) sum, and some decks use the functional form double(sum) or int(9.99) (Lab 3 notes mention these). For these simple number types all three do the same thing; static_cast is the modern, easier-to-search form.
  • 84.3333 has 6 significant digits, which is the default for cout. Lab 5 shows how to print exactly 2 decimals.

Common student pitfalls

  • Casting the result instead of an operand: static_cast<double>(sum / count).
  • Expecting int n = 9.99; to round to 10. It truncates to 9, and g++ gives no warning with -Wall.

Ask the class

  • "Give two different fixes for 1 / 2 * base * height." (0.5 * base * height, base * height / 2.0, or 1.0 / 2 * base * height.)

Lab 4 · Assignment operators

Assignment and Compound Assignment

= evaluates the right side, then stores the value in the variable on the left. It is an instruction, not an equation.

OperatorExampleSame asx becomes
+=x += 5;x = x + 5;20 → 25
-=x -= 3;x = x - 3;25 → 22
*=x *= 2;x = x * 2;22 → 44
/=x /= 5;x = x / 5;44 → 8
%=x %= 3;x = x % 3;8 → 2

Key concept

  • The whole right side is computed first: x *= y + 1 means x = x * (y + 1).
  • Assignment groups right to left: a = b = 0; is a = (b = 0);
  • The left side must be a variable. 5 = x; does not compile.

Suggested time: about 5 min

Teaching tips

  • Read x = x + 5 aloud as "x gets x plus 5" or "store x + 5 into x". Mathematically it's impossible; as an instruction it's natural.
  • Each line in the table continues from the previous value, exactly like the program. Run it and compare.
  • Compound assignment is shorter and avoids typos in long names: total_energy_kwh += reading;
  • The last line (x *= y + 1 → 2 × 5 = 10) is the trap worth stopping on. A student who expands it as x * y + 1 gets 9.

Common student pitfalls

  • Writing =+ instead of +=. x =+ 5; compiles as x = +5; and silently stores 5.
  • Putting a space inside the operator: x + = 5; is a syntax error.

Ask the class

  • "If x = 7, what is x after x %= 4; x *= x;?" (3, then 9.)

Lab 4 · Unary operators

Increment ++ and Decrement --

Both add or subtract 1. The position (before or after the variable) decides which value the expression uses.

#include <iostream>
using namespace std;

int main() {
    int a = 5;
    int b = a++;    // use a, THEN add 1
    int c = ++a;    // add 1, THEN use a
    cout << "a = " << a << endl;
    cout << "b = " << b << endl;
    cout << "c = " << c << endl;
    int d = a--;    // use a, THEN subtract 1
    int e = --a;    // subtract 1, THEN use a
    cout << "d = " << d << ", e = " << e
         << ", a = " << a << endl;
    return 0;
}
FormNameWhat happens
++a / --aPrefixChange a first, then use the new value
a++ / a--PostfixUse the current value, then change a

Common pitfall

  • Changing the same variable twice in one expression, e.g. x = a++ + a++;, is undefined behavior. Different compilers may print different answers.
  • Alone on a line, count++; and ++count; do the same thing.

Suggested time: about 8 min

Teaching tips

  • Press Step slowly on lines 6 and 7. Each takes two steps so students see the order: postfix copies first, then changes a; prefix changes a first, then copies.
  • Memory hook: read left to right. In ++a you see ++ first, so the increment comes first. In a++ you see a first, so its value is used first.
  • Prefix/postfix only matters when the expression's value is used (assigned, printed, or combined). Loops in Lab 7 use i++ alone, where it makes no difference.

Common student pitfalls

  • Thinking b = a++ gives b the new value.
  • Forgetting that a itself still changes in both forms.
  • Writing a+ + or a + 1++. Only variables can be incremented.

Ask the class

  • "With int n = 10;, what does cout << n++ << endl; print, and what is n afterward?" (10, then n is 11.)

Lab 4 · Relational operators

Relational Operators Produce bool

A comparison asks a yes/no question. The answer is true or false, which cout prints as 1 or 0.

OperatorMeaningx = 7, y = 10Value
==equal tox == yfalse (0)
!=not equal tox != ytrue (1)
<less thanx < ytrue (1)
>greater thanx > yfalse (0)
<=less than or equal tox <= 7true (1)
>=greater than or equal tox >= yfalse (0)

Common pitfall

  • cout << x < y; does not compile. << ranks above <, so C++ reads it as (cout << x) < y. Write cout << (x < y);
  • =< and => are not operators. The = always comes second.

Suggested time: about 6 min

Teaching tips

  • Connect to Lab 3: bool is 1 byte and holds true or false. Relational expressions are where bools come from.
  • boolalpha is "sticky": once sent to cout, every later bool prints as a word until noboolalpha.
  • In x * 10 >= 75 no parentheses are needed: arithmetic ranks above relational, so it is (x * 10) >= 75.
  • Preview Lab 6: these expressions become the conditions in if (score >= 75).

Common student pitfalls

  • Using = to compare. x = y assigns; it doesn't compare.
  • Comparing doubles with ==: 0.1 + 0.2 == 0.3 is false because of binary rounding. Compare with a tolerance instead (e.g. fabs(a - b) < 1e-9).
  • Characters compare by code: 'A' < 'a' is true (65 < 97).

Ask the class

  • "What does cout << (5 != 5); print?" (0.) "With boolalpha?" (false.)

Lab 4 · Logical operators

Logical Operators and Short-Circuit Evaluation

&& (AND), || (OR), and ! (NOT) combine conditions, just like Lab 1's AND, OR, NOT.

Truth table
ABA && BA || B!A
falsefalsefalsefalsetrue
falsetruefalsetruetrue
truefalsefalsetruefalse
truetruetruetruefalse

Short-circuit evaluation

  • C++ evaluates the left operand first.
  • && stops at the first false; || stops at the first true. The right side is never run.
  • So b != 0 && a / b > 2 is safe even when b is 0.

CpE connection

These are the same truth tables as the AND, OR, and NOT logic gates you will build in digital logic design.

Suggested time: about 8 min

Teaching tips

  • Same wording as Lab 1: AND is false if any part is false; OR is true if any part is true.
  • Demo the short-circuit: swap the operands to a / b > 2 && b != 0 and run with b = 0. The division now happens first, and the program typically crashes ("Floating point exception"). Order matters!
  • Line 12 is a range check: "abnormal temperature" means outside 36.0–37.5 °C. Ask what the opposite (normal) condition is: temp >= 36.0 && temp <= 37.5. That is De Morgan's law in action.
  • ! ranks very high, so !(temp > 37.5) needs its parentheses. Without them, !temp > 37.5 means (!temp) > 37.5, which is nonsense.

Common student pitfalls

  • Writing a single & or |. Those are bitwise operators: they compile, never short-circuit, and can give surprising results.
  • Writing temp < 36.0 || > 37.5. Each side of || must be a complete condition.

Ask the class

  • "Write a condition that is true when age is from 13 to 19." (age >= 13 && age <= 19.)

Lab 4 · The hierarchy · ILO 2

Operator Precedence and Associativity

Precedence: which operator goes first. Associativity: which side goes first on a tie.

Highest precedence first (operators used in this course)
#OperatorsKindAssociativity
1a++ a-- f(x)Postfix, function callleft → right
2++a --a -a +a !Prefix, unary, NOTright → left
3* / %Multiplicativeleft → right
4+ -Additiveleft → right
5<< >>Stream (shift)left → right

Associativity in action

  • 20 - 5 - 3 → (20 - 5) - 3 = 12, not 18
  • 100 / 10 / 2 → (100 / 10) / 2 = 5, not 20
  • a = b = c = 0 → a = (b = (c = 0))
  • !x && y → (!x) && y

Precedence in action

  • x + y * 2 → x + (y * 2)
  • a > 0 && b > 0 || c > 0 →
    ((a > 0) && (b > 0)) || (c > 0)
  • cout << a + b → cout << (a + b) ✔

Parentheses ( ) beat everything. When in doubt, add them. They cost nothing and make your intent obvious.

Suggested time: about 8 min

Teaching tips

  • Big picture first: unary → arithmetic → stream → relational → equality → AND → OR → assignment. Assignment is last because the whole right side must be computed before anything is stored.
  • Mnemonic used in many C/C++ courses: "PUMAS REBL TAC" (Postfix, Unary, Multiplicative, Additive, Shift, Relational, Equality, Bitwise, Logical, Ternary, Assignment, Comma). We skip bitwise and comma in this course.
  • static_cast<T>(x) sits at level 1 with function calls. A C-style cast (double) x sits at level 2.
  • The ternary operator ?: is covered in Lab 6.
  • This table leaves out operators students haven't met yet (::, [], ., ->, bitwise & ^ |, comma). The complete table is on cppreference.com under "C++ Operator Precedence".
  • Precedence decides grouping, not always the order in which operands run. For example, && and || always run their left side first (short-circuit).

Common student pitfalls

  • Applying strict "PEMDAS": thinking addition always comes before subtraction. + and - share one level and go left to right.
  • Assuming && and || have equal precedence. && binds tighter.

Ask the class

  • "Which runs first in total = price * qty + fee?" (*, then +, then =.)

Lab 4 · Code tracing · ILO 2

Evaluate It by Hand, Step by Step

Find the highest-precedence operator, compute it, rewrite the expression, and repeat.

Evaluate step by step

10 + 6 / 2 * 3 - 4 % 3

  1. 6 / 2 = 3 → 10 + 3 * 3 - 4 % 3
  2. 3 * 3 = 9 → 10 + 9 - 4 % 3
  3. 4 % 3 = 1 → 10 + 9 - 1
  4. 10 + 9 = 19 → 19 - 1
  5. 19 - 1 = 18 Answer: 18

Fully parenthesized

(10 + ((6 / 2) * 3)) - (4 % 3)

* / % share level 3 and go left to right, then + - share level 4 and go left to right.

Same as Lab 1?

Yes: C++ also gives 18. Now change 6 to 7: 10 + 7 / 2 * 3 - 4 % 3 is still 18 in C++, because 7 / 2 is 3. On a calculator it would be 19.5.

Evaluate step by step

5 + 3 >= 2 * 4 && !(7 % 2 == 0)

  1. 7 % 2 = 1 → 5 + 3 >= 2 * 4 && !(1 == 0)
  2. 1 == 0 is false → 5 + 3 >= 2 * 4 && !false
  3. !false = true → 5 + 3 >= 2 * 4 && true
  4. 2 * 4 = 8 → 5 + 3 >= 8 && true
  5. 5 + 3 = 8 → 8 >= 8 && true
  6. 8 >= 8 is true → true && true
  7. true && true Answer: true (cout prints 1)

Fully parenthesized

((5 + 3) >= (2 * 4)) && (!((7 % 2) == 0))

Order of levels: ( ), then !, then * %, +, >=, ==, and finally &&.

Precedence vs. evaluation order

Precedence only decides the grouping. When the program runs, && computes its left side first (short-circuit). The answer is the same either way.

Evaluate step by step · start with x = 4, y = 3

x += y++ * 2

  1. y++ gives the old y, 3 (y becomes 4) → x += 3 * 2
  2. 3 * 2 = 6 → x += 6
  3. x = x + 6 = 4 + 6 → x = 10
  4. x = 10, y = 4 Answer: x is 10, y is 4

Fully parenthesized

x += ((y++) * 2)

Postfix ++ is level 1, * is level 3, and += is level 10, so the assignment happens last.

Try the prefix version

With x += ++y * 2 (again x = 4, y = 3): y becomes 4 first, 4 × 2 = 8, so x = 12 and y = 4.

Suggested time: about 10 min

Teaching tips

  • Use the tabs one at a time. For each, give students 60 seconds to work it on paper first, then click Show next step while they check.
  • Technique to teach: underline the operator you apply at each step, and copy the whole rewritten expression on a new line, like the reveal. Lab Exercise Part 3 asks for exactly this format.
  • In tab B, the order shown (parentheses first) is the hand-evaluation order. The compiled program evaluates 5 + 3 >= 2 * 4 first and would skip the right side if it were false. Same answer, as long as there are no side effects.
  • Verify each in Codechum: cout << (5 + 3 >= 2 * 4 && !(7 % 2 == 0)); prints 1.

Common student pitfalls

  • Doing 10 + 6 first (strict left to right).
  • In B, applying ! only to 7. The parentheses make it apply to the whole comparison.
  • In C, using the new y (4) in the multiplication.

Ask the class

  • "Evaluate 12 - 4 * 3 / 2 % 5." (4 * 3 = 12, 12 / 2 = 6, 6 % 5 = 1, 12 - 1 = 11.)

Lab 4 · Code tracing

Trace It: A Program of Mixed Expressions

Predict every output line on paper, then step through and check your work.

#include <iostream>
using namespace std;

int main() {
    int x, y;
    cout << "Enter x and y: ";
    cin >> x >> y;
    int r1 = x + y * 2 - x % 3;
    int r2 = (x + y) / 2;
    double r3 = static_cast<double>(x + y) / 2;
    bool r4 = x > y || (y % 2 == 0 && x != 0);
    x += y++ * 2;
    cout << "r1 = " << r1 << endl;
    cout << "r2 = " << r2 << endl;
    cout << "r3 = " << r3 << endl;
    cout << "r4 = " << r4 << endl;
    cout << "x = " << x << ", y = " << y << endl;
    return 0;
}

Why the parentheses on line 11?

Without them, the meaning is the same (&& binds tighter than ||), but g++ -Wall warns "suggest parentheses around '&&' within '||'". Add them for clarity.

Suggested time: about 10 min

Teaching tips

  • Give students 3 minutes with 7 and 4 on paper. Then press Step; each status line explains which operator goes first.
  • Then try inputs that change the story: 3 8 (x > y is false, so || must check the right side), 3 7 (r4 false, and r2 = 5 while r3 = 5.0 prints as 5), and -7 2 (negative %: −7 % 3 = −1).
  • Point out line 15: a double holding 5.5 prints as 5.5, and 5.0 prints as 5. Default cout drops trailing zeros.

Common student pitfalls

  • For r1, computing x + y first (7 + 4 = 11, 11 × 2 = 22 …).
  • For r4, expecting the output true. Without boolalpha, a bool prints as 1 or 0.
  • On line 12, forgetting that y changes too (it prints 5, not 4).

Ask the class

  • "Which variable would change if line 12 were x += ++y * 2?" (Both still change, but x becomes 7 + 10 = 17.)

Lab 4 · CpE application

Splitting a Number into Digits with / and %

A three-digit 7-segment display needs each digit separately. Integer / removes digits from the right; % 10 keeps only the last digit.

#include <iostream>
using namespace std;

int main() {
    int reading;
    cout << "Enter a 3-digit reading: ";
    cin >> reading;
    int hundreds = reading / 100;
    int tens = (reading / 10) % 10;
    int ones = reading % 10;
    int reversed = ones * 100 + tens * 10 + hundreds;
    cout << "Hundreds: " << hundreds << endl;
    cout << "Tens    : " << tens << endl;
    cout << "Ones    : " << ones << endl;
    cout << "Reversed: " << reversed << endl;
    return 0;
}
ExpressionWith 472Idea

(n / 10) % 1047 % 10 = 7drop 1, keep the last
n % 102keep the last digit

Suggested time: about 7 min

Teaching tips

  • Real use: a microcontroller driving three 7-segment digits must send each digit separately. The same / and % trick splits seconds into minutes and seconds (the seatwork) and pesos into bills (the lab exercise).
  • Trace 472, then 905 (tens = 0, reversed = 509), then 120 (reversed = 21: the leading zero of "021" disappears, because an int has no leading zeros).
  • General pattern: the k-th digit from the right is (n / 10k) % 10.

Common student pitfalls

  • Writing reading / 10 % 10 without parentheses. It still works (same level, left to right), but the parentheses show the intent.
  • Using double reading. Then % won't compile and / keeps the fraction.
  • Entering a 4-digit number like 1472: "hundreds" becomes 14. The program assumes valid input. Checking it needs if (Lab 6).

Ask the class

  • "How do you get the sum of the digits of 472?" (hundreds + tens + ones = 13.)

Lab 4 · Quick check

Quick Check

Answer on paper first, then click to reveal.

1What are 17 / 5 and 17 % 5?

3 and 2. Both operands are int, so / gives the quotient and % the remainder.

2After double d = 7 / 2;, what does cout << d; print?

3. The int division happens before the value is stored. Fix: 7.0 / 2.

3With int a = 3;, what are b and a after int b = a++ * 2;? After int b = ++a * 2; (starting again from 3)?

Postfix: b = 6, a = 4. Prefix: b = 8, a = 4.

4What does cout << (3 > 2 > 1); print?

0. Left to right: 3 > 2 is true (1), then 1 > 1 is false. Write 3 > 2 && 2 > 1.

5Evaluate !(5 > 3) || 4 % 2 == 0. Which operator is applied last?

!(true) is false; 4 % 2 == 0 is true; false || true = true. || is applied last (lowest precedence here).

6What do 2 ^ 3 and pow(2, 3) give? Name the family of %=, !=, and !.

2 ^ 3 = 1 (10 XOR 11 = 01); pow(2, 3) = 8. %= is assignment, != is relational, ! is logical.

Suggested time: about 6 min

Teaching tips

Seatwork: Server Uptime in Hours, Minutes, Seconds

A Raspberry Pi in the CpE laboratory logs its uptime in seconds. A number like 7384 is hard to read, so the lab technician wants it in hours, minutes, and seconds.

Instruction: Write a C++ program that reads the total seconds (an int) and displays it as hours, minutes, and seconds using only / and %. Example: 7384 s = 2 h 3 min 4 s.

Need a hint?

Hint 1

1 hour = 3600 seconds and 1 minute = 60 seconds. How many whole hours are in 7384 s? Use /.

Hint 2

What is left after removing the hours? That is total_seconds % 3600. Divide that by 60 for the minutes.

Hint 3

The leftover seconds are simply total_seconds % 60. Check: 2 × 3600 + 3 × 60 + 4 = 7384.

Wrap-up

Operators: What to Remember

Key takeaways

  • Four families: arithmetic, assignment, relational, logical.
  • int / int drops the fraction (toward zero); % needs ints and takes the sign of the left operand.
  • Cast an operand, not the result: static_cast<double>(sum) / count.
  • Prefix changes first; postfix uses the old value first.
  • Relational and logical results are bool: 1/0, or true/false with boolalpha.
  • Order: unary → * / % → + - → << → relational → equality → && → || → assignment. Parentheses win.
