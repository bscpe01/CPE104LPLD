Lab 2 · Meet C++

What is C++?

Definition

C++ is a general-purpose programming language for building fast, high-performance applications. It was created by Bjarne Stroustrup as an extension of the C language.

Cross-platformThe same source code can be compiled on Windows, macOS, Linux, and Unix.
Close to the hardwareGives programmers a high level of control over system resources and memory.
CompiledYour code is translated into machine code once, then runs fast.
StandardizedAn ISO committee updates the language: C++11, 14, 17, 20, 23.

A short history

  1. 1972Dennis Ritchie creates the C language at Bell Labs.
  2. 1979Bjarne Stroustrup begins "C with Classes" at Bell Labs: C plus features C did not have.
  3. 1983Renamed C++. ++ means "add one": one step beyond C.
  4. 1985First commercial release and the book The C++ Programming Language.
  5. 1998First international standard (C++98).
  6. 2011+"Modern C++": a new standard about every 3 years.

Suggested time: about 4 min

Teaching tips

  • From your deck notes: "cross-platform" means it can be used on different systems (Windows, Mac, Unix, Linux). Stress that the source code is portable; the compiled .exe is not (a Windows .exe does not run on Linux).
  • The "classes" in "C with Classes" are the object-oriented features students will meet in Labs 12–14.
  • We compile with C++17 settings, so everything shown in this course works on Codechum and current IDEs.

Common student pitfalls

  • Confusing C, C++, and C#. C# (Microsoft, 2000) is a different language that only looks similar.

Ask the class

  • "Why do you think it is called C++ and not D?" (The ++ operator adds 1, a programmer joke: "C, incremented".)

Lab 2 · Meet C++

Why Use C++?

C++ is one of the world's most popular programming languages, and a natural fit for computer engineers.

It runs the world

  • Operating systems and device drivers
  • Graphical user interfaces and web browsers
  • Embedded systems: appliances, cars, medical devices
  • Game engines and 3D graphics

It organizes big programs

  • C++ is object-oriented: classes give programs a clear structure.
  • Code can be reused, which lowers development cost.
  • You will build classes in Labs 12–14.

It transfers

  • C++ syntax is close to C, C#, and Java.
  • Learn it once and switching languages is easy (both ways).
  • Most "hard" languages feel easy afterwards.

CpE connection

Arduino sketches are written in C/C++. The same if, loops, and variables you learn here control sensors, motors, and LEDs on microcontrollers.

The honest part

C++ gives you power and responsibility. The compiler is strict, and small mistakes are common at first. That is normal, and today's seatwork is all about fixing them.

Lab 2 · C++ Quickstart

Anatomy of Your First C++ Program

Strict rules

  • C++ is case-sensitive: Main, Cout, Return are errors.
  • Lines starting with # are directives, not statements: no ;.
LinePartWhat it does
1#include <iostream>Preprocessor directive. Brings in the input/output stream library, which defines cout and cin.
2using namespace std;Lets us use names from the std (standard) namespace, such as cout, without typing std::.
4int main()The main function. Every program starts running here. int: it returns a whole number to the OS.
4, 7{ }Braces mark the start and end of main's body (a block).
5cout << "…";A statement: prints the text between the quotes. Every statement ends with ;
6return 0;Ends main and tells the OS the program finished successfully (0 = OK).

Suggested time: about 8 min

Teaching tips

  • Live-code it in Codechum from an empty file instead of pasting. Codechum shows Hello World! and then its own "Program Terminated" line; that line is from Codechum, not from your program.
  • From your deck notes: a namespace is a region where a group of entities (variables, classes, functions) lives. std holds the standard library, so with using namespace std; the compiler is never confused about which cout we mean.
  • Blank lines and indentation are ignored by the compiler. They exist for humans (see the conventions slide).
  • Optional: return 0; may be omitted in main only (C++ adds it automatically), but we always write it in this course.

Common student pitfalls

  • Semicolon after #include <iostream> or after int main().
  • Typing iostream.h (old pre-standard header, an error on modern compilers).
  • Curly “smart quotes” copied from Word or a PDF: “Hello” is not "Hello" to the compiler.

Ask the class

  • "Change the message to your own name and run it again. What else had to change?" (Nothing. Only the text inside the quotes.)

Lab 2 · C++ Quickstart

Omitting using namespace std;

You will see programs without line 2. They write std:: in front of each standard name instead.

Style used in this course

#include <iostream>
using namespace std;

int main() {
    cout << "Hello World!";
    return 0;
}

Also correct: the std:: prefix

#include <iostream>

int main() {
    std::cout << "Hello World!";
    return 0;
}

Key idea

A namespace is a named group of related names. std is the namespace of the C++ standard library. :: (scope resolution) means "the one that lives inside": std::cout is "the cout inside std".

Do neither, and the build fails

main.cpp:4:5: error: 'cout' was not declared in this scope;
did you mean 'std::cout'?

Suggested time: about 4 min

Teaching tips

  • Both programs print exactly the same Hello World!. Run both to prove it.
  • The error message shown is from g++ (Codechum's wording is similar). Teach students to read the line number (4:5 = line 4, column 5) and the hint after "did you mean".
  • Professional teams often prefer std:: in large projects to avoid name clashes, but for short programs using namespace std; is fine and matches our decks.

Common student pitfalls

  • Writing std:cout (one colon) or std.cout.
  • Writing using namespace std without the semicolon.

Ask the class

  • "If we remove line 2, which other words in a longer program need std::?" (cin, endl, string…)

Lab 2 · Compile & run

How Your Code Becomes a Running Program

When you press Run in Codechum or Build & Run in an IDE, five things happen in order.

Syntax errors (compile time)

Broken grammar: missing ;, misspelled cout, wrong case. The compiler stops and reports the line. Nothing runs.

Logic errors (run time)

The program builds and runs but gives the wrong answer, e.g. sum = x - y;. Only testing catches these.

Where you will code

Codechum: online compiler in the browser (one click compiles and runs). Desktop IDEs: Code::Blocks, Dev-C++, VS Code with g++. IDE = editor + compiler + debugger in one.

Suggested time: about 6 min

Teaching tips

  • Codechum hides steps 2–4 behind one button. In Code::Blocks, show the "Build log" so students see the compiler and linker actually run.
  • Connect to Lab 1's program development cycle: code → test → debug. Syntax errors are found by the compiler; logic errors are found by your test cases (rubric criterion: Functionality, Testing & Debugging).
  • Rule of thumb for students: fix the first error message first, then rebuild. One missing ; can cause a cascade of later messages.

Common student pitfalls

  • Editing the code but running the old executable (desktop IDEs: "Build" was not pressed). Codechum always rebuilds.
  • Ignoring warnings. A warning still builds, but often points to a real logic error.

Ask the class

  • "If you type sum = x * y; instead of x + y, which step catches it?" (None of them. It is a logic error; only testing reveals it.)

Lab 2 · C++ Output

Printing Text with cout and <<

The cout object, together with the insertion operator <<, sends values and text to the screen.

Surprise!

You can use as many cout statements as you want, but cout does not add a new line by itself. Both texts end up glued on one line.

Chaining with <<

One cout can print many items. Text in quotes prints exactly as typed; an expression without quotes is computed first.

cout << "5 + 3 = " << 5 + 3;

prints 5 + 3 = 8

Read it as an arrow

cout << "Hi";: the arrows point toward cout, so the data flows out to the screen.

Suggested time: about 5 min

Teaching tips

  • From your deck notes: cout belongs to the iostream library, and its purpose is to display the content between the double quotes exactly as it is.
  • Run the two-cout program and let students be surprised by the glued output. That motivates the next slide (\n and endl).
  • Demo: cout << "5 + 3"; vs cout << 5 + 3;. The first prints the text 5 + 3, the second prints 8.

Common student pitfalls

  • cout >> "Hi"; (arrows the wrong way). This is one of the bugs in today's seatwork.
  • Forgetting a space inside the quotes, so "Sum:" followed by a value prints Sum:8.
  • Missing closing quote: the error appears on the line, but often with a confusing message ("missing terminating " character").

Ask the class

  • "How would you make the output show a space between the two sentences?" (Add a space inside one of the strings.)

Lab 2 · C++ User Input

Reading Input with cin and >>

cin is a predefined object that reads data from the keyboard with the extraction operator >>.

Read it as an arrow

cin >> x;: data flows from the keyboard into the variable x.

Prompt first

Always print a prompt before cin so the user knows what to type. Without endl, the cursor waits on the same line.

Several values at once

cin >> a >> b; reads two values. The user separates them with a space or with Enter.

Wrong kind of input

Typing abc when an int is expected makes cin fail. Input validation comes in later labs.

Suggested time: about 6 min

Teaching tips

  • The comments in the code come from your deck example. Mention that int x; creates a box for a whole number (data types are Lab 3).
  • Run it live and type different numbers. Then type 4 7 and show that only 4 is read; the 7 waits for the next cin.
  • Show students where Codechum (or their IDE's console window) takes keyboard input before they need it in the seatwork.

Common student pitfalls

  • cin << x; (arrows reversed), another seatwork bug.
  • cin >> "Type a number: ";, trying to print a prompt with cin.
  • Using a variable that was never declared (cin >> y; with no int y;).

Ask the class

  • "Where does the typed 25 go, and how long does it stay there?" (Into x's memory; until the program changes it or ends.)

Lab 2 · Coding conventions

Same Program, Very Different Readability

Both programs compile and print the same output. Only one of them earns full marks for readability.

Hard to read

#include <iostream>
using namespace std;
int main(){int a,b;
cout<<"Enter 2 numbers: ";cin>>a>>b;
cout<<"Product: "<<a*b<<endl;return 0;}

Conventions we follow

  • Indent 4 spaces inside every { }.
  • One statement per line.
  • Meaningful names: product, not p.
  • Comments for purpose; blank lines between input, process, output.
  • Spaces around operators: a * b, cout << x.

Easy to read

#include <iostream>
using namespace std;

// Multiplies two whole numbers.
int main() {
    int first, second;

    cout << "Enter 2 numbers: ";
    cin >> first >> second;

    int product = first * second;
    cout << "Product: " << product << endl;
    return 0;
}

Suggested time: about 5 min

Teaching tips

  • Ask students to find the cin in the left program. It takes a while, and that is the point.
  • Tie it to the rubric: Structure, Readability & Standards is 25 of 100 points on every lab exercise.
  • Most IDEs can auto-format (Code::Blocks: Plugins → Source code formatter; VS Code: Shift + Alt + F). Still teach the habit; the Midterm Practical is typed by hand.

Common student pitfalls

  • Mixing tabs and spaces, so the indentation looks different on Codechum and on the projector.
  • Names like a1, a2, xx that mean nothing a week later.

Ask the class

  • "Which would you rather debug at 11 p.m. before a deadline?"

Lab 2 · Quick check

Quick Check

Answer in your head first, then click to reveal.

1Where does every C++ program start running?

In int main(). Execution starts at the first statement inside main's braces.

2What does #include <iostream> do, and why has it no semicolon?

It is a preprocessor directive that brings in the input/output library (cout, cin). Directives are not statements, so they take no ;.

3What is printed by cout << "A"; cout << "B";?

AB on one line. cout never adds a new line by itself; use \n or endl.

4Which is correct: cin << x; or cin >> x;?

cin >> x;. The arrows point where the data goes: from the keyboard into x.

5A missing semicolon is caught at which step: compile, link, or run?

At compile time. It is a syntax error, so no executable is produced and nothing runs.

6What does return 0; in main mean?

The program ends and reports success (0) to the operating system.

Suggested time: about 5 min

Teaching tips

  • Cold-call or use a quick show of hands per question before revealing.
  • Question 5 checks that students understood the build pipeline, not just the syntax.

Common student pitfalls

  • Answering Q3 with two lines. Run it live if anyone doubts.

Ask the class

  • Bonus: "What changes if we write Return 0;?" (Compile error: C++ is case-sensitive.)

  • Fixing the quotes on line 12 but forgetting the space before the closing quote, so the output reads You've entered7.
  • Testing only one number. Test odd, even, 0, and a negative odd like -3 (prints ODD because -3 % 2 is -1, not 0). A version that checks num % 2 == 1 would wrongly call -3 even.

Ask the class

  • "Which bugs did the compiler find for you, and which would only show up when you run and test?" (All of these are compile errors except the stray }; and missing spaces in the messages.)

Wrap-up

The Skeleton You Will Type in Every Lab

#include <iostream>   // cout, cin
using namespace std;  // standard names

int main() {          // starts here
    // input:   prompt, then cin >>
    // process: compute with =
    // output:  cout << … << endl;
    return 0;         // finished OK
}

Remember

  • cout << out to the screen; cin >> in from the keyboard.
  • cout adds no new line: use \n or endl.
  • Every statement ends with ;. C++ is case-sensitive.
  • Syntax errors stop the build; logic errors need testing.
