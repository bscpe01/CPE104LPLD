Lab 6 · Review

From Lab 1 IF … THEN to C++ if ( )

Every selection statement is driven by a condition: a bool expression that is either true or false.

Key concept

  • Relational operators < <= > >= == != give a bool: true (1) or false (0).
  • Logical operators combine them: && (both), || (at least one), ! (reverse).
  • Precedence (Lab 4): ! → arithmetic → < > → == != → && → ||.

Suggested time: about 5 min

Teaching tips

  • Point at each row and have students say the C++ form aloud. The two big changes: = becomes ==, and the condition always goes inside parentheses.
  • cout prints a bool as 1 or 0. The boolalpha manipulator switches it to true/false and stays on for later output.
  • In C++ any nonzero number counts as true when used as a condition. This explains several bugs later today (for example if (x = 5)).

Common student pitfalls

  • Writing if grade >= 75 without parentheses: a syntax error in C++.
  • Writing => or =<. The only valid spellings are >= and <=.

Ask the class

  • "With grade = 82, what is grade >= 75 && grade <= 100?" (true.) "And !(grade >= 75)?" (false.)

Lab 6 · Single alternative

The if Statement

Run a block only when the condition is true. Otherwise skip it and continue after the }.

if (condition) { statements; }

Suggested time: about 6 min

Teaching tips

  • Live-code it in Codechum or your IDE. Run it twice (92, then 60) so students see the warning line appear and disappear while "Reading recorded." always prints.
  • Trace the flowchart with your finger: the No path goes around the warning and rejoins. That is a single-alternative if: there is no else branch.
  • Emphasize the braces even for one statement. It is the course style and it prevents the bugs on the "Braces" slide.

Common student pitfalls

  • A semicolon right after the condition: if (temperature > 85); ends the if, so the block always runs.
  • Putting "Reading recorded." inside the braces, so it only prints when the CPU is hot.

Ask the class

  • "What prints for exactly 85?" (Only "Reading recorded." because 85 > 85 is false.) "How do we include 85?" (>=.)

Lab 6 · Dual alternative · Lab 1 Problem 3 in C++

The if-else Statement

Two paths, and exactly one of them runs: the if block when true, the else block when false.

if (condition) { statements; } else { statements; }

Suggested time: about 5 min

Teaching tips

  • Put the Lab 1 pseudocode next to it: IF programmer_age >= 18 THEN … ELSE … ENDIF. ENDIF becomes the closing brace of the else block.
  • Always test the boundary (18) as well as one value on each side (17 and 19). That habit earns the rubric's "normal, boundary, and edge test cases".
  • else has no condition. It catches everything the if did not.

Common student pitfalls

  • Writing else (programmer_age < 18): a compile error. else never takes a condition.
  • Two separate ifs (if (age >= 18) … if (age < 18) …). It works, but the second test is wasted work, and in longer chains it can print two messages.

Ask the class

  • "Can both messages ever print? Can neither print?" (No and no. That is the point of if-else.)

Lab 6 · Multi-way selection · Lab 1 Problem 4 in C++

The else if Ladder

Conditions are tested top to bottom. The first true one runs, and the rest are skipped. With ranges, test the highest threshold first.

Suggested time: about 10 min

Teaching tips

  • This is Lab 1 Problem 4, now in C++. Each ELSE IF … THEN line became } else if (…) {.
  • Trace 85 with the tracer, then 95, 59, and the boundaries 90 and 89.9. Watch how many diamonds light up: for 95 only one, for 59 all four.
  • Ask why the second test is just grade >= 80 and not grade >= 80 && grade < 90: we only get there when grade >= 90 was false.
  • grade is a double so 89.5 works. With int grade, typing 89.5 would store 89.

Common student pitfalls

  • Wrong order (grade >= 60 first): every passing grade becomes D. The compiler gives no warning, so only testing catches it.
  • Separate ifs instead of else if: 95 prints A, B, C, and D.
  • Forgetting the final else, so a grade like 45 prints nothing.

Ask the class

  • "What does 150 print?" (A.) "How would you reject grades outside 0 to 100?" (Add a validation if first. See the Input Validation slide and Lab Exercise Problem 3.)

Lab 6 · Nested selection

Nested if: A Decision Inside a Decision

Nest an if when the second question only matters after the first answer is yes. Each inner if lives completely inside one branch of the outer if.

Suggested time: about 6 min

Teaching tips

  • Story: an amusement-park ride. Height is checked first. Age only matters for riders who are tall enough.
  • Show how indentation mirrors the flowchart: the inner if/else is indented one level deeper, inside the outer if's braces.
  • Test all three paths: (130, 10), (150, 15), (110, 20). Then the boundaries (120, 12).
  • The same logic without nesting: if (h >= 120 && age >= 12) … else if (h >= 120) … else …. Both are correct; the next slide compares the two styles.

Common student pitfalls

  • Putting the "Too short" else in the wrong place, so it pairs with the inner if. Braces make the pairing explicit.
  • Nesting 4–5 levels deep. If it gets that deep, try an else-if ladder or compound conditions instead.

Ask the class

  • "For a 110 cm, 8-year-old, is the age ever checked?" (No. The outer condition is false, so the inner if never runs.)

Lab 6 · Same logic, two ways

Nested if vs Compound Condition: Leap Year

A year is a leap year if it is divisible by 4 but not by 100, or if it is divisible by 400. (2024 and 2000: leap. 1900 and 2026: not.)

#include <iostream>
using namespace std;

int main() {
    int year;
    cout << "Enter a year: ";
    cin >> year;

    if (year % 4 == 0) {
        if (year % 100 == 0) {
            if (year % 400 == 0) {
                cout << "Leap year" << endl;
            } else {
                cout << "Not a leap year" << endl;
            }
        } else {
            cout << "Leap year" << endl;
        }
    } else {
        cout << "Not a leap year" << endl;
    }
    return 0;
}

#include <iostream>
using namespace std;

int main() {
    int year;
    cout << "Enter a year: ";
    cin >> year;

    if ((year % 4 == 0 && year % 100 != 0) ||
        year % 400 == 0) {
        cout << "Leap year" << endl;
    } else {
        cout << "Not a leap year" << endl;
    }
    return 0;
}

&& is evaluated before ||, and both stop early (short-circuit) once the answer is known. The extra parentheses are for the reader.

Suggested time: about 10 min

Teaching tips

  • Run the tracer with 1900 (three diamonds, "Not a leap year"), then 2000, 2024, and 2026. Students should predict before you press Play.
  • Switch to the Compound tab. The single condition reads almost like the English rule, but it is harder to trace by hand. The nested version maps one diamond to one if.
  • Rule of thumb: nesting is clearer when each level asks a different question in order. A compound condition is clearer when it is short and mirrors a sentence.
  • Short-circuit: for 2026, year % 4 == 0 is false, so && skips year % 100 != 0 entirely.

Common student pitfalls

  • Dropping the inner parentheses changes nothing here (&& already binds tighter than ||), but students often guess the opposite. g++ -Wall even warns "suggest parentheses around '&&' within '||'", so keep them.
  • Writing year / 4 == 0 instead of year % 4 == 0.
  • Testing only 2024. A leap-year checker that says "divisible by 4" also passes 2024 but fails 1900.

Ask the class

  • "Is 2100 a leap year?" (No: divisible by 100 but not by 400.)

Lab 6 · Multi-way selection on one value

The switch Statement

When one int or char value is compared for exact matches, a switch is shorter and clearer than a long else-if ladder.

switch (expression) { case value: statements; break; … default: statements; }

How switch works

  • The expression is evaluated once, then control jumps to the case whose value matches.
  • Statements run until a break (or the closing brace). break exits the switch.
  • default runs when no case matches. It is optional, but always include it.
  • Case values must be constants and must be different from each other.

Suggested time: about 6 min

Teaching tips

  • Write the same program as an else-if ladder on the board (if (year_level == 1) … else if (year_level == 2) …) and compare. Same logic, but switch shows the "menu" shape at a glance.
  • Pseudocode link: Farrell calls this the case structure. In a flowchart it is drawn as a chain of Decision symbols, each with two exits (next slide).
  • The default label is the switch version of the final else. Use it for input validation ("Invalid year level").

Common student pitfalls

  • Forgetting break: execution falls through into the next case. (Grouping slide.)
  • Writing case = 1: or case 1;. The syntax is case 1: with a colon.
  • Using a variable as a case label (case limit:). Labels must be constants.

Ask the class

  • "What prints for 0? For -1?" (Invalid year level, through default.)

Lab 6 · switch on a char

Trace It: A switch Calculator

The operator character picks the arithmetic. Inside case '/', a nested if guards against division by zero.

Suggested time: about 10 min

Teaching tips

  • Trace 7.5 * 4 (= 30), then 12 / 0 (the nested if), then 9 % 2 (default). Type the operator in the small op box.
  • cin >> a >> op >> b reads "7.5 * 4" in one line. A char reads exactly one non-space character.
  • The flowchart shows the case structure as a chain of two-exit Decisions (course rule). The compiled switch jumps straight to the matching case, so it does not really test each case one by one.
  • One-line cases (case '+': … break;) are fine when each case is a single short statement. Longer cases use the multi-line form, like case '/'.

Common student pitfalls

  • case "+": with double quotes: a string literal, which is a compile error. Characters use single quotes.
  • Forgetting break after the '/' block, so the default message prints too.
  • Without the b != 0 check, 12 / 0.0 with doubles prints inf. With int operands, dividing by zero is undefined behavior and usually crashes.

Ask the class

  • "How would you add %?" (Only for integers: % needs int operands. With doubles you would need fmod from <cmath>.)

Lab 6 · switch details

Grouping Cases, Fall-through & Limits

A case with no break falls into the next one. Used on purpose, that lets several values share one block.

Enter score (0-100): 87
B

Grouping chars

Accept both cases of a letter by stacking labels: case 'y': case 'Y': then one shared block ending in break;

Accidental fall-through

int choice = 1;
switch (choice) {
    case 1: cout << "Coffee ";    // no break!
    case 2: cout << "Tea ";       // no break!
    case 3: cout << "Juice "; break;
    default: cout << "Water";
}

Output: Coffee Tea Juice. Every case after the match runs until a break.

What switch can and cannot do
AllowedNot allowed
int, char, bool, long (integral types)double, float, string
Constant labels: case 7: case 'A':Variables: case limit:
Exact matchesRanges: case 90-100: means case -10:

Suggested time: about 7 min

Teaching tips

  • score / 10 is integer division (Lab 4): 87 / 10 = 8, 100 / 10 = 10. That turns ranges into exact values that switch can match.
  • case 10: has no statements and no break, so 100 falls into case 9 and also prints A. Empty labels stacked like this are the normal way to group values, and g++ does not warn about them.
  • The table's last row is a real trap: case 90-100: compiles, because 90-100 is the constant -10. GCC has a case 90 ... 100: extension, but it is not standard C++, so avoid it.
  • Use switch for exact matches on one int/char value (menus, codes, operators). Use an else-if ladder for ranges, doubles, strings, or conditions on several variables.

Common student pitfalls

  • Missing break in a non-empty case. With -Wextra, g++ warns "this statement may fall through".
  • Forgetting validation: 105 / 10 = 10 prints A, and -5 / 10 = 0 prints F. Check the range with an if first.
  • Trying switch (name) with a string: compile error.

Ask the class

  • "In the Coffee example, what prints when choice is 3? When it is 9?" (Juice. Water.)

Lab 6 · Selecting a value

The Conditional (Ternary) Operator ?:

A compact if-else that produces a value. Use it to choose between two values, not to run two blocks of code.

condition ? value_if_true : value_if_false

Common pitfall

  • ?: has very low precedence. Inside cout, wrap it in parentheses: cout << (a > b ? a : b);. Without them, the line does not compile.
  • Nested ternaries (x ? y : z ? u : v) are hard to read. Use an else-if ladder instead.
Enter two integers: 7 12
Larger: 12
7 is odd

Suggested time: about 5 min

Teaching tips

  • Read (a > b) ? a : b aloud as "if a is greater than b then a, otherwise b".
  • It is called ternary because it takes three operands. It is the only operator in C++ that does.
  • Both result values should have compatible types (two ints, or two strings like "even" and "odd").

Common student pitfalls

  • cout << a > b ? a : b; is parsed as (cout << a) > b ? …, which does not compile.
  • Using ?: to call statements that print, e.g. x > 0 ? cout << "pos" : cout << "neg";. It technically works but is unreadable. Use if-else.

Ask the class

  • "Write one line that stores the absolute value of x in y." (int y = (x < 0) ? -x : x;)

Lab 6 · Style that prevents bugs

Braces, Indentation & the Dangling else

The compiler ignores indentation: without braces, an else pairs with the nearest unmatched if.

Style rules for Lab 6 and beyond

Braces on every if, else, and loop body · indent 4 spaces per level · write } else { on one line · compile with -Wall -Wextra: g++ flags this bug as "suggest explicit braces to avoid ambiguous 'else'".

Suggested time: about 6 min

Teaching tips

  • Ask the class to predict the output of the buggy version for 50 before revealing "Ice". Most will say nothing prints. The else belongs to if (temperature > 100).
  • For -5, the buggy version prints nothing: the outer if is false and the else is inside it.
  • In the fixed version 50 prints nothing on purpose (it is neither steam nor ice), which matches the original intent.
  • IDE help: Code::Blocks has Plugins → Source code formatter (AStyle). VS Code has Format Document. Auto-format re-indents code to show its real structure.

Common student pitfalls

  • Two statements under an if without braces: only the first is controlled (see the pitfalls slide).
  • Mixing tabs and spaces, which looks fine in one editor and messy in Codechum.

Ask the class

  • "Which if does the else belong to?" Have them draw the braces in by hand.

Lab 6 · Defensive selection

Input Validation with if

Check for bad input before you compute with it. Here a zero resistance would mean dividing by zero.

Validation pattern

  1. Test each invalid case first and print a clear message.
  2. Put the real computation in the final else, so it only runs on good data.

Suggested time: about 5 min

Teaching tips

  • Connect to Lab 1's Ohm's law worked example, which also guarded against resistance = 0 before dividing.
  • Run it three times: valid (12, 400), zero resistance, and a negative voltage (-3, 10) to show each branch.
  • The output 0.03 uses default cout formatting (6 significant digits). Add fixed << setprecision(4) from Lab 5 if a fixed number of decimals is required.
  • Ask what else could go wrong: typing letters. cin then fails and the variable becomes 0. Re-asking until the input is valid needs a loop (Lab 7, do-while).

Common student pitfalls

  • Validating after the division, when the damage is already done.
  • Checking only resistance == 0. A negative resistance is invalid input too, so test <= 0.

Ask the class

  • "Which branch runs for voltage = -3 and resistance = 0?" (The first one. Only the first true condition runs.)

Lab 6 · Floating-point conditions

Comparing Doubles: Avoid ==, Use a Tolerance

Many decimals have no exact binary form, so two "equal" computed doubles may differ in the last digit.

Why?

0.1 + 0.2 is stored as 0.30000000000000004. The test fabs(a - b) < EPSILON asks "are they close enough?" (fabs is in <cmath>).

Engineering use: tolerance bands

A 1 kΩ ±5% resistor passes inspection if fabs(measured - 1000) <= 50.

Suggested time: about 5 min

Teaching tips

  • Show cout << setprecision(17) << 0.1 + 0.2; live (needs <iomanip>). Seeing 0.30000000000000004 convinces students.
  • The tolerance depends on the problem: 1e-9 for pure math, the sensor's accuracy for measurements, the resistor's ±5% for inspection.
  • Comparing a double to a value the user typed, like resistance <= 0, or using < and >= for ranges is fine. The danger is == or != on results of arithmetic.

Common student pitfalls

  • Using abs on doubles without <cmath>: some compilers pick the int version and truncate 0.4 to 0. Use fabs.
  • Forgetting the absolute value: (a - b) < EPSILON is also true when a is much smaller than b.

Ask the class

  • "A resistor measures 1047 Ω. Does it pass ±5%? What about 948 Ω?" (Yes: off by 47. No: off by 52.)

Lab 6 · Debugging

Spot the Bug: Six Selection Pitfalls

All six compile (some with warnings), and all six give wrong results. Compile with -Wall -Wextra to catch most of them.

1 · = instead of ==

if (x = 5) {
    cout << "five";
}

Assigns 5 to x. 5 is nonzero, so it is always true. Fix: x == 5.

2 · Semicolon after if

if (grade < 75); {
    cout << "Failed";
}

The ; is an empty if body. The block always runs. Fix: delete the ;.

3 · Missing braces

if (balance < 0)
    cout << "Overdrawn!";
    balance = 0;

Only the first statement belongs to the if. balance = 0; always runs. Fix: add braces.

4 · Missing break

case 1: cout << "Add";
case 2: cout << "Edit";
        break;

Choice 1 prints AddEdit: it falls through into case 2. Fix: break; after each case.

5 · Ranges in the wrong order

if (grade >= 60) {
    cout << "D";
} else if (grade >= 90) {
    cout << "A";
}

95 prints D, and "A" can never print. No warning. Fix: highest threshold first.

6 · Math-style range

if (0 < x < 10) {
    cout << "in range";
}

0 < x gives 0 or 1, which is always < 10: always true (even for 50). Fix: 0 < x && x < 10.

Suggested time: about 8 min

Teaching tips

  • Run it as a game: show one card at a time and give pairs 30 seconds to explain the bug before you read the answer.
  • Warnings g++ gives with -Wall -Wextra: #1 "suggest parentheses around assignment used as truth value", #2 "suggest braces around empty body", #3 "this 'if' clause does not guard…" (misleading indentation), #4 "this statement may fall through", #6 "comparisons like 'X<=Y<=Z' do not have their mathematical meaning". #5 gives no warning at all.
  • Codechum and some IDEs hide warnings by default. In Code::Blocks: Settings → Compiler → enable -Wall and -Wextra.

Common student pitfalls

  • Ignoring warnings because "it compiled". A warning is often a logic bug.
  • Fixing #6 as 0 < x || x < 10: always true again. A range needs &&.

Ask the class

  • "Which of the six can the compiler NOT detect?" (#5, wrong order. Only testing with 95 finds it.)

Lab 6 · Check your understanding

Quick Check

Answer on your own first, then click to reveal.

1With int x = 0;, what does if (x = 0) { cout << "zero"; } print?

Nothing. x = 0 assigns 0, and 0 is false. The intended test is x == 0, which would print "zero".

2An else-if ladder tests >= 90, >= 80, >= 70, >= 60, else F. How many conditions are evaluated for a grade of 72?

Three: 72 >= 90 (false), 72 >= 80 (false), 72 >= 70 (true → C). The last test and the else are skipped.

3Rewrite if (a > 0) { if (b > 0) { cout << "both"; } } as a single if.

if (a > 0 && b > 0) { cout << "both"; }. Nesting with no else is the same as &&.

4Why can't you write switch (price) when price is a double?

A switch expression must be an integral type (int, char, bool, …). Use an if-else ladder for doubles, strings, and ranges.

5int n = 2; then switch (n) { case 1: cout << "A"; case 2: cout << "B"; case 3: cout << "C"; break; default: cout << "D"; }. Output?

BC. It jumps to case 2, prints B, falls through to case 3, prints C, then break exits before default.

6What is stored in m? int a = 3, b = 7; int m = (a > b) ? a : b;

7. The condition 3 > 7 is false, so the value after the colon (b) is chosen.

Suggested time: about 6 min

Teaching tips

  • Use show of fingers (1–6) or a quick MS Teams poll for Q2 and Q5 before revealing.
  • Q1 and Q5 are the two most common Lab 6 bugs. If many miss them, revisit the pitfalls slide.

Common student pitfalls

  • Q2: counting the else as a "condition". The else has no test.
  • Q5: answering "B" (forgetting fall-through) or "BCD" (forgetting that break also skips default).

Ask the class

  • Follow-up to Q3: "What if the inner if had an else? Can you still merge them?" (Not directly. You would need an else-if ladder.)

Lab 6 · Seatwork

Seatwork: Triangle Classifier

A CAD tool must classify triangles from their side lengths (whole numbers, in cm).

Instruction: Read three sides. If they cannot form a triangle (a side ≤ 0, or any two sides add up to no more than the third), print Not a valid triangle. Otherwise print Equilateral triangle (3 equal sides), Isosceles triangle (exactly 2 equal), or Scalene triangle (none equal).

Need a hint?

Hint 1

Validate first: a + b > c && a + c > b && b + c > a, plus every side > 0.

Hint 2

Put the classification in a nested if-else ladder inside the valid branch.

Hint 3

Test equilateral before isosceles. Why does the order matter?

Why int sides?

With double sides, a == b can fail for values that should be equal after a computation. You would compare with a tolerance instead.

Suggested time: about 20 min (15 working, 5 review)

Running the seatwork

  • Start the timer and walk around. Ask students to write their test table (at least the five cases in the answer) before coding.
  • Open hints one at a time only if many students are stuck. Hint 3's answer: if isosceles (a == b || …) is tested first, 7 7 7 would print "Isosceles".
  • Before revealing, show one student solution that uses nesting and one that uses a flat ladder with the validation as the first if. Both are correct.

Common student pitfalls

  • Using >= in the triangle inequality, which accepts 1 2 3 (a flat "triangle").
  • Writing a == b == c. It compares (a == b), which is 0 or 1, with c.
  • Only checking a + b > c and forgetting the other two pairs.

Ask the class

  • "Can a triangle be both isosceles and right? Give sides." (Not with whole numbers, since the hypotenuse would be a·√2. That is a nice side discussion.)
