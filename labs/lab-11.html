Lab 11 · Modular programming · ILO 1

Why Write Functions?

Divide and conquer: split a big problem into small tasks, solve each one once, then combine them.

Modular

Each function does one job. main() reads like an outline.

Reusable

Write power() once, call it from anywhere, any number of times.

Testable

Test one small function at a time; find bugs faster.

Team-friendly

Different people can write different functions at the same time.

Note

Duplicated code is a warning sign. If you copy and paste a block, it probably wants to be a function.

Key concept

sqrt and pow were written by someone else; you only needed their name, inputs, and result. Today you write your own.

Suggested time: about 4 min

Teaching tips

  • Point out that students already used the "black box" idea: nobody looked inside sqrt. A good user-defined function should be just as easy to use.
  • Engineering analogy: an IC chip on a breadboard. You need its pinout (inputs and outputs), not its internal transistors.
  • The final project rubric (Algorithmic Design & System Architecture) explicitly rewards "well-structured C++ functions".

Common student pitfalls

  • Forgetting #include <cmath> for sqrt and pow.
  • Making one giant function that does everything (input, compute, output). One task per function.

Ask the class

  • "In pow(a, 2), what are the inputs and what comes back?" (Inputs a and 2; it returns a².)

Lab 11 · Function basics · ILO 1

Anatomy of a Function

The header says what goes in and what comes out; the body says how.

returnType functionName(type param1, type param2) { statements; return value; }

Calling it

double rt = seriesResistance(100, 220); → rt is 320. The values 100 and 220 are copied into r1 and r2.

Naming

  • Use a verb + noun in camelCase: computeAverage, printReport, readGrades.
  • The return type and the returned value must match (double ↔ total).

Suggested time: about 5 min

Teaching tips

  • Read the header aloud as a sentence: "seriesResistance takes two doubles, r1 and r2, and gives back a double."
  • Series resistance (RT = R1 + R2) comes from their circuits course, so the math is not a distraction.
  • The body could be one line (return r1 + r2;). Show both: the local variable version is easier to trace.

Common student pitfalls

  • Putting a semicolon after the header of a definition: double f(double x); { … }. That turns it into a prototype followed by a stray block (compile error).
  • Writing types in the call: seriesResistance(double 100, double 220).

Ask the class

  • "Write the header of a function that takes a voltage and a resistance and returns the current." (double current(double volts, double ohms).)

Suggested time: about 6 min

Teaching tips

  • Demo: delete the prototype and compile. g++ reports "'current' was not declared in this scope". Put it back and it compiles. Errors are the best teacher here.
  • Parameter names are optional in a prototype (double current(double, double);), but keeping them documents the meaning.
  • The prototype and the definition header must match in return type, name, and parameter types.
  • This version has no R = 0 check, to keep the focus on structure. Ask what Lab 1's refine step added (the division-by-zero guard); the lab exercise requires it.

  • Forgetting the semicolon at the end of the prototype.
  • Changing the definition (e.g. to int ohms) but not the prototype: the linker then reports "undefined reference to current(double, double)".

Ask the class

  • "Which line runs first: line 11 or line 18?" (Line 11, the call. The definition only runs when called.)

Lab 11 · Flow of control · ILO 1

Trace It: Jumping Into a Function and Back

A call pauses main(), copies the arguments into the parameters, runs the function, then returns.

#include <iostream>
using namespace std;

double power(double volts, double amps);

int main() {
    double voltage, current;
    cout << "Enter volts and amps: ";
    cin >> voltage >> current;

    double p1 = power(voltage, current);
    cout << "Power = " << p1 << " W" << endl;

    double p2 = power(voltage, current * 2);
    cout << "2x current: " << p2 << " W" << endl;
    return 0;
}

double power(double volts, double amps) {
    double watts = volts * amps;
    return watts;
}

Suggested time: about 8 min

Teaching tips

  • Press Step slowly. Watch the highlighted line jump from 11 down to 19, then back up to 11. Students often believe code always runs top to bottom; this breaks that belief.
  • The Memory panel labels the function's variables [power] …. They appear on the call and disappear on return: parameters and locals live only while the function runs.
  • The second call shows reuse: the same code runs with different arguments (current * 2 is evaluated first, then copied).
  • Try other inputs, e.g. 12 V and 1.5 A (18 W and 36 W).

Common student pitfalls

  • Expecting the names to match. voltage in main and volts in power are different variables; only the values are copied, by position.
  • Thinking watts can be used in main. It is local to power.

Ask the class

  • "How many times does line 20 run?" (Twice, once per call.)

Lab 11 · Function basics · ILO 1

void vs Value-Returning · Parameters vs Arguments

A void function does a job; a value-returning function computes an answer you can use.

#include <iostream>
using namespace std;

void printLine(int width) {      // returns nothing
    for (int i = 0; i < width; i++) {
        cout << "-";
    }
    cout << endl;
}

int cube(int n) {                // returns an int
    return n * n * n;
}

int main() {
    printLine(20);               // a statement
    cout << "3 cubed = " << cube(3) << endl;
    int side = 4;
    int volume = cube(side);     // side → n
    cout << "Volume = " << volume << endl;
    printLine(20);
    return 0;
}
ParameterArgument
Wherein the function headerin the call
Exampleint nside, 3
What it isa local variable that receives a valuethe value (or variable) you send

Common pitfall

int x = printLine(5); does not compile: a void function has no value to store.

Suggested time: about 6 min

Teaching tips

  • Memory hook: parameter = placeholder (in the header); argument = actual value (in the call).
  • A value-returning call can go anywhere a value can: inside cout, on the right of =, inside another call (cube(cube(2)) is 512).
  • A void function may still use return; (with no value) to leave early.

Common student pitfalls

  • Calling a value-returning function as a statement and ignoring the result: cube(3); compiles but does nothing useful.
  • Printing inside a function that should return the value. "Return, don't print" makes functions reusable.
  • Passing the wrong number of arguments: "too few arguments to function".

Ask the class

  • "Should a function that checks if a resistor value is valid be void or return something?" (Return bool.)

Lab 11 · Parameter passing · ILO 2

Pass-by-Value vs Pass-by-Reference

One character makes the difference: int x receives a copy; int& x becomes another name for the caller's variable (Lab 10).

By value: void swapByValue(int x, int y)

Memory just before the function returns:

a5main
b9main
x9copy
y5copy
temp5local

Only the copies were swapped. a and b are unchanged.

By reference: void swapByReference(int& x, int& y)

Memory just before the function returns:

a · x9main
b · y5main
temp5local

x and y are other names for a and b, so a and b are swapped.

ModeParameterFunction getsCan change caller?Use for
By valueint xa copyNosmall inputs (int, double, char)
By referenceint& xan aliasYesoutputs, swaps, several results
By const referenceconst string& sa read-only aliasNobig inputs (string) without copying

Suggested time: about 7 min

Teaching tips

  • This is ILO 2. Draw both pictures on the board before showing the code on the next slide.
  • Analogy: pass-by-value is giving someone a photocopy of your notes (they can scribble on it; your notes are safe). Pass-by-reference is lending them your actual notebook.
  • The only change in the code is & after the type in the parameter list. The call looks exactly the same: swapByReference(a, b).

Common student pitfalls

  • Putting & in the call (swapByReference(&a, &b)). That passes addresses (pointers) and does not compile with int& parameters.
  • Passing a literal to a non-const reference: swapByReference(5, 9) does not compile (a reference needs a variable). A const reference accepts literals.

Ask the class

  • "Which mode would you use for a function that reads two numbers from the keyboard into the caller's variables?" (By reference.)

Lab 11 · Parameter passing · ILO 2

Trace It: The Classic Swap, Both Ways

Same body, same call. Only the parameter types differ.

#include <iostream>
using namespace std;

void swapByValue(int x, int y) {
    int temp = x;
    x = y;
    y = temp;
}

void swapByReference(int& x, int& y) {
    int temp = x;
    x = y;
    y = temp;
}

int main() {
    int a = 5, b = 9;
    swapByValue(a, b);
    cout << "By val: a=" << a << " b=" << b << endl;
    swapByReference(a, b);
    cout << "By ref: a=" << a << " b=" << b << endl;
    return 0;
}

Suggested time: about 7 min

Teaching tips

  • Before stepping, ask for a prediction of both output lines. Many students predict "a=9 b=5" for both.
  • During swapByValue, the Memory panel shows x (copy of a) and y (copy of b) changing while a and b stay put. During swapByReference, x (alias of a) always shows the same value as a.
  • Notice the names swapByValue/swapByReference. C++ already has a std::swap; distinct names avoid confusion.

Common student pitfalls

  • Believing the function "forgot" to swap. It swapped its own copies, which are destroyed on return.
  • Adding & to only one parameter: then only one of the two values changes.

Ask the class

  • "If we called swapByReference twice in a row, what would a and b be?" (Back to 5 and 9.)

Lab 11 · Parameter passing · ILO 2

Reference Parameters in Practice

return gives back one value; reference parameters can fill in several. const& reads without copying.

Enter 3 temperatures: 31 27 34
Lowest: 27
Highest: 34
Bulacan Station, Sensor A: 31.5
Humidity (%): 78

Suggested time: about 7 min

Teaching tips

  • minMax is void because it "returns" through its reference parameters: a, b, c are inputs (by value), low, high are outputs (by reference). Students need this pattern in Problem 2 of the lab exercise.
  • The argument names (lowest, highest) differ from the parameter names (low, high). They are bound by position.
  • const string&: a string can be long, so copying it costs time and memory. A const reference gives the function access without a copy and promises not to change it: adding label = "x"; inside report would not compile. For small types like int and double, plain pass-by-value is fine.
  • A const reference can also bind to a literal ("Humidity (%)"); a plain string& cannot.

Common student pitfalls

  • Forgetting the & on an output parameter: the program compiles, but main's variables stay uninitialized (garbage).
  • Marking an output parameter const: then the function cannot assign to it (compile error).

Ask the class

  • "How would you also return the average of the three?" (Add a double& average parameter, or return it as the function's value.)

Lab 11 · Parameter passing · ILO 2

Passing Arrays to Functions

#include <iostream>
using namespace std;

double average(const int a[], int n) {   // read-only
    double sum = 0;
    for (int i = 0; i < n; i++) {
        sum += a[i];
    }
    return sum / n;
}

void calibrate(int a[], int n, int offset) {
    for (int i = 0; i < n; i++) {
        a[i] += offset;   // caller's array!
    }
}

int main() {
    int readings[5] = {12, 7, 30, 18, 25};
    cout << "Average: " << average(readings, 5) << endl;
    calibrate(readings, 5, -2);
    cout << "After:   " << average(readings, 5) << endl;
    return 0;
}

Key concept

  • Pass the array and its size: int a[] (empty brackets) plus int n.
  • Call with the array name only: average(readings, 5).
  • The function receives the address of element 0 (Lab 10), so arrays are effectively passed by reference: calibrate changed readings.
  • Add const when the function should only read.

Common pitfall

Inside the function, sizeof(a) is the size of a pointer (8), not of the array. That is why the size travels as a separate parameter.

Suggested time: about 6 min

Teaching tips

  • Connect to Lab 10: readings converts to &readings[0], so the function gets a pointer to the caller's elements. int a[] in a parameter list really means int* a.
  • Why const? If average accidentally wrote a[i] = 0, the compiler would stop it. Use const for every array a function only reads.
  • 12 + 7 + 30 + 18 + 25 = 92, and 92 / 5 = 18.4. After subtracting 2 from each, 82 / 5 = 16.4.

Common student pitfalls

  • Calling with brackets: average(readings[], 5) or average(readings[5], 5). The second passes one (out-of-bounds) element.
  • Hard-coding 5 inside the function instead of using n.
  • Integer division: if sum were an int, sum / n would truncate to 18.

Ask the class

  • "Write the header of a function that returns the largest element of an array of doubles." (double largest(const double a[], int n).)

Teaching tips

  • Defaults fill from the right: you cannot skip the first argument and give the second (printLine(, '*') is not C++). Put the parameter most likely to change first.
  • With a prototype, write the default values in the prototype only, not again in the definition.
  • The compiler picks the overload whose parameter list matches the call: by number of parameters (shown) or by types, e.g. int maxOf(int, int) and double maxOf(double, double).

Common student pitfalls

  • Repeating the default value in both the prototype and the definition: "default argument given for parameter 1 … after previous specification".
  • Two overloads that differ only in return type: "ambiguating new declaration".
  • Ambiguous calls, e.g. maxOf(3, 4.5) with the two versions above: the compiler cannot choose.

Ask the class

Lab 11 · Scope & lifetime

Scope and Lifetime: Where Variables Live

Scope = where a name can be used. Lifetime = how long the variable exists.

#include <iostream>
using namespace std;

int callCount() {
    static int count = 0;   // created once
    count++;
    return count;
}

int plainCount() {
    int count = 0;          // new on every call
    count++;
    return count;
}

int main() {
    for (int i = 0; i < 3; i++) {
        cout << "static " << callCount();
        cout << ", plain " << plainCount() << endl;
    }
    return 0;
}

Avoid global variables

Any function can change a global, so bugs are hard to trace. Pass values as parameters instead. Global constants (const int SIZE = 4;) are fine.

Suggested time: about 6 min

Teaching tips

  • The output shows the difference in one glance: the static counter keeps counting, the plain one restarts at 1.
  • Both functions have a local named count; they are different variables. The loop's i exists only inside the for.
  • Use case for static locals: counting how many times a function ran, or generating ID numbers. Use sparingly.
  • The final project rubric's top level asks for "zero global variables". Global constants are allowed.

Common student pitfalls

  • Using a variable from main inside another function ("'x' was not declared in this scope"). Pass it as a parameter.
  • Declaring a variable inside an if block and using it after the block.
  • "Fixing" scope errors by making everything global.

Ask the class

  • "What would callCount() return on its 10th call?" (10.)

Top-Down Design: From Problem to Structure Chart

Problem: read a student's name and 4 grades, then print the average and a letter grade.

ModuleGetsGives back

How to decompose (stepwise refinement)

  1. Write main() as a list of big steps.
  2. Turn each step into a function with a verb name.
  3. Decide inputs and outputs → parameters and return type.
  4. Write and test one function at a time.

Suggested time: about 6 min

Teaching tips

  • This is the "modular design exercise" activity. Build the chart with the class: ask "What are the big steps?" and draw the boxes on the board before revealing this slide.
  • A structure chart shows who calls whom, not the order of every statement; the small numbers show the order main calls them. The modules are drawn as Predefined Process boxes to connect with Lab 1.
  • The table is the design contract: once the headers are agreed, different students could write different functions (team-friendly).
  • Step 4 tip: a function can first be a "stub" (e.g. return 'A';) so the program compiles while the rest is unfinished.

Common student pitfalls

  • Boxes that are too big ("doEverything") or too tiny ("addOne"). Each box should be one clear task you can name with a verb.
  • Reading input inside computeAverage: mixing tasks makes a function harder to reuse and test.

Ask the class

  • "We now also want the highest grade. Where does the new box go, and what is its header?" (Under main: double highestGrade(const double grades[], int n).)

Lab 11 · Optional preview

(Optional) Recursion: A Function That Calls Itself

Solve a smaller version of the same problem, until a base case can be answered directly.

#include <iostream>
using namespace std;

long long factorial(int n) {
    if (n <= 1) {                 // base case
        return 1;
    }
    return n * factorial(n - 1);  // recursive case
}

int main() {
    int n;
    cout << "Enter n: ";
    cin >> n;
    cout << n << "! = " << factorial(n) << endl;
    return 0;
}

Enter n: 5
5! = 120

Unfold factorial(5)

  1. factorial(5) = 5 × factorial(4)
  2. factorial(4) = 4 × factorial(3)
  3. factorial(3) = 3 × factorial(2)
  4. factorial(2) = 2 × factorial(1)
  5. factorial(1) = 1 (base case: stop)
  6. 2 × 1 = 2, 3 × 2 = 6, 4 × 6 = 24, 5 × 24 = 120 Answer: 120

Common pitfall

No base case (or one that is never reached) means the calls never stop, and the program crashes with a stack overflow.

Suggested time: about 4 min (skip if short on time)

Teaching tips

  • Optional slide; recursion is not assessed in Lab Exercise 11. Use it if the class is ahead of schedule.
  • Every call gets its own copy of n, just like the two calls to power() earlier. The calls stack up, then return in reverse order.
  • long long holds up to 20!; 21! overflows even a long long.
  • A loop version works too (Lab 1 notes had one). Recursion shines later for problems like tree traversal.

Common student pitfalls

  • Writing return factorial(n); (same size, never shrinks) instead of factorial(n - 1).
  • Negative input: with n <= 1 as the base case, it returns 1 instead of looping forever, but mathematically the answer is undefined. Validate input.

Ask the class

  • "How many calls to factorial happen for n = 5?" (5.)

Lab 11 · Check your understanding

Quick Check

Answer on paper first, then click to compare.

1In int cube(int n) called as cube(side), which is the parameter and which is the argument?

n is the parameter (in the header); side is the argument (in the call). Its value is copied into n.

2void addOne(int n) { n++; } … int x = 5; addOne(x); cout << x; prints?

5. n is a copy (pass-by-value); changing it does not change x.

3What one-character change makes Q2 print 6?

Make the parameter a reference: void addOne(int& n). Now n is another name for x.

4Why write const string& name instead of string name?

No copy of the (possibly long) string is made, and const guarantees the function cannot change it.

5Can two functions share a name if they differ only in return type?

No. Overloads must differ in their parameter lists (number or types of parameters).

6A function with static int count = 0; count++; return count; is called 4 times. What does the 4th call return?

4. A static local is created once and keeps its value between calls.

Suggested time: about 6 min

Teaching tips

  • Think-pair-share: 2 minutes alone, 1 minute with a seatmate, then open the answers.
  • Q2–Q3 are ILO 2 in miniature. If many miss Q2, replay the swap tracer.

Common student pitfalls

  • Q3: answering "add & in the call" (addOne(&x)). That passes an address and does not compile with an int parameter.
  • Q6: answering 1 (thinking the initializer runs every call).

Ask the class

  • "Which question was hardest?" Use the answer to choose what to review before the lab exercise.

  • Start the timer and walk around. Open hints one at a time only if many students are stuck.
  • After revealing, run the tracer with 9 3 7, then try 1 2 3 (no swaps) and 3 2 1 (three swaps). Ask students to predict the number of swaps first.
  • The tracer's Memory panel shows first (alias of a) etc., so students see which of main's variables each call touches.

Common student pitfalls

  • Forgetting &: the output is the unsorted input.
  • Only two calls (a, b) and (b, c): fails for 3 2 1 → prints 2 1 3.
  • Swapping without a temp variable (first = second; second = first;) duplicates one value.

Ask the class

  • "How would you sort in descending order with the same function?" (Call it with the arguments reversed, e.g. sortTwo(b, a).)
