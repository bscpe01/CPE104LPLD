Lab 5 · Review of Lab 1

The Three Control Structures

A control structure decides the order in which statements run. Every program is built from just three, each with one entry and one exit.

1 · Sequence Today: Lab 5

Statements run one after another, each exactly once.

2 · Selection Lab 6

A condition chooses one of two paths.

3 · Repetition Labs 7–8

Steps repeat while a condition stays true.

Key concept

Every program you wrote in Labs 2–4 was already sequential. Today you learn to design sequential programs deliberately: plan the inputs, the formulas, and the outputs before you type.

Suggested time: about 4 min

Teaching tips

  • Same three structures as Lab 1 (Böhm and Jacopini, 1966). The syllabus covers them in C++ over Labs 5–8, one structure at a time.
  • Everyday sequence: a recipe with no "if" and no "repeat until", where every step happens once, in order.
  • Selection and repetition contain sequences inside them, so getting sequence right comes first.

Common student pitfalls

  • Believing a program "knows" to wait or go back. Without selection or repetition, the computer runs each line exactly once, top to bottom.

Ask the class

  • "Converting 37.5 °C to °F: which structure? Checking whether a temperature is a fever? Logging a temperature every minute?" (Sequence, selection, repetition.)

Lab 5 · Sequence

Sequential Execution: Order Matters

Statements run top to bottom, each exactly once. A formula uses the values its variables have at that moment.

Wrong order

double length, width, area;
area = length * width;   // garbage * garbage!
cout << "Enter length and width (m): ";
cin >> length >> width;
cout << "Area = " << area << " sq. m" << endl;

The area is computed before the input exists. It prints an unpredictable value (often 0, sometimes something like 6.9e-310), no matter what the user types.

Key concept

  • C++ assignment is not a spreadsheet formula. area does not update when length changes later.
  • Safe order: declare → input → process → output.

Right order

#include <iostream>
using namespace std;

int main() {
    double length, width, area;
    cout << "Enter length and width (m): ";
    cin >> length >> width;
    area = length * width;   // after the input
    cout << "Area = " << area << " sq. m" << endl;
    length = 10;   // area stays 14.4
    cout << "Area = " << area << " sq. m" << endl;
    return 0;
}

Suggested time: about 6 min

Teaching tips

  • Run the wrong-order version live. Depending on the compiler and settings it prints 0 or a strange tiny number, which is exactly the point: the result is unpredictable. Recent g++ versions with -Wall may warn that length "is used uninitialized".
  • The second "Area = 14.4" surprises students who use Excel. In a spreadsheet the cell would update; in C++ the statement already ran and will not run again.
  • Link to Lab 3: uninitialized local variables hold garbage.

Common student pitfalls

  • Writing the formula next to the declaration "to keep things together".
  • Printing before computing: the cout for the result is placed above the formula line.

Ask the class

  • "How would you make the second line print 32 (10 × 3.2)?" (Recompute: put area = length * width; again after length = 10;.)

Lab 5 · Program design

The IPO Model: Input → Process → Output

Before coding, list what comes in, what must be computed, and what goes out. That list is an IPO chart.

IPO chart: convert a sensor's Celsius reading to Fahrenheit and Kelvin
InputProcessOutput
celsius
double, in °C		 1. fahrenheit = celsius × 9 / 5 + 32
2. kelvin = celsius + 273.15		 fahrenheit (°F)
kelvin (K)
Test: 37.5 37.5 × 9 / 5 + 32 = 99.5
37.5 + 273.15 = 310.65		 99.5 °F
310.65 K

How to fill it in

  1. Output first: what does the problem ask for?
  2. Input: what values must the user supply? Note the units.
  3. Process: which formulas turn the inputs into the outputs?
  4. Hand-compute one test case now, to check the program later.

Suggested time: about 6 min

Teaching tips

  • The IPO chart is steps 1–2 of Lab 1's "Steps in Creating an Algorithm" (inputs and outputs, then the process), written as a table. Gaddis and Farrell both use it.
  • Work backwards from the output: ask "what does the user want to see?" first. Students who start from the inputs often collect values they never use.
  • The test row matters for CO2: the hand-computed 99.5 is what students compare against when the program runs.
  • The symbols in the diagram are the same flowchart symbols from Lab 1: parallelogram for input/output, rectangle for process.

Common student pitfalls

  • Listing constants (9, 5, 32, 273.15) as inputs. They are fixed; they belong in the process, or as named constants.
  • Leaving out units, which causes the unit mistakes later (W vs kW, cm vs m).

Ask the class

  • "Write the IPO chart for the area of a circle given its diameter." (In: diameter. Process: radius = diameter / 2; area = π r². Out: area.)

Lab 5 · From plan to program

Translating Pseudocode and Flowcharts to C++

Each pseudocode line and each flowchart symbol becomes one (or two) C++ lines. Translate line by line.

Pseudocode (Lab 1 style)Flowchart symbolC++
// This program converts …(goal statement)// This program converts …
STARTTerminalint main() {

Translation rules

INPUT / GET → cin >> · DISPLAY / PROMPT → cout << · SET / COMPUTE → = · every statement ends with ;

Watch the operators

Translate operators too (Lab 4): ^ → pow(), = in a condition → ==, and check every division for int / int.

Suggested time: about 6 min

Teaching tips

  • Do this live: paste the pseudocode into Codechum as comments, then type the C++ line under each comment. Students see that the plan becomes the code's documentation.
  • Pseudocode doesn't declare variables, but C++ must. Collect every name that appears in the pseudocode and declare it once, near the top, with the right type.
  • The prompt and the input are often one parallelogram in the flowchart ("Input celsius"). That's acceptable, as in Lab 1.

Common student pitfalls

  • Copying pseudocode commas into cout: cout << "Kelvin: ", kelvin; compiles (comma operator) but never prints kelvin. Use << between items.
  • Forgetting the space at the end of a prompt string, so the typed value sticks to the colon.

Ask the class

  • "Translate COMPUTE area = 3.1416 * radius ^ 2." (area = 3.1416 * pow(radius, 2); with <cmath>, or 3.1416 * radius * radius.)

Lab 5 · Flowchart ↔ C++

Trace It: Temperature Converter

Step through the program and watch each flowchart symbol light up as its C++ line runs.

#include <iostream>
using namespace std;

int main() {
    double celsius, fahrenheit, kelvin;
    cout << "Enter temperature in Celsius: ";
    cin >> celsius;
    fahrenheit = celsius * 9 / 5 + 32;
    kelvin = celsius + 273.15;
    cout << "Fahrenheit: " << fahrenheit << endl;
    cout << "Kelvin: " << kelvin << endl;
    return 0;
}

Suggested time: about 7 min

Teaching tips

  • Click Hide on the flowchart first and ask students to draw it from the code. Then reveal it and compare.
  • Trace 37.5 (99.5 °F, 310.65 K), then 100 (212, 373.15), then −40 (−40 °F, the one temperature where both scales agree).
  • Line 8 works because celsius is a double: celsius * 9 is a double, so / 5 is real division. Ask what 9 / 5 * celsius + 32 would print (Lab 4 pitfall: 1 × celsius + 32).
  • Expected output for 37.5: Fahrenheit: 99.5, Kelvin: 310.65 (default cout, 6 significant digits).

Common student pitfalls

  • Declaring int celsius. Then 37.5 is read as 37 and the rest of the input is left unread.
  • Writing (5 / 9) when converting the other way (°F → °C). It's 0 in integer math; use 5.0 / 9.

Ask the class

  • "Which symbol does line 5 (the declaration) correspond to?" (None. Declarations aren't drawn in this course's flowcharts.)

Lab 5 · Library functions

Math Functions in <cmath>

Add #include <cmath> and C++ gives you the functions a scientific calculator has. They return double.

FunctionMeaningExample → result
pow(x, y)xypow(2, 10) → 1024
sqrt(x)square rootsqrt(144.0) → 12
fabs(x)absolute valuefabs(-7.5) → 7.5
ceil(x)round upceil(4.2) → 5

round(x)nearest (.5 away from 0)round(2.5) → 3
sin(x) cos(x)x in radianssin(30 * PI / 180) → 0.5

Suggested time: about 7 min

Teaching tips

  • The distance formula is the Pythagorean theorem, the same idea as Lab 6's battlefield coordinates: √(30² + 40²) = 50.
  • Last line, a real use of ceil: how many 8-GB flash drives hold 100 GB of files? 100 / 8 = 12.5, rounded up to 13. Rounding down would leave files behind.
  • Negatives: ceil(-4.2) = −4, floor(-4.2) = −5, round(-2.5) = −3. "Up" means toward +∞, not "away from zero".
  • There's no standard π constant before C++20 (std::numbers::pi), so the course defines const double PI = 3.14159265358979; (next slides).

Common student pitfalls

  • Passing degrees to sin/cos. sin(30) is sin of 30 radians (≈ −0.988).
  • Using abs on a double. abs also has an integer version (the C one), and with some headers or older compilers abs(-7.5) ends up as 7. fabs always works on doubles.
  • Writing sqrt x or pow(x): functions need parentheses and the right number of arguments.

Ask the class

  • "How many 20-seat jeepneys carry 75 students?" (ceil(75.0 / 20) = 4.)

Lab 5 · Formatted output

Formatted Output with <iomanip>

Manipulators control how cout prints: a fixed number of decimals and neat columns.

ManipulatorEffectLasts
setprecision(n)Alone: n significant digits. With fixed: n decimal placessticky
fixedFixed-point notation (never 1e+06), keeps trailing zerossticky
setw(n)Print the next item in a field n characters widenext item only
left / rightAlignment inside the field (default: right)sticky

Remember

  • setw and setprecision need #include <iomanip>.
  • For money and measurements, use cout << fixed << setprecision(2); once, before printing the results.
  • Sticky = stays in effect until you change it.
  • Formatting changes only how a value looks, not the value stored.

Suggested time: about 8 min

Teaching tips

  • The first three lines print the same value three ways. Ask students to explain the difference between 54.5 (3 significant digits) and 54.545 (3 decimal places).
  • Count characters in the table output with the class: "Quantity" plus 4 spaces fills 12; "Value" is pushed right inside 8. Numbers line up on the decimal point because they all have 2 decimals and are right-aligned.
  • fixed, left, and right live in <iostream>; only manipulators that take an argument (setw, setprecision) need <iomanip>. Including both is the simple rule.
  • To go back to default formatting: cout << defaultfloat << setprecision(6);

Common student pitfalls

  • Expecting setw to apply to every later item. It resets after one item.
  • Putting setprecision(2) without fixed and getting 55 instead of 54.55.
  • A string longer than the setw width is not cut; it just pushes the columns out of line.

Ask the class

  • "What does cout << fixed << setprecision(1) << 9.87; print?" (9.9.)

Lab 5 · Engineering example 1

Series and Parallel Resistance

Given two resistors, compute their equivalent resistance when connected in series and in parallel.

Formulas

Rseries = R1 + R2

Rparallel = (R1 × R2) / (R1 + R2)

"Product over sum" works for exactly two resistors. The general form is 1 / (1/R1 + 1/R2).

InputProcessOutput
r1, r2 (Ω)series and parallel formulasr_series, r_parallel (Ω, 2 decimals)

Common pitfall

With int r1, r2; the general form 1 / r1 is 0 (integer division) for any resistor above 1 Ω. Keep measurements in double, or write 1.0 / r1.

Suggested time: about 6 min

Teaching tips

  • Hand check first: 1000 × 470 = 470,000; 470,000 / 1470 = 319.73. A quick sanity check: the parallel value is always smaller than the smaller resistor.
  • Try 220 and 220: series 440, parallel 110 (two equal resistors in parallel give half).
  • The parentheses in line 10 are required: without them, r1 * r2 / r1 + r2 = r2 + r2.
  • Output uses "ohms" rather than Ω, since the Ω symbol may not display in a Windows console.

Common student pitfalls

  • Dropping the parentheses around the denominator.
  • Entering kΩ values for one resistor and Ω for the other (1 and 470). Units must match.
  • R1 = R2 = 0 divides 0 by 0 and prints nan or -nan. Guarding against it needs if (Lab 6).

Ask the class

  • "Two 1 kΩ resistors in parallel: predict the output before running." (500.00 ohms.)

Lab 5 · Engineering example 2

How Much Does Your PC Cost to Run?

Energy (kWh) = power (W) × hours ÷ 1000. Cost = energy × rate per kWh.

#include <iostream>
#include <iomanip>
using namespace std;

int main() {
    double watts, hours, days, rate;
    cout << "Power rating (W): ";
    cin >> watts;
    cout << "Hours used per day: ";
    cin >> hours;
    cout << "Number of days: ";
    cin >> days;
    cout << "Rate (PHP per kWh): ";
    cin >> rate;
    double energy_kwh = watts * hours * days / 1000;
    double cost = energy_kwh * rate;
    cout << fixed << setprecision(2);
    cout << "Energy used: " << energy_kwh << " kWh" << endl;
    cout << "Cost: PHP " << cost << endl;
    return 0;
}

Suggested time: about 8 min

Teaching tips

  • ₱11.85/kWh is a sample rate. Ask a student to look up the current Meralco (or local electric cooperative) residential rate and re-run with it.
  • Try other appliances in the tracer: a 1200 W aircon for 8 h/day, a 60 W laptop for 10 h/day, a 10 W Wi-Fi router for 24 h/day. Students are often surprised how much the "always on" router adds up.
  • Units: watts × hours = watt-hours; ÷ 1000 gives kilowatt-hours, which is what the meter counts.
  • The program prints "PHP" because the ₱ sign may not display in a Windows console.

Common student pitfalls

  • Forgetting the ÷ 1000, so the bill is 1000 times too large.
  • Declaring int watts, days. Here it would still work, because hours is a double and the expression is evaluated left to right. But watts / 1000 * hours * days with an int watts would give 0 for anything under 1000 W. Use doubles for measurements.
  • Placing fixed << setprecision(2) after the cout lines it should format.

Ask the class

  • "Which output line would change if the rate went up by ₱1?" (Only the cost.)

Lab 5 · Engineering example 3

Named Constants: Volume of a Water Tank

A cylindrical tank holds V = π r² h cubic meters, and 1 m³ = 1000 L. Fixed values get a name.

Why named constants?

  • Readable: LITERS_PER_CUBIC_M explains itself; 1000 does not.
  • One place to change: update the value once, and every formula follows.
  • Protected: the compiler rejects any change.

const double PI = 3.14159265358979;
const double GRAVITY = 9.81; // m/s^2

Convention: UPPER_SNAKE_CASE names, so constants stand out from variables.

Common pitfall

PI = 3.14; later in the program → error: assignment of read-only variable 'PI'. A const must get its value when it is declared.

Suggested time: about 7 min

Teaching tips

  • Hand check: r = 0.6 m, π × 0.36 × 1.5 ≈ 1.6965 m³ ≈ 1696.46 L. 1696.46 / 20 = 84.8, rounded up to 85 jugs.
  • Line 15 combines Lab 4 and today: ceil returns a double (85.0), and static_cast<int> makes it a whole count so it prints as 85, not 85.00.
  • Typical rooftop tanks in the Philippines hold 500–2000 L, so 1696 L is a realistic answer. Sanity-checking magnitudes is part of testing.
  • Lab 3 introduced const; here the point is which numbers deserve a name: physical constants and conversion factors, not the 2 in "diameter / 2".

Common student pitfalls

  • Using the diameter as the radius, which makes the volume 4 times too large.
  • Mixing units: the diameter in cm and the height in m.
  • Using round instead of ceil for the jug count. Here both give 85, but a tank needing 84.3 jugs would round down to 84 and be left short.

Ask the class

  • "Which values in this program are inputs, which are constants, and which are computed?"

Lab 5 · Engineering example 4

Free Fall: How Long, How Fast?

Dropped from height h (no air resistance), an object falls for t = √(2h / g) and lands at v = g·t.

From formula to code

h = ½ g t² ⇒ t = √(2h / g)

v = g t · 1 m/s = 3.6 km/h

Solve for the unknown on paper first, then code the rearranged formula.

Common pitfall

1 / 2 * GRAVITY * t * t is always 0: 1 / 2 is integer division (Lab 4). Write 0.5 * GRAVITY * t * t or GRAVITY * t * t / 2.

Suggested time: about 7 min

Teaching tips

  • Story: a phone slips from a 2nd-floor balcony (about 6 m). Run with 6: 1.11 s, 10.85 m/s (39.06 km/h). That's why phones break.
  • Hand check for 20 m: 2 × 20 / 9.81 = 4.077; √4.077 = 2.019 s; 9.81 × 2.019 = 19.81 m/s.
  • The variable is called fall_time, not time, to avoid confusion with the library function time().
  • The last output line is a physics check: after half the fall time, the object has dropped only a quarter of the height (5 m of 20 m), because distance grows with t².
  • Same structure as every example today: constants, input, process (several formulas, each using earlier results), formatted output.

Common student pitfalls

  • Writing sqrt(2 * height) / GRAVITY. The parentheses must enclose the whole fraction.
  • Using g = 9.8 in one place and 9.81 in another. A named constant prevents that.
  • Entering a negative height: sqrt of a negative number gives nan. Validation comes in Lab 6.

Ask the class

  • "If the height is 4 times larger, what happens to the fall time?" (It doubles: t grows with √h.)

Lab 5 · Engineering example 5

Unit Conversions: Bytes and Speeds

Most conversions multiply or divide by one factor. Name the factor once, and the formula explains itself.

From → toFactorFormula
bytes → KB1 KB = 1024 Bbytes / 1024.0
KB → MB1 MB = 1024 KBkb / 1024.0
km/h → m/s1000 m / 3600 skmh * 1000.0 / 3600
m/s → km/h× 3.6ms * 3.6

KB or KiB?

Operating systems usually count 1 KB as 1024 bytes (strictly, a kibibyte, KiB). Storage makers use 1000. That's why a "500 GB" drive shows about 465 GB on your PC.

Suggested time: about 6 min

Teaching tips

  • CpE context: file sizes, memory, and network speeds come in many units. Mixing them up is a classic bug (and a classic exam question).
  • long long (8 bytes) is used for bytes because file sizes easily exceed the int limit of about 2.1 billion (a 3 GB video is already over it).
  • Hand check: 60 km/h × 1000 / 3600 = 16.666… → 16.67 m/s. Quick mental rule: divide km/h by 3.6.
  • Ask students to convert their own phone's free storage (in bytes, from Settings) to GB.

Common student pitfalls

  • Multiplying when they should divide (bytes × 1024). A sanity check catches it: KB must be a smaller number than bytes.
  • Dividing long long bytes by 1024 (an int): integer division gives 3375, losing the fraction. The program divides by the double constant 1024.0.
  • Writing KMH_TO_MS = 1000 / 3600;, which is 0 (integer division) even though the constant is a double.

Ask the class

  • "A 100 Mbps connection downloads at most how many MB per second?" (100 / 8 = 12.5 MB/s, since 1 byte = 8 bits. This sets up the seatwork.)

Lab 5 · Program design

Sequential Program Design Checklist

Use this for every problem in the lab exercise. It is also how the rubric's Problem Analysis criterion is judged.

Checklist

  1. IPO chart: list the inputs and outputs, with units.
  2. Formulas: write each one on paper; solve for the unknown; convert units first (W → kW, cm → m, degrees → radians).
  3. Types: double for measurements, int for counts, const for fixed values.
  4. Order: declare → input → process → output.
  5. Test: hand-compute one case before running; then try a boundary (0) and a typical value.
  6. Output: labels, units, fixed + setprecision.

Common pitfalls

  • Using a variable before it has a value (formula above cin).
  • Uninitialized variables: double total; total += x; adds to garbage. Start with double total = 0;
  • Integer division in formulas: 9 / 5, 1 / 2, 1 / r.
  • Forgetting #include <cmath> or <iomanip> ("'sqrt' was not declared in this scope").
  • Unit mistakes: degrees into sin, W vs kW, diameter vs radius.
  • ^ for powers. Use pow or multiply.

Suggested time: about 5 min

Teaching tips

  • Map the checklist to the rubric. Steps 1–2 are Problem Analysis & Algorithm Formulation; step 5 is Functionality, Testing & Debugging; steps 3, 4, and 6 are Structure, Readability & Standards.
  • Have students copy the checklist into the top of their lab file as a comment block and tick items off.
  • Step 5 is CO2 in action: a program is "correct" only when its output matches a value you computed independently.

Common student pitfalls

  • Testing only with the sample input. The rubric's Functionality level depends on normal, boundary, and edge cases.
  • Trusting output that "looks reasonable" without a hand check.

Ask the class

  • "Which pitfall have you already hit this semester?" (Quick poll; most will say integer division.)

Lab 5 · Quick check

Quick Check

Answer on paper first, then click to reveal.

1Which control structure runs every statement exactly once, top to bottom?

Sequence. Selection (Lab 6) may skip statements; repetition (Labs 7–8) may run them many times.

2A program prints a strange area like 6.9e-310 no matter what is typed. What is the most likely bug?

The formula runs before cin, so it uses uninitialized (garbage) values. Move it after the input.

3What do cout << setprecision(2) << 3.14159; and cout << fixed << setprecision(2) << 3.14159; print?

3.1 (2 significant digits) and 3.14 (2 decimal places).

4Evaluate sqrt(pow(3, 2) + pow(4, 2)), ceil(7.1), and floor(-7.1).

5, 8, and −8 (floor rounds toward −∞).

5With double c = 100;, why does f = 9 / 5 * c + 32; give 132 instead of 212?

9 / 5 is integer division = 1, so f = 100 + 32. Write c * 9 / 5 + 32 or 9.0 / 5 * c + 32.

6What does cout << setw(5) << 42 << "|" << 7 << "|"; print?

   42|7|: three spaces, then 42 right-aligned in 5 characters. setw affects only the next item, so 7 has no padding.

Suggested time: about 6 min

Teaching tips

  • Run as a think-pair-share, or have students hold up fingers for multiple-choice versions.
  • Q3 and Q6 are the most-missed. If many students miss them, re-run the format demo slide with their suggested values.
  • Q5 links back to Lab 4; it is the most common bug in temperature-conversion programs.

Common student pitfalls

  • Q4: answering −7 for floor(-7.1).
  • Q6: padding the 7 as well.

Ask the class

  • "Which checklist step would have caught the bug in Q5?" (Step 5: hand-compute 100 °C → 212 °F first.)

Lab 5 · Seatwork

Seatwork: How Long Will the Download Take?

You need to download a 4.7 GB IDE installer and course files before the next lab. Your home internet is 25 Mbps. Will it finish before the jeep ride to school?

Instruction: Make an IPO chart, then write a C++ program that reads the file size (GB) and the internet speed (Mbps) and displays the download time in seconds and in minutes, with 2 decimal places. Use 1 GB = 1000 MB and 1 byte = 8 bits.

Need a hint?

Hint 1

Speed is in megabits per second, size is in gigabytes. Convert the size to megabits first: GB × 1000 × 8.

Hint 2

time (s) = size in megabits ÷ speed in Mbps. Minutes = seconds ÷ 60.

Hint 3

Hand check: 4.7 × 8000 = 37,600 Mb; 37,600 ÷ 25 = 1504 s, a little over 25 minutes.

Seatwork timer

15:00

Answer & walkthrough: locked

Opens when your instructor releases it. Enter the passphrase your instructor gives you.

Suggested time: about 20 min (15 working, 5 review)

Running the seatwork

  • Require the IPO chart on paper before anyone opens the IDE. Walk around and check the units in the charts first.
  • Open hints only if many students are stuck after 5 minutes. Hint 3 gives the hand check; it's fine to show it to everyone near the end.
  • Extension for fast finishers: also print the time as whole minutes and seconds using static_cast<int> and % (Lab 4), e.g. 1504 s = 25 min 4 s.
  • Real downloads are slower than the rated speed (overhead, Wi-Fi). The program computes the ideal minimum.

Common student pitfalls

  • Forgetting the × 8 (bytes vs bits) and getting 188 s.
  • Using 1024 instead of 1000. Accept it if the student states the assumption; the answer becomes 1540.10 s.
  • Dividing in the wrong order (speed ÷ size).

Ask the class

  • "How fast must the internet be to finish in 10 minutes?" (37,600 Mb ÷ 600 s ≈ 62.7 Mbps.)

  • <cmath>: pow, sqrt, fabs, ceil, floor, round, sin (radians!).
  • <iomanip>: fixed + setprecision(2) for results, setw for columns.
  • Name fixed values with const; watch units and integer division.
  • Trust a program only after it matches a hand-computed test case.
