Lab 9 · Motivation

Why Arrays? 40 Grades, 40 Variables?

In Labs 7–8 each cin overwrote the previous value. To use the values again (sort them, list the ones above the average) you must keep them all.

Without an array

int g1, g2, g3, g4, g5, g6, g7, g8,
    g9, g10, /* ... */ g40;
cin >> g1 >> g2 >> g3 /* ... */ >> g40;
int sum = g1 + g2 + g3 /* ... */ + g40;
// list the grades above average?
// 40 more if statements...

Does not scale: 80 names to type, and changing 40 to 45 means editing every line.

With an array

const int SIZE = 40;
int grades[SIZE];
int sum = 0;
for (int i = 0; i < SIZE; i++) {
    cin >> grades[i];
    sum += grades[i];
}

One name, one loop. Change SIZE and the whole program follows.

Key concept

An array is a fixed-size group of elements of the same type, stored next to each other in memory, and reached through one name plus an index: grades[0], grades[1], …

Suggested time: about 5 min

Teaching tips

  • Bridge from Lab 7: the sentinel average program could compute the average, but it could not then print "which grades were above the average", because every grade was gone. That exact problem is today's seatwork.
  • Analogy: a row of numbered lockers, or a jeepney's seat numbers. One name (the row), and a number to pick one box.
  • "Same type" matters: an int array holds only ints. Mixed data (name + grade) needs a struct or class, later in the course.

Common student pitfalls

  • Thinking an array can grow by itself. A C++ array has a fixed size decided when it is declared.

Ask the class

  • "What else in engineering is naturally a list?" (sensor samples, resistor values in a circuit, daily power readings, pixel rows.)

Lab 9 · 1D arrays

Declaring an Array

Give the element type, a name, and the number of elements in square brackets. The size must be a constant.

type name[SIZE]; · e.g. const int SIZE = 5; int grades[SIZE];

#include <iostream>
using namespace std;

int main() {
    const int SIZE = 5;     // size: a constant
    int grades[SIZE];       // grades[0] .. grades[4]
    grades[0] = 88;                 // first element
    grades[SIZE - 1] = 95;          // last element
    cout << "First: " << grades[0] << endl;
    cout << "Last: " << grades[SIZE - 1] << endl;
    cout << "Bytes: " << sizeof(grades) << endl;
    return 0;
}

First: 88
Last: 95
Bytes: 20
Vocabulary
ElementOne box in the array, like grades[2]
Index (subscript)The box number, from 0 to SIZE − 1
SizeHow many elements: fixed when declared
sizeofBytes used: 5 ints × 4 bytes = 20

Why const int SIZE?

Standard C++ needs the size at compile time. A named constant also means you change one line, and every loop that uses SIZE follows.

Suggested time: about 6 min

Teaching tips

  • Read the declaration aloud: "grades is an array of 5 ints".
  • Stress that the last element is grades[SIZE - 1], i.e. grades[4], not grades[5]. Write 0 1 2 3 4 on the board under five boxes.
  • sizeof(grades) gives the bytes of the whole array (20), not the count of elements. The next slides show how to get the count.
  • Only elements 0 and 4 got values here. Elements 1 to 3 hold garbage, which is fine as long as we never read them.

Common student pitfalls

  • Declaring int grades[5]; and then using grades[5] as the "fifth" element.
  • Using a plain variable as the size: int n; cin >> n; int a[n];. g++ accepts it as an extension, but it is not standard C++ (see pitfalls).

Ask the class

  • "How many bytes does double volts[10]; use?" (10 × 8 = 80.)

Lab 9 · 1D arrays

Indexes Start at 0: How an Array Sits in Memory

The elements are stored back to back. For an int array each element is 4 bytes, so the addresses go up by 4.

int grades[5] = {88, 92, 75, 64, 95};

[0]880x7ffc10
[1]920x7ffc14
[2]750x7ffc18
[3]640x7ffc1c
[4]950x7ffc20

Addresses are illustrative; real ones change every run. The 4-byte steps are real for int.

Index = offset

The index counts steps from the start. grades[2] is 2 steps past the first element: address = start + 2 × 4 bytes.

Reading and writing

cout << grades[2]; prints 75.
grades[2] = 80; replaces it.
grades[i + 1]: any int expression works as an index.

Valid indexes

Only 0 to 4. grades[5] and grades[-1] are outside the array, and C++ does not stop you (more on this later).

Suggested time: about 6 min

Teaching tips

  • Why start at 0? Because the index is the offset from the start of the array: the first element is 0 steps away. This is also why arrays and pointers (Lab 10) fit together so well.
  • Compare with double volts[3]: its addresses go up by 8, because a double is 8 bytes.
  • Optional demo: cout << &grades[0] << " " << &grades[1]; prints two real hex addresses 4 apart. They change every run, which is why the slide's addresses are only examples.

Common student pitfalls

  • Mixing up the index and the value: in grades[2] = 75, 2 is the position and 75 is the data.
  • Saying "the 2nd element" for grades[2]. It is the 3rd element. Use "element at index 2" to stay precise.

Ask the class

  • "If grades[0] is at 0x7ffc10, where is grades[4]?" (0x7ffc10 + 16 = 0x7ffc20.)

Lab 9 · 1D arrays

Initializing Arrays

Give starting values in braces. Missing values become 0, and C++ can count the list for you.

#include <iostream>
using namespace std;

int main() {
    int full[5] = {90, 85, 77, 92, 68};
    int partial[5] = {90, 85};      // rest are 0
    int inferred[] = {3, 1, 4, 1, 5, 9};  // size 6
    int zeros[5] = {};              // all 0
    cout << "partial:";
    for (int i = 0; i < 5; i++) {
        cout << " " << partial[i];
    }
    cout << endl;
    int count = sizeof(inferred) / sizeof(inferred[0]);
    cout << "inferred size: " << count << endl;
    cout << "full[4] = " << full[4] << endl;
    cout << "zeros[2] = " << zeros[2] << endl;
    return 0;
}

Suggested time: about 6 min

Teaching tips

  • Live: print an uninitialized local array (int g[5]; cout << g[0];). The value is garbage and may differ between runs and machines. Then add = {} and run again.
  • "Partial list → the rest are zero" is the easiest way to start counters and accumulators at 0.
  • The sizeof trick only works where the array was declared. Once arrays are passed to functions (Lab 11) it no longer works, which is one reason to keep a SIZE constant.

Common student pitfalls

  • Giving more values than the size: int a[3] = {1, 2, 3, 4}; is a compile error ("too many initializers").
  • Believing int a[5] = {7}; makes all five elements 7. Only a[0] is 7; the rest are 0.

Ask the class

  • "What does int a[4] = {1}; contain?" (1 0 0 0.)

Lab 9 · Traversal

Traversal: Visit Every Element with a Loop

The loop counter becomes the index: for (int i = 0; i < SIZE; i++) visits 0 to SIZE − 1, once each.

#include <iostream>
using namespace std;

int main() {
    const int SIZE = 5;
    double volts[SIZE];
    cout << "Enter " << SIZE << " readings: ";
    for (int i = 0; i < SIZE; i++) {
        cin >> volts[i];        // fill each element
    }
    cout << "Last to first:" << endl;
    for (int i = SIZE - 1; i >= 0; i--) {
        cout << "volts[" << i << "] = " << volts[i];
        cout << endl;
    }
    return 0;
}

Enter 5 readings: 12.5 11.8 12.1 12.6 11.9
Last to first:
volts[4] = 11.9
volts[3] = 12.6
volts[2] = 12.1
volts[1] = 11.8
volts[0] = 12.5

Printing in reverse is impossible without storing the values, since the last one typed comes out first.

#include <iostream>
using namespace std;

int main() {
    const int SIZE = 5;
    double volts[SIZE] = {12.5, 11.8, 12.1, 12.6, 11.9};
    double total = 0;
    for (double v : volts) {    // each value in turn
        total += v;
    }
    cout << "Total: " << total << endl;
    cout << "Average: " << total / SIZE << endl;
    return 0;
}

Total: 60.9
Average: 12.18

When to use it

  • Reads every value, start to end. No index to get wrong.
  • Use the normal for when you need the index (printing [i], going backward, comparing neighbors).
  • v is a copy: changing v does not change the array.

Suggested time: about 8 min

Teaching tips

  • Live-code the first program. Type all 5 values on one line, then try typing them one per line: cin accepts both.
  • The reverse loop starts at SIZE - 1 and stops after 0 (i >= 0). Ask why it doesn't start at SIZE.
  • Range-based for needs C++11 or newer. Codechum and current g++ are fine; very old Dev-C++ setups may need -std=c++11 in the compiler options.
  • To change elements inside a range-based for you write for (double& v : volts). That & is a reference, which is next lab's topic.

Common student pitfalls

  • for (int i = 1; i <= SIZE; i++): skips element 0 and touches element SIZE, which does not exist.
  • Trying cin >> volts; or cout << volts; to read or print the whole array. You must loop over the elements (printing volts shows an address).

Ask the class

  • "How would you print only the elements at even indexes?" (i += 2, or if (i % 2 == 0).)

Lab 9 · Array algorithms

Sum, Average, and Counting

The Lab 7 accumulator and counter patterns, applied to an array: one pass through the elements does both.

#include <iostream>
#include <iomanip>
using namespace std;

int main() {
    const int SIZE = 8;
    int grades[SIZE] = {88, 72, 95, 64, 79, 91, 70, 85};
    int sum = 0, passed = 0;
    for (int i = 0; i < SIZE; i++) {
        sum += grades[i];           // accumulator
        if (grades[i] >= 75) {
            passed++;               // counter
        }
    }
    // cast first, to avoid integer division
    double average = static_cast<double>(sum) / SIZE;
    cout << "Sum: " << sum << endl;
    cout << fixed << setprecision(2);
    cout << "Average: " << average << endl;
    cout << "Passed: " << passed << " of " << SIZE;
    cout << endl;
    return 0;
}

Sum: 644
Average: 80.50
Passed: 5 of 8

Pattern

  • Accumulator: sum += grades[i];
  • Counter with a condition: if (grades[i] >= 75) passed++;
  • Average = sum ÷ SIZE, computed after the loop.

Integer division

sum / SIZE with two ints gives 80, not 80.5. Cast one side to double first.

Suggested time: about 6 min

Teaching tips

  • Ask the class to compute the sum by hand first: 88 + 72 + 95 + 64 + 79 + 91 + 70 + 85 = 644. Then 644 / 8 = 80.5.
  • static_cast<double>(sum) is the modern C++ cast; (double) sum also works and may be what students saw in Lab 3–4.
  • 75 is the passing grade used here; adjust to your institution's grading scale if you prefer.

Common student pitfalls

  • static_cast<double>(sum / SIZE): the division already happened in integer math, so the cast comes too late (80.00).
  • Computing the average inside the loop on every pass. It works, but it is wasted work and confusing to read.

Ask the class

  • "How would you also count the failing grades?" (SIZE - passed, no second loop needed.)

Lab 9 · Array algorithms

Highest and Lowest, and Where

Start with element 0 as the "best so far" and compare it with the rest. Keep the index too, to say which day.

#include <iostream>
using namespace std;

int main() {
    const int DAYS = 7;
    double temp[DAYS] = {31.5, 33.2, 30.8, 34.1,
                         32.7, 29.9, 33.0};
    double highest = temp[0], lowest = temp[0];
    int highDay = 0, lowDay = 0;
    for (int i = 1; i < DAYS; i++) {
        if (temp[i] > highest) {
            highest = temp[i];
            highDay = i;        // remember WHERE
        }
        if (temp[i] < lowest) {
            lowest = temp[i];
            lowDay = i;
        }
    }
    cout << "Highest: " << highest << " C on day ";
    cout << highDay + 1 << endl;
    cout << "Lowest: " << lowest << " C on day ";
    cout << lowDay + 1 << endl;
    return 0;
}

Suggested time: about 7 min

Teaching tips

  • Analogy: a "king of the hill" game. The first reading starts on top; each new reading challenges it and takes over only if it is bigger.
  • Starting from temp[0] (not 0 or 100) works for any data, including negative temperatures. The loop can then start at i = 1.
  • Ask: "What if two days tie for the highest?" With > the first one is kept; with >= the last one wins.

Common student pitfalls

  • Starting highest = 0: fails for all-negative data (see the pitfalls slide).
  • Using else if between the max and min tests. It works here because the first element is already both, but it hides the idea that the two checks are independent.
  • Forgetting to store the index, then searching the array again to find where the maximum was.

Ask the class

  • "How would you print the range (highest − lowest)?" (34.1 − 29.9 = 4.2.)

Lab 9 · Searching

Linear Search: Check Each Element in Turn

Compare the target with element 0, 1, 2, … and stop at the first match. If the loop ends, it is not there.

#include <iostream>
using namespace std;

int main() {
    const int SIZE = 6;
    int partNo[SIZE] = {42, 17, 89, 5, 63, 28};
    int target;
    cout << "Part number to find: ";
    cin >> target;
    bool found = false;
    int position = -1;
    for (int i = 0; i < SIZE; i++) {
        if (partNo[i] == target) {
            found = true;
            position = i;
            break;          // stop at the first match
        }
    }
    if (found) {
        cout << "Found at index " << position << endl;
    } else {
        cout << target << " is not in the list.";
        cout << endl;
    }
    return 0;
}

Work: up to SIZE comparisons (the worst case is a target at the end or not present at all).

Suggested time: about 8 min

Teaching tips

  • Trace with 5 (found at index 3, 4 comparisons), 42 (found at once, 1 comparison), and 50 (not found, 6 comparisons).
  • The flag found plus position is the Lab 8 "decide after the loop" pattern. position = -1 is a common "nothing yet" value, because -1 can never be a real index.
  • Linear search works on unsorted data. Faster searches (binary search) need sorted data, which is one reason we sort next.

Common student pitfalls

  • Printing "not found" inside the loop in an else: it prints once for every non-matching element.
  • Returning or printing the index as a "position" without adding 1 when the problem counts from 1 (Lab Exercise Problem 2 does).

Ask the class

  • "How would you count all matches instead of stopping at the first?" (remove the break, add a counter.)

Lab 9 · Sorting

Bubble Sort: Swap Neighbors Until Sorted

Swap neighbors that are out of order. Each pass "bubbles" the largest remaining value to the end; a pass with no swaps means done.

#include <iostream>
using namespace std;

int main() {
    const int SIZE = 5;
    int arr[SIZE];
    cout << "Enter " << SIZE << " numbers: ";
    for (int i = 0; i < SIZE; i++) {
        cin >> arr[i];
    }
    for (int pass = 1; pass < SIZE; pass++) {
        bool swapped = false;
        for (int i = 0; i < SIZE - pass; i++) {
            if (arr[i] > arr[i + 1]) {
                int temp = arr[i];      // swap the
                arr[i] = arr[i + 1];    // neighbors
                arr[i + 1] = temp;
                swapped = true;
            }
        }
        cout << "After pass " << pass << ":";
        for (int i = 0; i < SIZE; i++) {
            cout << " " << arr[i];
        }
        cout << endl;
        if (!swapped) {
            break;      // no swaps: already sorted
        }
    }
    return 0;
}

Suggested time: about 12 min

Teaching tips

  • Before the code, sort 5 volunteers by height using only "compare two neighbors, swap if needed". They discover bubble sort themselves.
  • Swapping needs a third variable: like swapping the drinks in two glasses, you need an empty glass (temp). Show the wrong version arr[i] = arr[i+1]; arr[i+1] = arr[i]; (both become the same value).
  • The inner limit SIZE - pass shrinks each pass because the end of the array is already sorted.
  • Early exit: pass 3 made no swaps, so the array is sorted and break skips pass 4. In the tracer, try 1 2 3 4 5: only one pass.
  • Trace 5 4 3 2 1 (worst case: 4 passes, 10 swaps) and 1 2 3 4 5 (best case: 1 pass, 0 swaps).
  • Descending order: change > to < in the comparison. Lab Exercise Problem 1 needs this.

Common student pitfalls

  • Inner loop i < SIZE: then arr[i + 1] reads arr[5], outside the array.
  • Resetting swapped outside the outer loop, so the early exit never (or always) triggers.

Ask the class

  • "For 5 elements, what is the most comparisons bubble sort can make?" (4 + 3 + 2 + 1 = 10.) "For n elements?" (n(n − 1)/2: the nested-loop triangle from Lab 8.)

Lab 9 · Sorting (optional)

Selection Sort: Find the Smallest, Put It in Front

Each pass finds the smallest value in the unsorted part and swaps it into place: at most one swap per pass.

#include <iostream>
using namespace std;

int main() {
    const int SIZE = 5;
    int arr[SIZE] = {29, 10, 14, 37, 13};
    for (int i = 0; i < SIZE - 1; i++) {
        int minIndex = i;           // smallest so far
        for (int j = i + 1; j < SIZE; j++) {
            if (arr[j] < arr[minIndex]) {
                minIndex = j;
            }
        }
        int temp = arr[i];      // one swap per pass
        arr[i] = arr[minIndex];
        arr[minIndex] = temp;
        cout << "After pass " << i + 1 << ":";
        for (int k = 0; k < SIZE; k++) {
            cout << " " << arr[k];
        }
        cout << endl;
    }
    return 0;
}

Teaching tips

  • Pass 3 shows "no change" because 14 was already in place; selection sort still does the full scan (no early exit).
  • Both sorts do about n²/2 comparisons, so both are slow for large arrays. Real programs use std::sort (later courses); writing your own sort is about learning nested loops and swaps.

Common student pitfalls

  • Storing the minimum value instead of its index, so there is no way to know which element to swap with.
  • Starting the inner loop at 0 instead of i + 1.

Ask the class

  • "Which sort would you choose if swaps were very expensive (e.g., moving heavy crates)?" (selection sort.)

Lab 9 · 2D arrays

Two-Dimensional Arrays: Rows and Columns

int m[3][4]; is 3 rows of 4 ints: a table. Use two indexes, row first, then column: m[r][c].

const int ROWS = 3, COLS = 4;
int m[ROWS][COLS] = {
    {1, 2, 3, 4},       // row 0
    {5, 6, 7, 8},       // row 1
    {9, 10, 11, 12}     // row 2
};
cout << m[1][2];        // row 1, col 2: prints 7
m[2][0] = 0;            // change one element

#include <iostream>
#include <iomanip>
using namespace std;

int main() {
    const int ROWS = 3, COLS = 4;
    int m[ROWS][COLS] = {
        {1, 2, 3, 4},           // row 0
        {5, 6, 7, 8},           // row 1
        {9, 10, 11, 12}         // row 2
    };
    for (int r = 0; r < ROWS; r++) {    // rows
        for (int c = 0; c < COLS; c++) {  // cols
            cout << setw(4) << m[r][c];
        }
        cout << endl;
    }
    cout << "m[1][2] = " << m[1][2] << endl;
    return 0;
}

Teaching tips

  • Read m[1][2] as "row 1, column 2". Find it in the table (highlighted), then in the memory strip: it is element 1 × 4 + 2 = 6 of the strip (counting from 0).
  • The nested loops are the Lab 8 grid pattern: outer loop = rows, inner loop = columns, endl after each row.
  • The inner braces in the initializer are optional but make the rows visible. Always include them.
  • "Multi-dimensional" also allows int cube[2][3][4]; (3D), but 2D covers almost every lab problem.

  • Writing m[1, 2] (Python/Excel style). In C++ that is not a 2D index; always use two brackets m[1][2].
  • Swapping rows and columns: m[c][r] in the loops. It still compiles, but reads the wrong elements (and goes out of bounds when rows ≠ columns).

Ask the class

  • "How many bytes does int m[3][4] use?" (12 × 4 = 48.)

Lab 9 · 2D arrays

Row Sums and Column Sums

Rows: the outer loop picks a row, the inner loop walks across it. Columns: swap the loops so the inner loop walks down a column.

#include <iostream>
#include <iomanip>
using namespace std;

int main() {
    const int STUDENTS = 3, QUIZZES = 4;
    int score[STUDENTS][QUIZZES] = {
        {18, 15, 20, 17},
        {12, 19, 16, 14},
        {20, 18, 19, 20}
    };
    cout << "           Q1  Q2  Q3  Q4  Total" << endl;
    for (int s = 0; s < STUDENTS; s++) {
        int rowSum = 0;             // reset per row
        cout << "Student " << s + 1;
        for (int q = 0; q < QUIZZES; q++) {
            cout << setw(4) << score[s][q];
            rowSum += score[s][q];
        }
        cout << setw(7) << rowSum << endl;
    }
    cout << "Quiz sum ";
    for (int q = 0; q < QUIZZES; q++) {
        int colSum = 0;         // reset per column
        for (int s = 0; s < STUDENTS; s++) {
            colSum += score[s][q];  // walk DOWN
        }
        cout << setw(4) << colSum;
    }
    cout << endl;
    return 0;
}

           Q1  Q2  Q3  Q4  Total
Student 1  18  15  20  17     70
Student 2  12  19  16  14     61
Student 3  20  18  19  20     77
Quiz sum   50  52  55  51

Which loop is outside?

  • Per row (each student's total): s outside, q inside.
  • Per column (each quiz's total): q outside, s inside.
  • Reset the sum at the start of each row or column.

Suggested time: about 8 min

Teaching tips

  • Point at the console: the "Total" column comes from the row loop, the "Quiz sum" row from the column loop.
  • The index order in score[s][q] never changes (always row first). Only the order of the loops changes.
  • Check one value by hand: Quiz 3 = 20 + 16 + 19 = 55.
  • setw(4) and setw(7) keep the columns aligned with the header. Spacing in the header string was counted to match.

Common student pitfalls

  • Declaring rowSum before the outer loop: Student 2's total becomes 131 (70 + 61).
  • Writing score[q][s] in the column loop. With 3 rows and 4 columns, q = 3 reads past the last row.

Ask the class

  • "How would you find the student with the highest total?" (track the max of rowSum and its row index: the max-with-index pattern.)

Lab 9 · 2D arrays

2D Arrays at Work: Seat Plan and Matrix Addition

Any grid fits in a 2D array: seats in a room, pixels, a sensor grid, or a matrix in your math class.

#include <iostream>
using namespace std;

int main() {
    const int ROWS = 4, COLS = 6;
    // O = open seat, X = taken
    char seat[ROWS][COLS] = {
        {'X', 'X', 'O', 'X', 'O', 'O'},
        {'O', 'X', 'X', 'X', 'X', 'O'},
        {'X', 'X', 'X', 'X', 'X', 'X'},
        {'O', 'O', 'O', 'X', 'O', 'O'}
    };
    int totalOpen = 0;
    for (int r = 0; r < ROWS; r++) {
        int open = 0;
        cout << "Row " << char('A' + r) << ": ";
        for (int c = 0; c < COLS; c++) {
            cout << seat[r][c] << " ";
            if (seat[r][c] == 'O') {
                open++;
            }
        }
        cout << " open = " << open << endl;
        totalOpen += open;
    }
    cout << "Open seats: " << totalOpen << " of ";
    cout << ROWS * COLS << endl;
    return 0;
}

Row A: X X O X O O  open = 3
Row B: O X X X X O  open = 2
Row C: X X X X X X  open = 0
Row D: O O O X O O  open = 5
Open seats: 10 of 24

A char 2D array, a per-row counter, and a grand total. char('A' + r) turns row 0, 1, 2, 3 into the letters A, B, C, D.

#include <iostream>
#include <iomanip>
using namespace std;

int main() {
    const int ROWS = 2, COLS = 3;
    int a[ROWS][COLS] = {{1, 2, 3}, {4, 5, 6}};
    int b[ROWS][COLS] = {{10, 20, 30}, {40, 50, 60}};
    int sum[ROWS][COLS];
    for (int r = 0; r < ROWS; r++) {
        for (int c = 0; c < COLS; c++) {
            sum[r][c] = a[r][c] + b[r][c];
        }
    }
    cout << "A + B =" << endl;
    for (int r = 0; r < ROWS; r++) {
        for (int c = 0; c < COLS; c++) {
            cout << setw(5) << sum[r][c];
        }
        cout << endl;
    }
    return 0;
}

A + B =
   11   22   33
   44   55   66

Matrix addition

Add elements in the same position: sum[r][c] = a[r][c] + b[r][c]. Both matrices must have the same number of rows and columns.

Suggested time: about 8 min

Teaching tips

  • Seat plan: ask students to mark this room's seats and change the array to match. Then ask how to find the first open seat (a nested search with a flag, as in Lab 8).
  • Matrix addition: connect to their math class (matrices in algebra). One nested loop computes, a second one prints, which keeps the logic clear.
  • Matrix multiplication needs three nested loops. It is a good challenge for strong students, but not required here.

Common student pitfalls

  • Using "O" (a string) instead of 'O' (a char) in the comparison: it does not compile.
  • Trying sum = a + b; for whole arrays. Arrays don't support + or =; work element by element.

Ask the class

  • "How would you compute A − B? 2 × A?" (same loops, different formula.)

Lab 9 · Rules that bite

Out-of-Bounds Access and Copying Arrays

C++ does not check array indexes, and it cannot copy a whole array with =. Both are your job.

Out of bounds = undefined behavior

#include <iostream>
using namespace std;

int main() {
    int scores[3] = {90, 85, 77};
    for (int i = 0; i <= 3; i++) {  // BUG
        cout << scores[i] << " ";
    }
    cout << endl;
    return 0;
}

There is no automatic error. One run printed:

90 85 77 -495524352

The next run printed a different number. With -O2 optimization, the loop never stopped and crashed. Anything can happen.

original[0] = 100
backup[0]   = 7

Coming later: std::vector (can grow, knows its size) and std::array (fixed size, copies with =) solve many of these problems. They are covered in later courses.

Suggested time: about 7 min

Teaching tips

  • The left output is a real run with g++ (no optimization); the garbage value differed on every run. When this exact program was compiled with g++ -O2, the optimizer assumed the out-of-bounds read could not happen, so the loop did not stop at i = 3: it printed thousands of garbage values and then crashed (segmentation fault). That is what "undefined behavior" means: the compiler promises nothing.
  • Out-of-bounds writes are worse than reads: they can silently change other variables. This is a classic source of security bugs (buffer overflows).
  • backup = original; does not compile ("invalid array assignment"). Uncomment line 8 live to show the error.

Common student pitfalls

  • "It ran fine, so it's correct." Undefined behavior can look fine today and fail on the instructor's machine or in Codechum.
  • Comparing arrays with ==: it compares addresses, not contents, and is almost always false. Compare element by element.

Ask the class

  • "Which one-character change fixes the left program?" (<= → <.)

Lab 9 · Debugging

Four Classic Array Bugs

Each one compiles. Find the bug, predict what happens, then reveal the fix.

Bug 1 · i <= SIZE

int a[5];
for (int i = 0; i <= 5; i++) {  // BUG
    a[i] = 0;                   // a[5]!
}

The last pass writes a[5], one past the end, and may overwrite another variable.

Show the fix 
const int SIZE = 5;
int a[SIZE];
for (int i = 0; i < SIZE; i++) {
    a[i] = 0;
}

Use i < SIZE. The valid indexes are 0 to SIZE − 1.

Bug 2 · Uninitialized array

int count[5];           // BUG: garbage
for (int i = 0; i < 5; i++) {
    count[i]++;         // garbage + 1
}

A local array starts with garbage, so the counts are garbage + 1.

Show the fix 
int count[5] = {};      // all five start at 0
for (int i = 0; i < 5; i++) {
    count[i]++;         // now 1 each
}

Initialize counters and accumulators: = {} sets every element to 0.

Bug 3 · Variable as the size

int n;
cin >> n;
int grades[n];          // BUG: not standard C++

A "variable-length array" is a g++ extension, not standard C++. Other compilers (like MSVC) reject it, and a large n can crash the program.

Show the fix 
const int MAX = 50;     // biggest allowed
int grades[MAX];
int n;
cin >> n;               // then check n <= MAX
// use only grades[0] .. grades[n - 1]

Declare the maximum size as a constant and use only the first n elements.

Bug 4 · Max starts at 0

int highest = 0;        // BUG: assumes >= 0
for (int i = 0; i < SIZE; i++) {
    if (temp[i] > highest) {
        highest = temp[i];
    }
}   // temps -5, -8, -2 give 0

With all-negative data (a freezer sensor), no value beats 0, so the "highest" is 0, which is not even in the array.

Show the fix 
int highest = temp[0];  // start from a real value
for (int i = 1; i < SIZE; i++) {
    if (temp[i] > highest) {
        highest = temp[i];
    }
}   // temps -5, -8, -2 give -2

Start from the first element. In 2D problems, reset max/min at the start of each row too.

Suggested time: about 8 min

Teaching tips

  • Open one tab at a time. Give pairs 1 minute to find the bug and predict what happens, then click "Show the fix".
  • Bug 3: compile with g++ -pedantic to see the warning "ISO C++ forbids variable length array". Codechum may accept it, but the rubric's "Standards" criterion should not.
  • Bug 4 also appears as "forgetting to reset max/min": when finding the highest score per student in a 2D array, the max must restart for each row, or student 2 inherits student 1's maximum.

Common student pitfalls

  • Fixing bug 1 by making the array bigger (int a[6]) instead of fixing the loop condition.
  • Using a huge "safe" maximum like int a[10000000]; as a local variable: it can overflow the stack and crash.

Ask the class

  • "Which of these four bugs gives a compiler error?" (None! That is why tracing and testing matter.)

Lab 9 · Quick check

Quick Check

Answer on paper first, then click to reveal.

1For int a[5];, which indexes are valid?

0 to 4. The index counts from 0, so the last one is SIZE − 1.

2After int a[5] = {3, 1};, what is a[3]?

0. Elements without an initializer value are set to 0 when a list is given.

3What is wrong with for (int i = 0; i <= 5; i++) a[i] = 0; for int a[5]?

It writes a[5], which is outside the array: undefined behavior, with no automatic error. Use i < 5.

4Can you copy an array with b = a;?

No, it does not compile. Copy element by element in a loop.

5Linear search in an array of 100 elements: at most how many comparisons?

100, when the target is the last element or not in the array at all.

6int m[3][4]; has how many elements, and which one is stored right after m[0][3]?

12 elements. Memory is row-major, so m[1][0] comes right after m[0][3].

Suggested time: about 6 min

Teaching tips

  • Ask students to write answers 1–6 on a ¼ sheet, then reveal one at a time with a show of hands.
  • Q3 is the most important one for the lab exercise: ask a student to fix the loop out loud.

Common student pitfalls

  • Q1: answering "1 to 5". Q2: answering "garbage" (true only without an initializer list).
  • Q6: answering m[0][4], which does not exist (columns are 0 to 3).

Ask the class

  • "Which question would you put on the next quiz?" Their choice tells you what they found tricky.

Lab 9 · Seatwork

Seatwork: Readings Above the Average

A technician wants the average of 6 sensor readings, then every reading above the average: the slide 2 problem that needs an array.

Instruction: Read 6 double readings into an array. Print the average, the readings above it (in input order), and how many there are.

Need a hint?

Hint 1

You need two loops: the first reads and sums, the second compares each reading with the average.

Hint 2

The average can only be computed after the first loop ends. That is why the readings must be stored.

Hint 3

Print a space before each value (cout << " " << reading[i];) to avoid a trailing space.

Seatwork timer

10:00

Reveal answer & walkthrough 
#include <iostream>
using namespace std;

int main() {
    const int SIZE = 6;
    double reading[SIZE], sum = 0;
    cout << "Enter " << SIZE << " readings: ";
    for (int i = 0; i < SIZE; i++) {    // pass 1
        cin >> reading[i];
        sum += reading[i];
    }
    double average = sum / SIZE;
    cout << "Average: " << average << endl;
    int count = 0;
    cout << "Above average:";
    for (int i = 0; i < SIZE; i++) {    // pass 2
        if (reading[i] > average) {
            cout << " " << reading[i];
            count++;
        }
    }
    cout << endl << "Count: " << count << endl;
    return 0;
}

Enter 6 readings: 12 15 9 20 11 17
Average: 14
Above average: 15 20 17
Count: 3

Walkthrough

Pass 1 stores and sums: 84 ÷ 6 = 14. Pass 2 compares every stored reading with 14: 15, 20, and 17 are greater.

With decimals, e.g. 12.5 13.1 11.8 14.2 12.9 13.6, the average prints as 13.0167 (6 significant digits by default).

Suggested time: about 15 min (10 working, 5 review)

Running the seatwork

  • Start the timer. Open hints one at a time only if many students are stuck.
  • Fast finishers: also print the readings below the average, or the reading closest to the average.
  • Before revealing, run a student's program with 14 14 14 14 14 14: nothing is above the average, so the line is just "Above average:" and Count is 0. A good edge case.

Common student pitfalls

  • Comparing with the average inside the first loop, before the average is known.
  • Using int for the readings or the sum, so the average is truncated.
  • Using >=: the problem says "above".

Ask the class

  • "Why can't the Lab 7 sentinel loop (no array) solve this?" (The readings are gone by the time the average is known.)
