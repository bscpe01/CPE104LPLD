The 2.5 Mystery: Why Did 2.5 + 3.7 Give 2?

Lab 2's calculator stored its numbers in int variables. Watch what happens when the user types a decimal.

Lab 2 calculator: int

#include <iostream>
using namespace std;

int main() {
    int x, y;
    int sum;
    cout << "Type a number: ";

    cout << "Type another number: ";

Type another number: Sum is: 2

It never waited for the second number! cin put 2 in x, then choked on the leftover .5, so y became 0.

double x, y;
double sum;

Type a number: 2.5
Type another number: 3.7
Sum is: 6.2

Today's big idea

A variable's data type decides what it can hold, how much memory it uses, and what happens when the value doesn't fit.

Lab 3 · Data types

The Basic Data Types

Data types define the type of data a variable can hold.

TypeStoresExampleSize today*
intIntegers: whole numbers, no decimalsint num = 100;4 bytes (32 bits)
floatFloating-point numbers, single precision (about 7 digits)float num = 123.78987;4 bytes (32 bits)
doubleFloating-point numbers, double precision (about 15 digits)double num = 10098.98899;8 bytes (64 bits)

*Why "today"?

The C++ standard only promises that int is at least 16 bits. Old 16-bit compilers (like Turbo C++) used 2-byte ints. Codechum, g++, and Visual C++ use 4 bytes. You can check with sizeof (next slide).

Quotes matter

  • 'A' is a char; "A" is a string.
  • 'AB' is not one character. Use "AB".
  • string is not built into the language core: it is a class from the standard library.

Suggested time: about 6 min

Teaching tips

  • The examples are the ones on your Lab 3 deck. The deck lists int as 2 bytes (16 bits); that was true for old 16-bit compilers such as Turbo C++ under DOS. Every compiler students will use (Codechum, MinGW g++ in Code::Blocks/Dev-C++, Visual C++) uses a 4-byte int, so the slide shows 4 bytes.
  • Give one engineering example per row: int number of resistors; double resistance in ohms; char grade letter or resistor band code; bool "is the LED on?"; string component name.
  • Rule of thumb for this course: use double for decimals unless told otherwise.

Common student pitfalls

  • Using int for money, grades, or measurements, which silently loses the decimals.
  • Writing String with a capital S (Java habit). In C++ it is string.

Ask the class

  • "Which type for: a student number like 2026-00123? A phone number like 0917…?" (A string: it has a dash or a leading zero, and you never do math with it.)

Lab 3 · Memory sizes

Ask the Compiler: sizeof

sizeof(type) or sizeof(variable) gives the number of bytes it uses. 1 byte = 8 bits.

Why size matters

More bytes = more possible values. 4 bytes = 32 bits = 232 ≈ 4.3 billion different patterns, so an int can hold about −2.1 billion to +2.1 billion.

Suggested time: about 5 min

Teaching tips

  • This output is from g++ on 64-bit Linux; Codechum, MinGW (Code::Blocks / Dev-C++), and Visual C++ print the same numbers for these types.
  • This is where you correct the deck's "int = 2 bytes": run it and let the compiler settle it. Mention that 2 bytes was correct for 16-bit compilers like Turbo C++, which some older references and handouts still describe.
  • sizeof(num) shows that sizeof also works on a variable: its size comes from its type, not its value (100 or 2,000,000 both use 4 bytes).
  • sizeof(string) is left out on purpose: it prints the size of the string object (32 on g++, other values elsewhere), not the length of the text. Use .length() for text.

Common student pitfalls

  • Thinking bigger numbers take more memory in the same type. A type has a fixed size.
  • Confusing bits and bytes (×8).

Ask the class

  • "How many bits in a double?" (64.) "Why might a microcontroller programmer care?" (An Arduino Uno has only 2 KB of RAM; on that 8-bit board, int is 2 bytes again.)

Ask the class

  • "Why does unsigned char go to 255, not 127?" (No sign bit: all 8 bits count magnitude, 28 − 1 = 255.)

Lab 3 · Precision

float vs double: What "Precision" Means

Precision = how many significant digits a type can keep accurately. cout also shows only 6 significant digits unless you ask for more.

Read the output

  • Default cout rounds to 6 significant digits: 123.79, 10099. The stored values did not change.
  • The float could not store 123.78987 exactly: the extra …12 is rounding noise. A float is reliable to only about 7 digits.
  • The double kept every digit.

Suggested time: about 6 min

Teaching tips

  • Both literals are your deck's examples (float num = 123.78987;, double num = 10098.98899;), renamed num1/num2 so they can live in one program.
  • setprecision(n) sets the number of significant digits (total, not decimal places). Lab 5 adds fixed, which makes it mean decimal places: fixed << setprecision(2) for pesos.
  • Optional: 123.78987f (with f) is a float literal. Without the f it is a double that gets converted to float when stored.

Common student pitfalls

  • Thinking 10099 means the variable lost its decimals. It's only the display.
  • Comparing floating-point values with == (0.1 + 0.2 is not exactly 0.3). Revisit in Lab 6.

Ask the class

  • "A sensor gives readings like 3.14159265. Which type keeps all the digits?" (double.)

Lab 3 · Variables

Variables in C++

Definition

A variable is a name associated with a value that can be changed. Behind the name is a memory location big enough for its data type.

"Can be changed": watch the box

int num = 20;   // num holds 20
num = 35;       // now num holds 35

after line 1

num20int · 4 bytes

after line 2

num35int · 4 bytes

One value at a time

A variable holds exactly one value. Storing a new value replaces the old one; the 20 is gone.

Suggested time: about 5 min

Teaching tips

  • The diagram recreates your deck's int num=20 slide (data type, variable name, value). The code here adds spaces around =, matching our coding conventions.
  • Analogy: a labeled storage box in a stockroom. The label is the name, the box size is the type, and the content is the value. You can replace the content, but the box stays the same size.
  • = means "store into", not "is equal to". Read num = 35; as "num gets 35".

Common student pitfalls

  • Writing 20 = num;. The variable must be on the left.
  • Re-declaring: int num = 20; then int num = 35; in the same block is an error ("redeclaration"). To change it, drop the type.

Ask the class

  • "After num = num + 5;, what does num hold?" (40, if it held 35.)

Lab 3 · Program variables

Naming Variables: Rules and Conventions

Names of variables (and constants, functions…) are called identifiers. Rules are enforced by the compiler; conventions are enforced by your grade.

Rules: break one and it won't compile

  1. Use only letters, digits, or underscore _.
  2. Cannot begin with a digit: 2ndPlace ✗
  3. No spaces, punctuation, math, or special symbols: net pay, my-score, rate% ✗
  4. Not a reserved word: int, float, return, if ✗
  5. Case-sensitive: age, Age, and AGE are three different names.

Conventions: follow them for readable code

  • Meaningful names: totalCost, not tc or x1.
  • Pick one style and stay consistent:
    camelCase myNum, totalCost or snake_case total_cost.
  • Constants in UPPER_CASE: PI, MAX_SPEED.
  • Single letters only for short loop counters (i) or math formulas (x, y).

Avoid library names

Names already used by the standard library (cout, string, count, max) are not keywords, but with using namespace std; they can clash and cause confusing errors.

Suggested time: about 6 min

Teaching tips

  • Rules 1–4 are from your deck. The deck also says "ANSI guarantees only the first 32 characters to be significant." That is an old C limit (C89 guaranteed 31 significant characters for internal names). Modern C++ compilers support much longer names (g++ has no practical limit), so it is omitted from the slide. Mention it only if students have seen it in an older book.
  • The deck's last rule ("names reserved for function names and the standard library") is split here: keywords can never be used; library names are legal but risky. A real example: a global variable named count becomes ambiguous with std::count once <algorithm> is included.
  • Our decks use camelCase (myNum, myFloatNum), so this lab does too.

Common student pitfalls

  • Using a hyphen (first-name). The compiler reads it as first minus name.
  • Mixing Total and total in one program and getting "not declared" errors.

Ask the class

  • "Is Int a legal variable name?" (Yes, because only lowercase int is reserved. But it is a terrible name.)

Lab 3 · Scope of variables

Scope: Where Can a Variable Be Used?

A global variable is declared outside all functions. A local variable is declared inside a function or block { } and exists only there.

Notice

  • Globals start at 0 automatically. Locals start with garbage unless you give them a value.
  • int b(2); is another way to write int b = 2;
  • Prefer locals. Globals can be changed from anywhere, which makes bugs hard to find.

Shadowing

int total = 100;  // global
// later, inside main:
int total = 7;    // hides it!
cout << total;    // prints 7

Suggested time: about 6 min

Teaching tips

  • This program follows your deck's Code::Blocks example (globals x, y, m; locals a = 5, b(2), result). The deck's string z[20] (an array) is left out until Lab 9. Trace it: a becomes 6, result = 6 − 2 = 4.
  • Block scope preview: a variable declared inside if { … } or a loop body disappears at the closing brace. Students will hit this in Labs 6–7.
  • When functions arrive (Lab 11), scope becomes essential: each function has its own locals.

Common student pitfalls

  • Making everything global "so it works everywhere". It works until two parts of the program change the same variable.
  • Shadowing by accident: declaring int total again inside main and then wondering why the global never changes. (::total refers to the global, but the real fix is better names.)

Ask the class

  • "Which variables in this program could another function use?" (Only the globals: x, y, m.)

Uninitialized variables

int total; followed by cout << total; prints garbage: whatever bits were left in that memory. g++ warns:

warning: 'total' is used uninitialized

Always give a variable a value before you use it.

Suggested time: about 6 min

Teaching tips

  • All three forms and the myNum example come from your deck (slides 10–12). The complete program combines "declare, then assign 15" with an overwrite to 10.

Lab 3 · Memory allocation

What a Declaration Does in Memory

Each declaration reserves a block of bytes, sized by the data type. The name is how you refer to it; the address is how the computer finds it.

Every variable has four things

  • Name: myNum, for humans.
  • Type: int, which fixes the size (4 bytes) and how the bits are read.
  • Value: 5, the current contents.
  • Address: where those bytes start in memory.

Where is myText?

A string is an object that keeps its characters in a separate, resizable block of memory, so it can grow as text is added.

Memory budget

These four variables use 4 + 8 + 1 + 1 = 14 bytes. Tiny on a laptop with 8 GB, but it matters on a microcontroller with 2 KB.

Suggested time: about 5 min

Teaching tips

  • This slide addresses ILO 2, "memory allocation concepts". Keep it concrete: one row = one byte, a declaration claims a block of rows.
  • Students will print real addresses with &myNum in Lab 10 (References and Pointers). Today, just plant the idea that every variable has an address.
  • In real programs the compiler may leave gaps (alignment) and may order variables differently. The diagram simplifies on purpose.

Common student pitfalls

  • Thinking the variable name is stored in memory at run time. Only the value is; names are for the compiler and for you.
  • Thinking a double holding 5 uses less memory than one holding 5.99. Same type, same 8 bytes.

Ask the class

  • "If we add long long big = 0;, how many more rows?" (8.)

Lab 3 · Constants

Constants: Values That Never Change

Constants store fixed data that remains the same for the whole run of the program. Add const before the type.

Syntax: const data_type constant_name = value_of_constant;

Ana lives at house no. 1234
Circle area = 19.625

Try to change one…

const float PI = 3.14;
PI = 3.1416;    // not allowed!

…and the program will not compile:

error: assignment of read-only variable 'PI'

Why use constants?

  • Safety: the compiler stops accidental changes.
  • Readability: PI says more than 3.14.
  • One place to edit: change the value once, everywhere updates.
  • A const must get its value when declared.

Suggested time: about 6 min

Teaching tips

  • The three declarations are exactly your deck's examples. Many style guides would write the last two as MY_NAME and HOUSE_NUMBER; point out that UPPER_CASE makes constants easy to spot (our naming slide).
  • The error text is g++'s; Codechum shows the same kind of message with a line number.
  • Engineering constants make great examples: const double GRAVITY = 9.81; (m/s²), const double METERS_PER_MILE = 1609.34;. The second one is useful in Lab Activity 3.
  • Optional: 19.625 prints exactly because 3.14 × 6.25 rounds cleanly in 6 significant digits.

Common student pitfalls

  • const int MAX; with no value: compile error ("uninitialized const").
  • Thinking const makes a program faster. Its main benefit is safety and readability.

Ask the class

  • "Which values in a Meralco bill calculator should be constants?" (The rate per kWh, fixed charges, VAT rate.)

Lab 3 · User input for strings

Reading Text: cin >> vs getline

cin >> stops at the first space. getline reads the whole line.

cin >> course; reads one word

#include <iostream>
#include <string>
using namespace std;

int main() {
    string course;
    cout << "Enter your course: ";
    cin >> course;
    cout << "cin read: " << course << endl;
    return 0;
}

Enter your course: BS Computer Engineering
cin read: BS

getline(cin, course); reads the whole line

#include <iostream>
#include <string>
using namespace std;

int main() {
    string course;

    cout << "getline read: " << course << endl;

}

Enter your course: BS Computer Engineering
getline read: BS Computer Engineering

Rule

Use cin >> for numbers and single words. Use getline(cin, stringname); for names, addresses, sentences: anything that may contain spaces.

Where did "Computer Engineering" go?

It is still waiting in the input. The next cin >> would read Computer without letting the user type.

Lab 3 · A famous bug

The Leftover Enter: cin >> Followed by getline

After cin >> age; the Enter key ('\n') stays in the input. A following getline reads that empty line and doesn't wait.

Bug: the city is never asked

#include <iostream>
#include <string>
using namespace std;

int main() {
    int age;
    string city;
    cout << "Enter your age: ";
    cin >> age;
    cout << "Enter your city: ";
    getline(cin, city);
    cout << "City: [" << city << "]" << endl;
    return 0;
}

Enter your age: 18
Enter your city: City: []

Fix: throw away the leftover Enter

#include <iostream>
#include <string>
using namespace std;

int main() {
    int age;
    string city;
    cout << "Enter your age: ";
    cin >> age;
    cin.ignore(1000, '\n');  // drop the Enter
    cout << "Enter your city: ";
    getline(cin, city);
    cout << "City: [" << city << "]" << endl;
    return 0;
}

Suggested time: about 6 min

Teaching tips

  • Run the buggy version live: the program prints the city prompt and finishes immediately. The brackets in City: [] make the empty string visible. Ask students what they think happened before explaining.
  • Draw the input buffer on the board: 1 8 \n. cin >> age takes 1 and 8 and leaves \n; getline sees \n first and returns an empty string.
  • cin.ignore(1000, '\n') means "discard up to 1000 characters, or until a newline is discarded". The fully general form uses numeric_limits<streamsize>::max(); 1000 is plenty for keyboard input. Another fix is getline(cin >> ws, city); (skip leading whitespace).
  • Simplest prevention: read all getline inputs before any cin >>, as in today's seatwork.

Common student pitfalls

  • Putting cin.ignore() before the first getline at the start of the program, which eats the first character the user types.
  • Adding cin.ignore() after every input "just in case".

Ask the class

  • "Does the bug happen if we swap the order (city first with getline, then age with cin)?" (No. getline consumes its own Enter.)

Lab 3 · Example challenge

The ₱200k/month Challenge: Reverse a Phrase

Hello, and thank you for participating in our test. We are looking for individuals who would be interested in becoming professional programmers. The starting salary would be around ₱200k/month. But we will only accept those who pass this test. We will be giving you a phrase and all you need to do is to reverse it. The person with the fastest time will be hired on the spot! Are you up for the challenge?

Reveal a worked solution 
#include <iostream>
#include <string>
using namespace std;

int main() {
    string phrase;
    string reversed = "";
    cout << "Enter the phrase: ";
    getline(cin, phrase);

    // start at the last index, walk back to index 0
    for (int i = phrase.length() - 1; i >= 0; i--) {
        reversed = reversed + phrase[i];
    }
    cout << reversed << endl;
    return 0;
}

Preview of Lab 7

The for loop repeats line 13 once per character, with i counting down from the last index (length − 1) to 0. You'll learn loops properly in Lab 7.

Suggested time: about 10 min

Teaching tips

  • The story and both sample outputs are from your deck's Example slide. Give students 3–4 minutes to think (or pseudocode) before revealing.
  • The solution uses only today's tools (getline, length, [], concatenation) plus one for loop, labeled as a preview. Read the loop aloud: "start i at the last index; while i is at least 0; after each round, subtract 1".
  • Set the tracer to Fast and watch reversed grow one character at a time in the Memory panel.
  • Alternative for strong students: #include <algorithm> and reverse(phrase.begin(), phrase.end());. It works, but the hiring test is about understanding indexes.

Common student pitfalls

  • Starting at i = phrase.length(): one past the last character.
  • Using cin >> phrase, which reverses only the first word (siht).
  • Using i > 0, which skips the first character.

Ask the class

  • "How would you print the phrase in UPPERCASE?" (Teaser: toupper, later.) "How would you check if a word is a palindrome, like racecar?"

Lab 3 · Seatwork

Seatwork: Engineering ID Card

Write a program that asks for the user's full name (may contain spaces), age (whole number), and height in meters, then prints an ID card.

Your card must

  1. Show the school name from a const string in a header line.
  2. Show the name inside double quotes (use \").
  3. Show the first letter of the name and the number of characters.
  4. Line up the labels with \t.

Need a hint?

Hint 1

Pick a type for each value: name → string, age → int, height → double.

Hint 2

Read the name first with getline(cin, fullName); Then cin >> the numbers. That order avoids the leftover-Enter bug.

Hint 3

First letter: fullName[0]. Number of characters: fullName.length().

15:00

Reveal a solution 
#include <iostream>
#include <string>
using namespace std;

int main() {
    const string SCHOOL = "BulSU College of Engineering";
    string fullName;
    int age;
    double height;

    cout << "Enter your full name: ";
    getline(cin, fullName);
    cout << "Enter your age: ";
    cin >> age;
    cout << "Enter your height in meters: ";
    cin >> height;

    cout << "\n*** " << SCHOOL << " ***\n";
    cout << "Name:\t\"" << fullName << "\"\n";
    cout << "Init:\t" << fullName[0] << "\n";
    cout << "Length:\t" << fullName.length() << " characters\n";
    cout << "Age:\t" << age << "\n";
    cout << "Height:\t" << height << " m\n";
    return 0;
}

What to notice

  • "\n*** " starts with a newline, which creates the blank line before the header.
  • All labels are 7 characters or less, so one \t lines them up at column 8.
  • The length (11) counts the space in "Alex Santos".

Extend it

Add the height in centimeters (×100) and the user's initials from both names. Which string tool would you need to find the space?

Suggested time: about 20 min (15 working, 5 review)

Running the seatwork

  • This seatwork combines every topic of the day except scope: types, const, getline, escape sequences, [], and length(). It deliberately avoids the four Lab Activity 3 tasks.
  • Walk around and look for the order of inputs: students who read age first and then getline the name will hit the leftover-Enter bug. Great teachable moment: send them back to the previous slide.
  • Accept any school or header text and any sensible label alignment; the point is the techniques.
  • Extension answer: fullName.find(' ') returns the index of the space (a preview; not required).

Common student pitfalls

  • Writing "Name:\t"" << fullName (wrong quote escaping). The output needs \" inside the string.
  • Using int for height, which prints 1 (and breaks the next input).
  • Labels of 8+ characters (Initial:) jump to column 16 and break the alignment.

Ask the class

  • "What does the card show if the user enters a name with a leading space?" (Init shows a blank. Input cleanup comes later.)
